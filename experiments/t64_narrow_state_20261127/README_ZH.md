# 24/32位跨块状态的真实模型验证

Issue225/PR266，负责人rayggxia。本实验只分析状态缩位，不修改原RTL、默认Decoder或正在运行的x一位实验。依据本地ffn_narrow_state_20261127的逐tile RNE合同，固定T64/W8、16/32、x/g/u组64基准+S/S2、准确Attention，比较64/32/24位。

每个K64 tile先产生signed23局部整数，再按输入/权重指数对齐到公共基准；右移RNE、左移和加法越界报错。基准由形状、采样上限、W8幅值127和全部输入尺度元数据的保守界计算，留两位余量，不使用最终输出或抵消程度。GU的64g/64u共享同一单位，Wd每128输出共享；真实40/152块按K顺序更新。宽64整数仅作为Python传输容器，所存状态及每次加法明确检查24/32位。

局部GEMM用FP32作精确整数容器：每一乘积及任意顺序的部分和绝对界小于2^23，TF32关闭；随后对齐、RNE、跨块累加全部int64模拟W位状态。GPU门禁对独立NumPy/Python任意整数oracle逐值检查，不能把未界定精度的浮点乘法当作硬件参考。

先跑25项CPU检查与16组GPU整数oracle（含真实40/152块），再重做完整BF16、64位无操作logits/旧8窗原字节一致检查。三宽度同8窗/9215目标单seed101。若24/32小测不超过64位1%，自动接该宽度完整WT2；1%只是资源触发，不代表质量验收。完整64位参考复用同学院环境已冻结的x一位实验，按模型/文本/原字节pilot验证后比较，不重复其健康作业。

重要边界：现有RTL的field_raw从恢复g生成sigmoid地址，当前PPL从P8重建g生成地址。本实验保持后者不变，以隔离状态缩位；两种入口差异另列，不能把结果宣称为整个新RTL codec逐位验收。公共尺度服务仍是宏接口，不因数值实验通过而认为面积/调度已经闭合。
