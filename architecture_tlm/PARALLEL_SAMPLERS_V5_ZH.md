# 全候选并行采样：赢家保持与校正拒绝 TLM v5

任务：Issue #87；负责人 jieruiz。算法依据为 Issue #78 / PR #86；不接管 Issue #37 的比较脚本。这里是可执行的 Python 事务模型，外存沿用已有 Link / 可选 DRAMSys 接口；不是 RTL、PT、物理 p-bit 仿真或新的 PPL 结果。

## 先看本版到底做了什么

**一个查询有 N 个候选，就一次读取全部 N 路（赢家）或 N−1 路（拒绝）的有偏随机位。没有64路分波，也没有逐节点更新。** 随机源技术尚未选定，只提供可配置的服务延迟、服务间隔和成本接口。所有输出都是候选地址，直接用于 V 读取和平均。

| 对比 | 赢家保持 | 校正拒绝 |
|---|---|---|
| 每轮有偏随机位 | N 路同时读取 | N−1 路同时读取，最大分数位置为空状态参考 |
| 一轮之后的工作 | 活跃计数、旧赢家测试，必要时均匀仲裁 | 零/单/多1检测，空态校正，必要时改变偏移 |
| 哪些轮产生样本 | 去掉预热之后每轮，包括保持 | 仅接受轮；拒绝仍计费 |
| 偏移是否每轮变 | 同一查询固定 | 拒绝后可能改变，必须计反馈与驱动更新 |
| 辅助公平随机位 | 从 M 个活跃地址均匀选一个，最多 ceil(log2 N) 位/尝试 | 空态接受硬币需 m 位，默认 m≤24 |
| 随机源电路 | 未决定，可本地PRNG＋比较器，也可DAC＋物理阵列 | 相同 |

例如候选512：赢家需要512路有偏采样接口，拒绝需要511路。辅助公平随机服务是独立接口，分别预留9路和24路的最大并行需求；它可以由共享随机源层级提供，**不等于已经决定增加9或24个物理 p-bit**。本版没有免费复用有偏通道，因为把它们改成50%再恢复也可能需要重新设置驱动。

同一采样器实例按头/查询串行复用。若要同时服务 H 个查询，需要 H 个实例或明确共享调度，不能把每查询 N 路当成全模型任意并发所需的总数。未使用槽不采样，但已配置容量仍参与面积预算。

## 完整数据路径及接口

`QK筛选 → 计算候选QK/√d → 读取候选分数 → 最大值/减法/驱动编码 → 并行采样器 → 地址直方图 → 原位置映射 → V去重/缓存/读取 → 按次数累加/平均 → Wo`

- 两个模块都实现 `request(ready, logits, samples, rng, identity, candidate_ids, output_ns_per_index=0, source=None)`，返回局部地址序列与事务回执；`finish(end)` 汇总活动、成本缺项及容量。
- `candidate_ids` 保存局部地址到原上下文位置的映射；禁止重复、越界容量或静默截断。
- 自定义随机源实现 `draw(drives)` 和 `fair(width)`。前者一次返回所有请求通道的布尔值，后者一次提供指定宽度的公平随机位。
- 默认 `IdealBitSource` 是独立 sigmoid 响应的**数值参考**。Python 的随机函数和循环耗时都不作为硬件操作或时钟。
- `drives` 的单位约定为 log-odds：P(1)=sigmoid(d)。若物理p-bit满足平均自旋=tanh(I)，应传入 I=d/2，得到 P(1)=[1+tanh(d/2)]/2；不能把同一个数原样当成tanh括号内输入。数字比较后端同样须按sigmoid(d)生成阈值。
- 源服务必须满足各候选与跨帧新鲜独立的假设。FFN同一个随机门限比较64个输入的共享，不能直接用到这里。
- 模块没有第二次 PV 采样；赢家重复地址按重复次数保留。下游继承 v4 的直方图、有限V缓存、GQA共享及重复加法调度，不宣称这些已经最优。

## 赢家保持：每轮具体做法

1. 找出最大分数地址，作为初始赢家。固定驱动 `d_i=z_i−max(z)−shift`，默认 shift=0。
2. 一次得到 N 个比特，概率为 sigmoid(d_i)。允许零个、一个或多个1。
3. 计数树得到活跃数量 M；检查**旧赢家自己的比特**。
4. 旧赢家比特为1，或 M=0：保持旧赢家。
5. 否则从活跃地址中均匀选一个。产生 k=ceil(log2 M) 个公平位；若整数≥M则重新取 k 位，所有尝试均收费；再用计数树按秩选地址。
6. 提交赢家；预热轮不输出，保留轮向单项输出寄存器写一个地址。

普通优先编码器不能替代第5步。仲裁只在需要切换时启动；此前数值参考有时会先产生一个最终未用的候选，二者转移分布相同，但随机数消耗不同，不能要求同一个软件seed逐位重现旧轨迹。

理想未量化响应的平稳分布为 Softmax；有限轮存在初始化与相关性误差。本版不凭轮数保证完整模型PPL，也不把1024轮称为1024个独立样本。

## 校正拒绝：每次提议具体做法

最大分数地址为参考 r；其余节点驱动 `d_i=z_i−z_r−m·ln2`，从 m=0 开始。

1. 一次得到全部 N−1 个非参考节点比特，归约树检测零、单、多1，并携带单1地址。
2. 单1：接受其地址。
3. 多1：拒绝，m增加1，默认上限24。
4. 全零：只有概率 2^(−m) 接受参考地址。用 m 个公平位全部为0实现；m=0时直接接受。
5. 空态校正失败：拒绝，m减1，最低0。
6. 偏移改变时，等待反馈、重新编码和驱动更新；随后才能发起下一轮。只有接受的地址进入输出寄存器。

`offset_update_mode=per_candidate` 默认显式重写所有非参考驱动；`shared_scalar` 则只更新一个公共偏移字。**后者是需要后端支持的接口能力，不是已证明免费的广播。** 两种模式的编码、配置位数和周期分别计入。

理想独立、未量化 sigmoid 与准确空态校正下，接受地址遵循目标 Softmax，拒绝过程不需要Markov预热。引入驱动量化或真实器件偏差后不能直接继承这一精确结论。

总提议数默认上限为 `samples × 64`；超限抛出带失败回执的 `SamplingCapError`，收费但不把部分轨迹当完整成功，也不回退到理想IID。

## 时序怎么计算

这是保守、可运行的**单帧阻塞状态机**：

`最大值/编码/配置一次 → [源命令＋稳定＋全宽读取 → 归约 → 判定/仲裁或反馈 → 提交/输出]重复`

- 每轮随机源只有一次全宽读取；N增大不会产生 N/P 个采样波次。N仍影响数字树深、初始加载量和面积。
- 源延迟与最短服务间隔是两件事；服务间隔在查询切换后也持续生效。
- 计数/归约/按秩选择的时延，按树深和每拍可跨越的逻辑级数计算。该级数是待综合替换的映射参数。
- 输出只有一个寄存器，下游写口慢时阻塞；停顿不能变成额外独立样本。
- 本版不提前生成下一帧，不宣称II=1。固定驱动赢家以后可做流水线优化，但须另行规定帧缓存、赢家反馈与回压协议。

随附示例取10ns/拍，源命令1拍＋稳定2拍＋读取1拍，树每拍2级。这些只用于验证可执行调度，**不是选定随机源后的时序预测**。例如512节点一次读取仍为4拍；一个完整更新还要归约、仲裁、提交，明显不等于1拍。

## 存储、数制和成本边界

- 显式统计位图、归约树、赢家/地址状态以及一个输出寄存器的位数；具体由寄存器、SRAM还是组合结构实现，待综合确定。
- 分数与映射复用现有紧凑缓存；不额外创建一张连续概率表。驱动保持状态属于随机源后端，不能在后端和主机两边重复收费或两边都漏掉。
- 默认连续响应参考传32位分数/驱动负载，**不代表采用32位DAC**。可显式设置 `drive_bits=8, drive_step=0.125, drive_max_code=255`，得到非正8位驱动 [−31.875,0]；这会实际量化数值响应，不能只改计费位数却宣称精度不变。
- 默认 `energy_pJ={}`、`idle_W=null`、`area={}`，未标定项不自动填0。返回活动数、已知小计和缺项；完整能量/面积字段为 null。
- 每类能量系数的单位是 pJ/对应动作；`biased_bit_draws` 指读出/接口动作，`source_slot_cycles` 指源通道工作周期，`macro_active_cycles` 指其余公共时钟/保持开销。填表时须划清互斥的成本边界，不能同时用整宏PT总能量和各子模块总能量重复收费。
- `winner_count_nodes` 与 `rejection_flag_nodes` 分开标定；公平随机位、按秩访问、控制、缓冲访问、配置位和输出地址各有独立活动项。
- `area` 接受有偏通道、辅助公平通道、数字逻辑本体、缓冲每位四项。源通道单价必须覆盖所选后端的驱动保持/比较或DAC外围；数字本体不再重复包含另计的缓冲面积。
- 整机适配器继续使用原有SRAM/外存模型；源成本未知时，整机J/token及面积设null，仅保留明确命名的部分/参数化账本。即使填完本模块，既有非Attention数字成本也仍可能未标定。

## 文件与运行方法

| 文件 | 作用 |
|---|---|
| `parallel_sampler_v5.py` | 源接口、资源/时序、活动账本、容量/成本契约 |
| `winner_hold_tlm_v5.py` | 赢家保持事务状态机 |
| `corrected_rejection_tlm_v5.py` | 校正拒绝事务状态机 |
| `screen_parallel_tlm_v5.py` | 接回筛选、QK、V读取及完整decode |
| `configs/parallel_sampler_v5.json` | 可调时序/驱动/成本配置 |
| `run_parallel_sampler_v5.py` | 可复现单模块及整机连通示例 |
| `checks/test_parallel_sampler_v5.py` | 行为、时序、失败、账本与集成检查 |

在仓库根运行：

```powershell
python -m unittest discover -s architecture_tlm/checks -p test_parallel_sampler_v5.py -v
python -m unittest discover -s architecture_tlm/checks -p test_screen_ising_v4.py -v
python architecture_tlm/run_parallel_sampler_v5.py --output NEW_EMPTY_DIRECTORY
python architecture_tlm/run_parallel_sampler_v5.py --attention --small --context 128 --samples 16 --output ANOTHER_EMPTY_DIRECTORY
```

正式形状去掉 `--small`；默认保留原数字FFN，也可以显式 `--variant fixed_sc_exact` 接入历史随机FFN情景。后者继承旧TLM的FFN参数，**不冒充已完成最新B4/T32/K32的硬件重标定**。`--bridge` 才启用真实DRAMSys后端，默认仍为Link；`--trace` 可传入现有Attention trace。新源/真实链下的整模型PPL需另做，不能引用旧Ising PPL直接验收。

单模块真实分数输入 `--input file.json` 格式为 `{"rows":[{"id":"row0","logits":[...],"candidate_ids":[...]}]}`。保存原输入及SHA，并声明筛选来源；不能把合成示例改名叫Qwen真实结果。
