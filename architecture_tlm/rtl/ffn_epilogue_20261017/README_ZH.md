# 数字 SwiGLU 后处理：供综合和 PT 表征的候选模块

本目录提供一个可综合的 `z = g × sigmoid(g) × u` 数字模块，补上随机矩阵之间的非线性和逐元素乘法成本。它是**定点近似候选**，不是原模型 BF16 运算的逐位等价实现，也不是已经通过 Qwen PPL 验证的新 FFN。没有写入任何假定的工艺面积或功耗。

对应 Issue #7；硬件模型基线为 `db3a79c876f46f4738274cc010a2066562dd27d2`。不包含模型、分词器或语料，故其版本/哈希不适用于本模块级验证。不能将本目录的合成激励结果当作真实模型活动率。

## 1. 数据格式与运算顺序

| 信号/步骤 | 编码与含义 |
|---|---|
| `g_in`, `u_in` | signed 16 位二进制补码；实数 = raw / 1024，范围 `[-32, 31.9990234375]` |
| sigmoid LUT | 正半轴 256 项，unsigned 17 位；实数 = raw / 65536，能够精确表示 1 |
| 第一次乘法 | `signed16 g × signed16 u → signed32`，不在这里截位 |
| 第二次乘法 | 将 sigmoid 显式补零扩为 signed18，再 `signed32 × signed18 → signed50` |
| 最终舍入 | 仅在最后按 `2^26` 除法进行一次对称 round-to-nearest, ties-to-even |
| `y_out` | 默认 signed24，实数 = raw / 1024；可通过 `OUT_W` 改变位宽，有效范围 2～32，实测了 24 和 16 |
| `saturated` | 舍入后超过输出补码范围时钳位并置 1 |
| `inexact` | 最后 `2^26` 除法有余数，或输出发生饱和时置 1；**不包含 LUT 误差和外部输入量化误差** |

输入两个 Q10 数与 Q16 sigmoid 相乘得到 Q36，因此回到 Q10 需要右移 26 位，而不是 16 或 20 位。默认 24 位输出范围为 `[-8192, 8191.9990234375]`，能够覆盖这里约 ±1024 的乘积范围；不把输出错误地限制到 ±32。

`g × u` 与 `sigmoid(g)` 先各自计算，再相乘，在无限精度实数中与先做 SiLU 等价。本模块在中间保留整数精度，只有最终一次舍入；这不代表它与 BF16 原运算顺序、溢出和舍入相同。实际 g/u 是否适合此 Q10 范围，仍需模型轨迹校准，输入转换/裁剪电路不在本模块内。

## 2. LUT 的精确定义与误差

对于 `a = abs(g_raw)`：

- `a < 8192`：`index = floor(a / 32)`，使用 `sigmoid(index / 32)` 的 Q16 最近偶数舍入值；
- `a >= 8192`：正数采用 65536，负数采用 0；
- 负半轴使用 `65536 - LUT[index]`，从而严格保持 `sigma(-g) = 1 - sigma(g)`；
- `abs(-32768)` 用 17 位幅度计算，不会在 16 位有符号数上溢出。

这里是对**幅度向下取格点**，不是直接对负实数向负无穷取整。`sigmoid_lut.svh` 是常量 case ROM，没有可写 LUT 或上千个需要复位的系数寄存器；综合后是逻辑还是 ROM 由目标流程决定，不能直接宣称是工艺 SRAM。

`generate_lut.py` 使用 Python Decimal、80 位十进制精度与最近偶数舍入生成 `.svh` 和 JSON。运行 `generate_lut.py --check` 可验证已提交系数的逐字节一致性。

实际遍历全部 65536 个可表示 g 输入，结果为：

| 误差项目 | 最大值 |
|---|---:|
| sigmoid 绝对误差 | 0.007567781406494278 |
| SiLU 绝对误差，最终输出舍入前 | 0.006848951192119019 |
| 在 `abs(u) <= 32` 下，SwiGLU 输出舍入前绝对误差上界 | 0.21916643814780862 |
| 不饱和时，最后一次 Q10 舍入的绝对误差上界 | 0.00048828125 |

这些是规定定点输入上的数值误差，不是相对误差，也不代表 PPL。采用更密 LUT、线性插值或其他近似会改变面积/时间/精度，不在这次候选中混入。

## 3. 时序接口：4 组寄存器、II = 1

| 寄存级 | 保存内容 |
|---|---|
| A | g/u 输入 |
| B | 精确 g×u，以及 LUT sigmoid |
| C | 二者的 50 位乘积 |
| D | 舍入、饱和后的输出与标志 |

时序用明确边沿定义：若输入在 **ce=1 的边沿 N** 接受，则输出在后续的 **ce=1 边沿 N+3** 更新有效。即接受边沿也计入时共经过 4 个寄存级，接受到产生输出跨越 3 个使能周期。连续 `ce=1, in_valid=1` 时每拍可以接收一个 g/u，并在流水线填满后每拍输出一个 z；不能把它理解为每 4 拍才能处理一个元素。

- `rst` 为同步高有效复位，优先于 `ce`，清空全部有效位及输出，丢弃在途输入。
- `ce=0` 时所有数据、有效位和输出标志保持；下游必须共享此全局使能，不能在暂停时重复消费保持为 1 的 `out_valid`。
- 没有自主反压或 ready 握手；下游来不及接收时必须暂停整个模块或在外部加入队列。
- `in_valid=0` 时输入 g/u 寄存器保持，避免外部无效输入直接驱动两个大乘法组合逻辑翻转；其他数据级也仅在对应有效位为 1 时更新。
- 输出无有效新数据时保持上一次值。功能 TB 同时验证数据保持、CE 暂停和流水复位。
- 有使能不意味着时钟树零功耗；若希望使用集成时钟门控，应在实际综合/布局流程中推导并测量 ICG，不能把数据保持直接当成时钟已关闭。

这是**单通道**模块，不能直接代表当前 TLM 的 `16 nonlinear/cycle` 吞吐。需要多少通道应根据 g/u 输出速率和可接受缓冲决定，不能把本模块一次结果直接当作 16 通道的物理面积/布线结果。它也不包含前后矩阵阵列、g/u 缓冲 SRAM、z 的概率编码或 BF16↔定点接口。

## 5. 交给 DC / 布局 / PT 的要求

1. **综合输入**：只读入 `swiglu_epilogue_q10.sv`，将本目录加入 include 搜索路径以找到 `.svh`；顶层为 `swiglu_epilogue_q10`，`OUT_W=24`。TB、Python、JSON 不进入综合。使用你们现有 55 nm 工艺库，报告真实 PVT、电压、温度及库版本。
2. **时序约束**：先以 100 MHz（10 ns 周期）约束 `clk`。指定实际输入延迟、输出负载、时钟不确定度，不把所有接口当零负载。复位同步，不能无条件 false-path 掉正常数据。若 10 ns 不满足，先返回关键路径和可达频率，避免仅凭 RTL 声称达标。
3. **至少报告综合与布局后两组结果**：组合/时序/总单元面积、寄存器数量、ROM 实际映射、乘法器映射、ICG 情况、WNS/TNS、关键路径；有布局时返回利用率、布线/时钟树及寄生后的结果。固定工艺条件下才比较版本。
4. **功耗输入**：先用 `tb_swiglu_power.sv` 产生合成活动，默认 100 MHz，可用 `HALF_PERIOD_NS` 参数改变频率。运行参数为 `+MODE=active|burst|idle +CYCLES=4096 +SEED=325229989 +VCD=<输出路径>`。模式分别为连续有效、每 256 拍前 64 拍有效、完全无效；三种模式的外部 g/u 都继续翻转，用来验证空闲隔离。
5. **功耗可信度**：RTL VCD 可先给早期估计；正式比较优先对综合/布局后网表重跑同等激励，注入真实延迟，向 PT 提供门级 SAIF/VCD 和寄生。报告活动映射覆盖率及未标注节点，避免将未映射节点默认为零翻转。时钟树与 ICG 功耗计入，不能只报乘法组合逻辑。
6. **统计窗口**：默认时钟中，3 个复位下降沿后在 30 ns 开始输入活动。`CYCLES=4096` 时，到 40990 ns 完成活动，再留 8 拍排空至 41070 ns。整段事务能量可在 30～41070 ns 积分：active 接受 4096 项、burst 接受 1024 项；用能量除实际有效项数。idle 单独报告流水排空后的保持功率，不能给 idle 除零的“每项能量”。如另截稳态窗口，应一并报告窗口及其中有效项数。
7. **需要返回的数据表**：见下表。不要将合成均匀输入的能量直接写成 Qwen 的实际每 token 能量；真实 g/u 轨迹到位后，用相同流程补跑。

| 需返回字段 | 单位/说明 |
|---|---|
| 工艺角、电压、温度、时钟频率 | 必填；综合、PT、布局库要对应 |
| 总面积 / 组合面积 / 时序面积 | μm²；标明是否包含时钟树 |
| 关键路径、WNS/TNS、可满足的 II | ns；此设计目标 II=1，不等于已满足 STA |
| active / burst / idle 动态功率 | μW；同时给统计窗口和有效项数 |
| 内部功率 / 网络翻转功率 / 漏电 | 分列，避免只比较部分功率 |
| active、burst 总能量及每有效项能量 | pJ，按同一窗口 `E=∫Pdt` 计算 |
| 稳态 idle 功率 | μW，包含寄存器/时钟实际实现的成本 |
| 活动覆盖率、是否门级/SDF/寄生 | 标明精度层级及缺失项 |
| 综合网表、约束、报告及活动文件 SHA-256 | 工艺库本体不上传公共仓库 |

这些参数返回后，可以替换 TLM 里目前按非线性/向量操作数计算的代理能量，并校验单通道、复制通道数和实际供数速率。完整 FFN 能效仍需加上随机矩阵阵列、权重存储、前后缓冲、转换、时钟和调度停顿，不能只用该模块的面积/功耗代表整个 FFN。
