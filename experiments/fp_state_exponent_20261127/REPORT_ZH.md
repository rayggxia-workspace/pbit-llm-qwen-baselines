# FP24后续编码与指数位数验证

2026-11-27，Issue225 / PR266。

**两个模型的本次数值回放均支持将状态从E8/M15压缩为E6/M15，即由24位改为22位：每一步和最终值均与原FP24一致，无上溢或下溢。FP24后续可以直接用整数逻辑完成概率编码，不需要重新经过FP32。**

## 实际指数有多大

以下是非零数的无偏指数e，即数值表示为±m×2^e、1≤m<2。统计每个K64块结束后真正写回的状态，包含中间结果，不仅是最终输出。零单独统计。

|模型与路径|全部写回状态指数范围|中间99.8%的指数区间|非零写回状态数|
|---|---:|---:|---:|
|Qwen3-4B T64，GU|−18～7|−11～3|2,211,594|
|Qwen3-4B T64，Wd|−18～12|−12～6|5,595,808|
|Qwen2.5-0.5B-Instruct，GU|−17～3|−11～2|1,547,984|
|Qwen2.5-0.5B-Instruct，Wd|−17～10|−13～3|5,602,438|

“中间99.8%”采用0.1%和99.9%经验分位端点；离散边界处实际覆盖率不低于该值。临时tile最小指数在4B中为−19，比最终输出更小，因此不能只看最终g/u来定指数位数。

|存储候选|正常数指数范围|4B结果|0.5B结果|
|---|---:|---|---|
|E8/M15，共24位|−126～127|原参考|原参考|
|**E6/M15，共22位**|**−30～31**|**所有状态及最终值与参考一致**|**所有状态及最终值与参考一致**|
|E5/M15，共21位|−14～15|GU/Wd下溢167/763次|GU/Wd下溢31/1,628次|
|E6/M17，共24位|−30～31|无上下溢，有效精度增加2位|无上下溢，有效精度增加2位|

E6采用偏置31。将E8存储改为E6需要重新编码指数，读回时恢复偏置，不能直接切掉原指数的高两位。表中E5采用常见偏置15、保留零/特殊指数的规则；换用自定义偏置和有限值编码是另一种格式，未在这里测试。

本轮“窄指数”只改变写回状态；临时tile保持E8指数，以隔离存储压缩。E6/M15的每个前缀状态都没有触碰范围边界，因此逐步结果相同，而非仅最终输出偶然相同。

## 得到FP24后怎样送入P-CIM

FP24已经包含符号、数量级和有效数字，后续无需再从宽整数中搜索最高有效位。不过，P8表示相对于所选尺度的幅度，仍需根据指数作少量移位和最近偶数舍入，不能固定截取尾数前8位。

1. **选尺度。** 每64项比较绝对值，选最小覆盖二次幂S；每个元素按当前规则使用S或S/2。浮点数的绝对值排序可直接比较指数和尾数，二次幂尺度可由最大值的指数及尾数是否恰为零生成。
2. **生成幅度P8。** 设包含隐含首位的16位有效数为M，值为±M×2^(e−15)，所选尺度为2^E，则概率码为RNE(M×2^(e−E−7))。保留当前255码与精确满幅256旁路规则。
3. **生成sigmoid地址。** 若使用原始g，则S8/F3地址为饱和RNE(g×8)，可直接由M和e移位得到。若保持现有PPL协议，则用幅度P8和所选指数重建g的地址。这两条路径都可用整数实现，但数值协议不同。
4. **Wd完成后。** 将状态转换为BF16，只需恢复8位偏置指数，并将尾数按RNE收至7位；正常范围内不需要通用乘法器或除法器。

本轮整数P8编码与现有参考逐项一致，原始g的S8/F3整数地址也与直接RNE参考一致。两项Slurm任务各6项CPU单测全部通过，包含跨指数随机输入和舍入边界。

同时确认了一项已有接口差异：4B的27,648个g中，原始g地址与P8重建g地址有1,624项不同，最终LUT阈值有1,046项不同（3.78%）；0.5B分别为2,055/55,296和1,956/55,296（3.54%阈值不同）。单项阈值差最大为8/256。它不等于PPL误差，现有PPL协议继续保持P8重建g，不能借此次位宽压缩静默切换到raw-g。

## 逻辑存储能省多少

以12槽、每槽128项为例：

|状态格式|每项位数|状态有效载荷|相对FP24|
|---|---:|---:|---:|
|原64位定点|64|12 KiB|—|
|32位定点|32|6 KiB|—|
|E8/M15|24|4.5 KiB|参考|
|**E6/M15**|**22**|**4.125 KiB**|**少8.33%，即384 B**|
|E6/M17|24|4.5 KiB|容量不变，保留更多有效位|

22位相对32位载荷减少31.25%，相对64位减少65.625%。这是数据容量，不是整片面积或能耗的同比降幅。例如每32项打包到128-bit存储字，24位需要6字、22位仍需6字；若不改变打包方式，宏容量可能不变。若物理接口仍按24/32位组织，也可选择E6/M17利用空出的指数位提高精度。

## 第二模型如何验证

采用官方后训练模型Qwen/Qwen2.5-0.5B-Instruct，固定revision `7ae557604adf67be50417f59c2c2f167def9a775`：24层，隐藏宽度896，FFN宽度4864。7个模型/分词器文件和官方LFS权重SHA核验通过。没有用旧Base缓存，也没有将4B的T64适配权重移植过去。

先运行未改动BF16完整WT2：292窗、299,077目标，PPL12.8361204；window2048/stride1024，原文不套聊天模板。随后取首、中、末三个真实上下文，每段4个token位置，覆盖全部24层；保留原模型前向不变，独立重放W8、GU16/Wd32、组64基准＋S/S2的完整FFN。W8每64×64 tile使用最小覆盖PoT尺度、RNE与幅值127；三流AND事件直接送Wd。GU覆盖14个K64块，Wd覆盖76个K64块。

共144个投影样本、110,592个GU最终值和73,728个Wd最终值；整数重放与GPU参考一致。诊断hook前后原生模型logits逐位一致，144份轨迹逐SHA校验通过。4B复用此前封存的36层真实128-token轨迹、完整40/152块，72份投影样本。

这些是局部算子和逐前缀数制验证，不是FP24/22随机模型的完整PPL。建议优先保留E6/M15作为存储候选，与E8/M15共享同一数值语义；下一步只需将浮点状态真正接入模型前向做PPL，并比较共享浮点累加器的电路成本。现有RTL/TLM默认、PPA与训练权重均未改动。
