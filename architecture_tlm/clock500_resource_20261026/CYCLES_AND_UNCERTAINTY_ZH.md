# 周期数、门控与物理证据的边界

500MHz每拍2ns；SRAM仍80MHz每拍12.5ns，HBM保留DRAMSys标准时序。本次保留原逻辑拍数和II，扩大显式资源。普通计算吞吐是可调架构假设，不是模拟器或55nm工艺库自动从功能推出。

| 功能 | 本次服务规则 | 边界 |
|---|---|---|
| 普通MAC | 2拍启动＋ceil(MAC数/每拍MAC数)，512或2048 MAC/拍 | 继承v6宏，阵列和局部端口未做500MHz STA |
| 向量/非线性 | 仍64/16路，按原vec函数取服务拍数 | 没有自动跟SC阵列一起扩容 |
| GU随机矩阵 | 1＋63×II1＋8＋2＝74拍/波 | Issue193计数frame为72拍；不是整个74拍阵列服务 |
| Wd三路AND直通 | 1＋(T−1)×II2＋8＋2：T64为137拍，T128为265拍 | 保留源/计数排空合同，没有用FP32精确SwiGLU替代 |
| 桶归约 | ceil(输出×档数/桶路数)＋2拍；路数64→256 | 4/7档规则宏 |
| 系数恢复 | ceil(输出/恢复路数)＋5拍；路数16→64 | 基准延迟6、II1；500MHz需重流水验证 |
| 宽部分和 | ceil(输出/累加路数)＋1拍；路数32→128 | signed64局部保存，R8窗口边界有访存 |
| 编码/场值/ROM/BF16恢复 | 分别64/64/16/16路，延迟3/2/1/3拍 | 原宏位宽/动作显式，但未完整500MHz电路闭环 |
| 时钟门控 | 排空后闲8拍停钟；请求时1拍唤醒 | 状态保留；ICG/CTS待表征 |

8阵列满波512输出，32阵列2048输出。后处理路数同步×4，GU仍74＋34＋37＋17＝162拍/波，Wd128为265＋58＋37＋17＝377拍/波，输出数变4倍。这是局部服务，不能把整机时间简单除以20。
实现入口：unified_v6/config.py、ffn_latest.py::batch_cycles、ffn_locality.py::context、ffn_local_pipeline_20261025/model.py。老宏来自早期可调预算；Sanger等论文可说明这种建模层级常见，不能证明我们的BF16电路已满足500MHz。

## 存储与并行

- 每SC权重波128KiB，双bank共256KiB；完整回包缓冲128KiB＋系数，下一波可与当前计算重叠，不假设整层驻留。
- R8是保存8个K64块的部分和，不是8组输入并行。窗口边界仍访问SRAM，权重每逻辑tile取一次，不是每个采样周期从DRAM取。
- 共享8MiB使用E宏/512bank，bank仍80MHz，聚合峰值655.36GB/s，fabric限定512GB/s；20ns CDC宏仍计入。更多bank意味着更多外围面积。
- HBM按真实DRAMSys请求、队列、响应和burst执行；上游HBM电流是零占位，物理能耗未知。
- 2048 MAC/拍的本地权重供给合同是4096B/拍，500MHz对应2.048TB/s本地聚合读口；不能由512GB/s共享SRAM自动证明。
- 地址和logits属于行为事务，不是真的Qwen权重推理，本轮没有新PPL。

## 门控与能量

Issue193 idle功耗的时钟一直翻转；数据CE不等于门控。计算模块空闲可停钟，但仍有漏电、部分输入活动、控制开销。
能量＝漏电×总时间＋开钟周期×idle动态每拍能量＋实际操作增量能量＋关钟期间残余动态；不同时叠加毛能量与扣空闲增量。
默认条件情景只去掉关钟窗口80%的原idle动态，并报告50%/100%敏感性。500MHz动态功率随频率一阶外推，泄漏不乘5，面积不因门控直接减少。ICG、CTS、布线、唤醒与提频修复未计价，不能当作零。
新restore RTL包含桶归约，TLM保守拆为串行两段；PPA只收一次硬件和活动增量，开钟时间用两段占用之和截到总时长的保守上界。流水线合并、精确联合占用与500MHzSTA待验证。
