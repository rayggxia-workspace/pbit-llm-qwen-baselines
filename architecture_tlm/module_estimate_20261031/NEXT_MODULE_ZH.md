# 当前改进落在哪里，下一模块做什么

2026-11-01，Issue225/PR226补充。仅审计原初估，不改变原RESULTS、模块或TLM默认，无新模型/RTL/DRAMSys运行。

## 1. 变化总表：主要降低FFN后半段的报价

以下为Qwen3-4B、B1/2K、256个NL核与8KV组并行的原情景，单位mJ/token。分项范围来自同一组四个情景，不把各行独立极值相加当新情景。

|分项|旧预算|新预算|变化解释|
|---|---:|---:|---|
|GU与Wd计数、恢复及新非线性核|49.97|34.20–37.07|主要降幅；新Wd集成实测取代旧代理，且NL采样T128→T64|
|共享数字MAC|17.98|16.69–17.14|有用MAC数没减少；主要随总时长缩短而减少背景费用|
|片上SRAM、数字本地缓冲及DMA缓冲|21.30|21.30|旧流量/价格基本原样保留，尚未取得新联合调度的节省|
|Attention采样器、PV与筛选逻辑|1.94|0.387–0.400|完整新采样核+新ADD价替换旧端点预算；混有源/采样数/背景口径变化|
|FFN随机源预留、跨K及其余项|1.80|1.65–1.70|主要保留旧价和按时间缩短的背景，并非新随机前端全接入|
|片上已计价合计|92.99|74.22–77.62|条件预算，不是完整芯片PPA或同质量消融|

FFN第一行节省约12.9–15.8mJ，是本轮主要收益。其新预算内部又分为：**GU保留计数/恢复约30.63–31.13mJ；新非线性→Wd活动+闲置约3.57–5.95mJ**。因此不能把1.470mJ本核活动当完整FFN，也不能认为GU已得到同样细化。

新估计仍混合了两类变化：电路价格由代理换成实测；算法/资源从NL T128变T64、旧max4/准确Softmax+PV变SparQ/赢家保持、增加KV组局部并行。不能把总差额全部解释为同资源同质量的电路结构节省。

## 2. 时间下降在哪里

|阶段|旧ms/token|当前初估ms/token|判断|
|---|---:|---:|---|
|Wg/Wu|14.98|14.98|仍用旧时序，未因新Wd核而加速|
|整个FFN阶段|25.21|25.21–26.63|不降，可能略增；新Wd100MHz计算忙时由旧5.80变7.22ms|
|QKV/O投影|16.36|16.36|仍是包含供数等待的旧阶段时间|
|lm_head/argmax|6.82|6.82|仍用旧阶段时间|
|Attention核心|8.95|3.18–3.80|来自8个KV组局部服务并行的条件推算|

所以52–54ms的改善主要依赖Attention并行，**不是新FFN电路已被证明更快**。只用一组Attention局部资源则整机74–80ms。1MiB局部预留能放进8MiB只证明容量可容纳，不能证明8组请求在同一SRAM/DDR上能按该时间完成。需要银行分配、实际端口、全局DMA在途/回压和共享后端联合重放。普通MAC500MHz与新核100MHz也是条件异频配置，接口/目标STA尚未闭合。

按当前初估，FFN阶段约占整token一半，QKV/O约三成、lm_head约一成多；但阶段包括供数、排队和恢复，不能把它们全部当算术忙时。旧GU阵列忙时仅约2.13ms，其14.98ms阶段中的其他时间还包括供数、恢复和调度。

## 3. 哪些已经细化，哪些还留在代理层

|Attention PV与筛选|匹配BF16→FP32 ADD、筛选逻辑、V去重/重复累加和有限队列回放|8组并行共享访存；最终归一化/输出等缺项；硬件量化/源与质量闭环|

“有数据但还没接入”与“必须再仿真”要分开。例：GF64完整核已有开钟idle 0.211867mW/实例，原初估只加活动核价，未加此闲置状态。利用现有数据、8实例和保留S128工作时长作敏感性，约需另加**0.087–0.090mJ/token**，片上范围变74.31–77.71mJ，排序和74–78的总括不变。它是开钟idle诊断，不是已测停钟泄漏；无需先重跑这项PPA。FFN随机源也有既有数据，缺的是实际源数量/共享/开启时间与核边界对应，不能把旧含比较器端点整价当纯源实测。

## 4. 当前最大问题与优先顺序

**电路模块优先做GU集成核；时间结论优先做统一存储调度接入。** 两者解决不同问题。

1. **GU保留报价最大，而且还可能过时。** 约31mJ、占新片上约四成，来自保留旧计数/恢复池而非本轮GU集成PPA。旧B7外推也覆盖GU，不能据它认定真实GU电路一定耗这么多。先固定当前输入与权重尺度合同，再判断需要几桶；若每64输入同一PoT尺度、相应权重块同一PoT尺度，组内可能只需一份加权和，无需逐元素4/7桶。不能在未确认数值合同前直接删除桶。
2. **外存决定总能量，但目前价仍是代理。** 约349mJ/次的外存占条件整机能量约八成，远高于新NL核。应把统一配置的命令/背景状态从现有DRAMSys/DRAMPower接回；这项主要是软件和参数整合，不是要求去仿真DRAM器件。不能用局部DDR4独立回放总功耗乘288，再叠全片背景。
3. **同资源/面积公平性未闭合。** 新256个64×8核匹配旧2048输出列，但旧GU池仍保留，再增加新核约28.22mm²；相同列数不等于相同总面积。8个Attention局部服务也需要实际分配算术和端口。当前不支持“同面积更快”结论。
4. **数值版本不统一。** 硬件交接k128、signed8/F4、burn0/GF64与训练k256、差分8位驱动/预热等不是同一配置；FFN分组尺度及64拍事件规则也需与训练绑定。不能只因为都是P8/S64就继承PPL。

## 5. 下一份GU模块应交付什么

这是建议，未启动新RTL或仿真，也未改已有训练方案。建议用一个可复制的**64输入×8输出GU代表核**，与当前Wd核工作粒度对齐；不必把整层做成RTL。

- 数值：固定W8、x为8位概率幅度+符号，T64精确归约作主参考；先核对“64输入共享PoT尺度”和W尺度的粒度。RNG比较、位权/符号、尺度、舍入和饱和全部在合同内。
- 数据通路：x比较前端共享给多列，W从驻留SRAM抽象接口稳定提供；采样期计数留本地，不逐拍写SRAM。单K64组在abs(W)<=127/T64时累加界为64×127×64=520192，signed20可容纳；跨K/指数对齐要更宽，不能把20位直接当全矩阵宽度。
- 出口：跨K对齐/累加后，按确定的RNE/饱和得到下一模块需要的g/u码。PoT可用移位，但仍必须标定动态量化/选择逻辑，不能用理想FP32隐藏。明确GU到现有g8/F3、u幅度接口的数值等价。
- 时序/PPA：实际首valid、服务II、连续帧、stall、输入保持、真ICG/开钟idle/停源状态；同时给前端与列后端分项，便于共享前端。先100MHz实测，500MHz若无STA支持则作单独资源情景，不能继承旧拍数便称达标。

**其次才优化新Wd核的横向前端复用。** 当前每8列一套64路非线性前端，复制256整核会重复LUT/转换/比较。可研究一个64路前端广播给更多列、保持同一事件流；这不同于已测的32路LUT时分共享（66→98拍，省面积但未省帧能量）。分开前端/后端后还需计广播带载，不能将前端删除后把连线成本置零。

短期不建议把主精力继续放在OR缩位或把Ising采样核再省几pJ：它们或有质量代价，或在当前总账中份额太小。先把GU大代理替换成集成核价，并让同一套存储后端实际接收两处新模块请求，更能判断我们架构的真正收益。
