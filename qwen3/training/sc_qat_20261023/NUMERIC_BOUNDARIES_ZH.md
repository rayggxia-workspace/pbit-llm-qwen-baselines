# 整数累加、8位接口与Python/TLM的共同数制约定

2026-10-24，Issue159/PR170。接续用户明确要求：Python可以使用FP32作为模拟工具；被模拟的每一次数值生成、转换和计算必须对应目标电路行为。TLM据同一行为描述资源、时间及能耗，不允许把算法上的理想转换当作免费硬件。没有RTL时可以先采用有边界、有参数来源的宏模块。

## 1. 累加器位宽和输出位宽是两个问题

固定W8码范围−127…127，输入幅度流b为0/1，符号独立。在一个共同尺度的N输入块内，T拍的带符号整数累加为：

`C = sum_t sum_i sign(x_i) * w_int[i] * b_i(t)`

保守界是 `|C| <= M=N*T*127`。支持正负M的二补码累加器最小位宽为 `1+ceil(log2(M+1))`。这是无溢出最坏界，不是激活统计范围，也不是每个电路实现必须放置一个同宽大进位加法器；CSA和分位平面可改变内部表示。

| 输入范围 | T16 | T32 | T64 |
|---|---:|---:|---:|
| 64输入、单一尺度的局部整数累加 | 18位 | 19位 | 20位 |
| 2560输入全部同尺度的合并整数累加 | 24位 | 25位 | 26位 |

第二行仅说明Qwen3-4B gate/up输入宽度带来的归约增位，**不是已确定的完整FFN累加器位宽**。真实分档/分tile有不同Sx和权重scale，对齐、scale乘法、保留小数位还会改变上界。四档间隔2的指数跨度为6，对齐到最细单位可能需要额外高位；不能无条件直接把19位当成完整输出格式。W4/W6用Qmax=7/31重算，同T32、N64分别15/17位。

不同计数结构也不能混称8位：T32的单路1计数范围0…32，需要6位；N64×T32的单个位平面非负计数0…2048，需要12位；加上INT8位权及符号归约后的同尺度有符号总数才是19位。

### 可以在输出压成8位

建议结构是：`宽整数计数 → 明确的尺度对齐/归约 → 舍入/饱和 → 8位接口码`。不能用8位计数器在每拍静默溢出，也不能假定每拍右移和最后一次右移等价。

对固定共同尺度，g_hat = (Sx*weight_scale/T)*C。若系数与目标输出步长之比是二次幂，输出码可用移位、舍入和饱和得到；否则采用已量化的乘数及移位宏，或重新约束权重尺度。原任意实数weight_scale不能作为免费转换。跨tile时，先定义共同累加单位、舍入位置、允许的最大移位和溢出行为，再推导宽度。

“8位”须明确：传统有符号INT8通常采用−127…127；历史A8是0…255幅度码外加符号，还可能需要true-one标志，不是总共8位。沿用历史随机比较器时，可以把g/u的幅度概率码设为A8，但g/u的真实数值还需要尺度和符号元数据。

共用一个固定尺度能统一电路，但尺度越大，8位步长越大。把范围放大只解决装不下，不保证精度足够。先按每层/每64通道固定PoT尺度，分别统计g/u裁剪率、零码率、误差和匹配PPL；不能从旧0.5B结果保证Qwen3-4B的8位足够。8位作为候选，10/12位作诊断对照；本次没有启动这些评测。

## 2. Python的dtype不等于目标硬件的数制

允许Python/PyTorch用float32或float64保存、向量化计算定点模拟值，只要它们产生与约定电路相同的有效输出；不要求用Python逐门执行。比如整数门限R∈0…255，幅度码q∈0…255，比较`R<q`即可模拟A8比较器，true-one单独处理。用浮点存储这些精确整数不改变比较语义。

但无约束FP32 SiLU与实际低精度响应不是同一操作。允许用浮点数学离线生成LUT，运行模拟必须使用冻结LUT/有限输入码/量化输出或已标定响应；若用物理p-bit宏，可规定驱动码、输入增益/裁剪、概率响应、更新间隔和相关性，不必先写数字LUT电路。

宽累加还要核对模拟容器自身精度：FP32只能保证整数精确到2^24。N2560、T64、W8最坏整数20,807,680超过此界，不能用FP32承载所有可能整数并宣称逐位一致。参考应选足够宽的整数容器，显式模拟目标截断/溢出；或证明使用的浮点容器对所需运算精确。FP64也不是无限精度。

训练主权重、优化器、教师和反向可以保持浮点。部署学生的前向必须遵守同一数值契约；STE只是反向代理，不是绕过硬件舍入或随机响应的许可。

## 3. 算法与TLM共用契约，分别负责质量和代价

| 宏模块 | 功能模拟必须规定 | TLM必须计入 |
|---|---|---|
| 输入格式→概率码 | 输入格式、尺度读取、取档、round/clip、q/256及满幅 | 输入/尺度读写、比较/移位或转换、latency/II、lane及缓冲 |
| SC矩阵及计数 | W码/scale、输入流联合分布、符号、累加位宽/溢出 | 样本数、阵列并行度、计数更新、权重驻留/读取及源接口 |
| 分档/跨tile恢复 | 共同小数点、scale格式、对齐顺序、保护位及舍入 | 移位/缩放/加法资源、实际中间字节、队列及回压 |
| g/u压缩 | 各自输出格式、固定/动态范围、饱和策略 | 量化宏、固定表读取；若动态则max归约也计入 |
| sigmoid/p-bit驱动 | g码→驱动；响应曲线或LUT、有限精度及相关性 | 查表/转换或模拟驱动成本、设置/更新/采样间隔 |
| 三流AND及down | 三流独立性、符号、尺度、非线性T及下游计数 | SNG/源端口、AND、统计、down调度及可能的缓冲 |
| 最终接口 | 恢复到BF16/残差的格式、舍入、饱和及异常范围 | 格式转换、残差加法、存储/带宽和依赖 |

每个宏的契约应含：输入/输出格式与单位、功能规则、参数与范围、随机规则、latency、II、lane、状态容量、读写、动作能量/面积/状态功率、来源版本及验证级别。算法、训练配置、导出模型与TLM记录同一个契约SHA；修改数值边界后不继承旧PPL/旧PPA。

**允许尚无RTL，但不能没有定义。** 已定义功能而PPA未知时，可以用标注来源的估计区间做敏感性分析；未知值保持unknown，不能填0。没有延迟依据时也可以用显式条件假设，但结果只能是条件估算。功能格式/转换仍未定义时，不能靠一个理想宏替它声称硬件质量已通过。

TLM不必重算全模型张量；可消费经验证的算子trace/事件，但必须保留影响结论的容量、依赖、访存、排队及采样工作量。宏调用必须能追溯到实际电路工作，不把exp、任意除法、重定标或浮点恢复隐藏为零周期/零能量。
