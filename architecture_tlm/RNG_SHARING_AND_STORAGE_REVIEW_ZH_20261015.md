# 输入随机源共享、分层 PRNG 与存储：最新实现核对

日期：2026-10-15。结论：输入侧优先采用“本地长状态 PRNG＋同字广播”，以种子/状态重放替代长随机字缓存；保留不同通道的阈值。权重侧随机源仍是当前双随机模型的最大成本，不能把输入侧共享收益直接推广给权重侧。

## 1. 两种“共享”解决的问题不同

| 方式 | 给 64 路比较器的随机字 | 主要收益 | 当前验证状态 |
|---|---|---|---|
| 本轮 PPL 的直接共享 | 同一个 8 位字 R | 少产生随机字；允许较强通道相关性 | IID 随机字、准确累加的完整 WT2 已测 |
| `rng32x64` 的扩展网络 | 64 个不同字 R_i | 共用 32 位状态，同时改善跨路联合分布 | 秩证明、合成序列、RTL 表达式检查；未测实际 Qwen PPL 或工艺 PPA |
| `rng_hierarchy.py` | 共享输入服务＋各阵列附近的大量权重 PRNG | 避免把海量权重随机数经全局池串行输送 | 宏模型与小规模 Bivium 位流检查；未测该实际源驱动的 Qwen PPL |

对准确累加的输入路径，共用 R 后，每路的边缘概率不变，但通道间误差相关性改变。
本轮三种子平均结果：固定权重 PPL 12.4387→12.4535，约 +0.12%；双随机权重
PPL 14.1106→14.1483，约 +0.27%。后者的权重噪声仍为条件高斯近似。

所以 **64 路输入不必强求 64 个低相关随机字**。在这一模式中，扩展网络可以旁路，
直接取一个字广播。面积版可省去输出网络的 504 个 XOR2；快速版对应 516 个。
仍需保留 32 位 LFSR 状态、反馈/跳步更新、64 个比较器、控制与实际布线缓冲。
沿用当前 16 步展开时，更新网络另有 61 个 XOR2，不能一并算作省掉。

建议保留长状态：**8 位输出不等于 8 位 LFSR 状态**。最大周期 8 位 LFSR 只有
255 个非零状态，4096 拍中会多次重复；不能视为本次 IID 随机字实验的直接实现。
32 位 LFSR 的具体取字、跳步、seed、停顿与重放规则仍需用实际序列验证。

扩展网络仍可作为需要低相关事件的候选，尤其是权重侧和直接相乘的两个随机操作数。
输入流与权重流不能直接使用同一个 R：两路阈值 p、q 的 AND 概率会成为
min(p,q)，而不是 p×q。固定二进制权重没有这个双随机独立性要求。

另一个边界是 OR：本轮共享实验采用准确空间累加。若 64 路阈值相同，共用 R
会使它们同时为 1；准确计数得到 64，OR 却只得到 1。故不能用本轮 PPL 证明
共享源与 OR2/4/8 组合仍有效；它需要另测，或采用配套互斥重映射。

## 2. 最新 TLM 实际上还保留了什么

代码核对位置：

- `system_decode.py::stochastic_matrix`：仍为 64 路各申请 12 位随机字，预生成
  T 拍，整段写 SRAM，再按输出波次读出重放。
- `rng_hierarchy.py::shared_words`：按请求 bit 数服务；尚无 64 路同字广播模式。
- `rng_reference.py::input_bits`：仍为每一路分别取 12 位字；缓存的是输入比较结果。
- `rng_hierarchy.py::weight_wave`：仍按 64×64 个权重事件供给，每列 4 个 Bivium，
  每阵列 256 个核，8 个阵列共 2048 个本地核。
- `run_rng_hierarchy.py` 刻意检查新旧架构的内存流量相同，因此“分层”尚未减少 replay。
- `system_decode.py::sc_kernel_power` 已按 `share_frontend_per_tile=true`
  把 64 个输出列的输入阈值、符号寄存器及比较前端共用一次。
  但不同阵列之间尚未进一步共用。
- 旧 `model.py` 是单核存储工作台，仍按输出列复制阈值寄存器，不等同于最新系统模型。
- TLM 的双随机 PPL 引用仍是旧独立采样参考；不能把它当作实际 Bivium 或 LFSR
  源的质量验证，也不能自动替换成本轮 A8 共享实验的 PPL。

## 3. 哪些寄存器/缓存能省

“概率阈值”“PRNG 状态”“随机字缓存”必须分开。

| 对象 | 是否因共享随机源而消失 | 建议 |
|---|---|---|
| 每路输入阈值 q_i、符号 | 不消失；64 个输入值不同 | 每组存一份，跨输出列/同步阵列广播；只在换输入时写入 |
| PRNG 状态 | 可大幅合并，但需遵守相关性协议 | 输入用少量本地长状态源；独立性敏感路径保留不同源/端口 |
| T 拍随机字 replay | 可以压缩，或用状态重放替代 | 首选保存起始状态，再生同一序列 |
| 权重 SRAM/权重幅值阈值 | 不消失；由模型参数量决定 | 装载后保持，避免逐拍读取/写入大权重阵列 |
| 结果计数器、跨输入块部分和 | 不消失；保存累计结果 | 沿用缓存累加/压缩器等结构，独立评估位宽和时钟门控 |

### 输入前端的位数

旧 RTL 每路概率使用 13 位（支持端点码 4096），加 1 位符号，共 14 位。

| 范围 | 阈值＋符号存储 |
|---|---:|
| 旧工作台：64 输出列各复制、8 阵列 | 458,752 bit = 56 KiB |
| 当前系统假设：每 64×64 阵列一份、8 阵列 | 7,168 bit = 896 byte |
| A8 编码：每阵列一份、8 阵列 | 4,608 bit = 576 byte |
| A8 编码：8 个同步阵列共用一份前端 | 576 bit = 72 byte |

最后一项需要同一输入 tile 的多个输出阵列同步消费，且应实测广播扇出/时序。
它不是把 64 个不同阈值变成一个阈值，也不适用于同时处理不同输入的阵列。
这里 A8 指本轮 0…255 阈值、q/256 编码；若要求额外表示概率恰为 1，需另留端点控制。

阈值在 4096 拍内不变，配置寄存器可用真实 ICG/适当保持结构，配置时才开时钟。
RTL 中 `if(cfg_we)` 只保证数据保持，并不保证综合后时钟被门控。旧功耗分项在数据
基本不切换时仍有较大寄存器 internal power；是否为时钟内部功耗应由 PT 分项确认。
本地 PRNG 本身不会自动替这些阈值寄存器关时钟。

### 随机序列重放

以一个 64 输入 tile、T=4096 为例：

| 重放策略 | 序列数据容量 |
|---|---:|
| 当前 64 路独立 12 位随机字 | 384 KiB |
| 64 路独立 8 位随机字 | 256 KiB |
| 64 路共用一个 8 位字，缓存整个序列 | 4 KiB |
| 保存 32 位 LFSR 起始状态并重新生成 | 起始状态 4 byte；另有工作状态 4 byte 和控制 |

后两项分别来自共享策略和确定性 PRNG 的可重放性。种子重放甚至在独立多端口方案中
也可采用；它不是共享随机数才有的性质。

每个输出波开始恢复同一输入 tile 的起始状态，执行同样的使能步数，即可重建相同
输入采样；输入值、概率、符号也必须保持可用。各层、token、输入组和阶段仍需有
不同且明确的流身份，不能反复拿同一个 seed 从头生成所有任务的输入噪声。
保存/恢复和反复生成有成本；不应把“没有长缓存”记成“没有随机源活动”。

权重源应保持独立的状态/域与更新协议，不能随输入重放一起不加区分地复位。
若多个消费者会停顿，必须按实际消费握手推进 PRNG，而非按墙钟盲目推进。

**容量的额外限制：**当前系统的 scratch 峰值为 609,536 byte，来自完整词表
logits（含接口向量），大于 384 KiB replay 加部分和的峰值。因此删掉 replay
不等于可以按 96 倍缩小整块 1 MiB scratch SRAM；当前峰值约 595.25 KiB 仍在。

## 4. 从最新账目看，节能重点在哪里

基准：24 层、2K context、2 个 decode token、T4096、8 阵列、100MHz。
这里使用已有 **简化 Link 外存** 的分层结果，而非 DRAMSys 新测结果。
PRNG 更新单价、面积、数字成本等含占位参数，以下用于排优先级。

| 双随机分层模型分项 | mJ/token | 意义 |
|---|---:|---|
| 本地权重 PRNG 更新 | 1285.269 | 总情景能耗的 84.10% |
| 本地权重随机数选择/比较 | 64.263 | 仍要处理大量不同权重阈值 |
| SC 核活动 | 66.210 | 当前仍用固定权重核作为双随机代理 |
| 输入随机字 replay 读写 | 10.438 | 属于 scratch_access，不是另加的一项 |
| 输入共享 PRNG 更新＋分发 | 1.359 | 不是当前主要瓶颈 |
| 阈值＋符号寄存器 internal 能量的删除上限 | 1.621 | 已按阵列共享；非实测门控收益，不能全当可省 |
| 总情景能耗 | 1528.291 | 未标定的完整系统估算 |

本地权重核状态：2048×177 = 362,496 bit，约 44.25 KiB；输入侧 8 个核另计。
这比当前 896 byte 的输入阈值＋符号大得多。若说“寄存器多”，现在更需要关注
权重 RNG 的状态与其 160-bit 展开逻辑，而不是继续按旧单输出 RTL 判断概率寄存器。

只把 384 KiB replay 改为 4 KiB，其他操作不变，原 replay 动态访问预算从
10.438 降为 0.109 mJ/token，减少约 10.329 mJ/token。

- 双随机总预算下约为 **0.68%**，尚未计源替换、时间变化及布线差异。
- 本次另跑固定权重的原分层配置，总预算 177.694 mJ/token，约为 **5.81%**。
- 再改成状态重放可进一步删除这 0.109 mJ 的缓存访问，但必须加入再生 PRNG 成本。
- 当前阈值寄存器的时钟优化删除上限约 1.621 mJ/token，不能把旧复制前端的高占比
  重复套用到最新已共享前端上。跨阵列前端合并和寄存器门控的收益相互重叠，不可直接相加。

时间上，当前每 token 约 53.093 ms 花在预生成输入随机字，另有 13.271 ms
写 replay 的串行预算。若改成计算期间本地产生，可尝试重叠/去掉这些阶段；
但源重启、端口争用、重播种和外存响应必须重跑调度，不能把约 66 ms 的删除预算
直接当成已经获得的加速。每 token 的 SC 波次计算服务本身约 411 ms，4096 拍仍在。

局部化本身也不保证收益：本次固定权重基准里，全局池为 486.351 ms/token、
175.987 mJ/token；原分层配置为 510.216 ms/token、177.694 mJ/token。
原因包括所配置的吞吐和旧 replay 调度，并不是某种源位置具有天然优势。

## 5. 建议的下一版架构与 TLM 接口

1. **输入前端先简化。** 同步 FFN 阵列簇旁放少量 32 位长状态 PRNG，每拍取一个
   8 位字，广播给 64 个比较器；旁路低相关扩展网。按物理负载选择一份集中前端
   或几份局部副本，不默认全芯片同一个随机字。
2. **用状态重放替代大随机字缓存。** 输入 tile 持有起始状态与阈值，按输出波次再生；
   计入每次实际更新、恢复状态、输入阈值装载和广播，不能只减少 SRAM 计数。
3. **权重路径单独降成本。** 保留与输入的独立性，比较更便宜的 LFSR/少量状态加
   低相关扩展网络与现有 2048 个 Bivium。先维持原每连接权重事件语义，再逐步试
   权重间共享；本轮输入共享 PPL 并没有验证后者。
4. **输入阈值保留小银行。** 概率、符号与尺度从激活 SRAM 装载，小寄存器银行在
   采样时保持；只开必要时钟，避免用 SRAM 每拍读全部阈值来替代小银行。
5. **TLM 把独立旋钮拆开。** `input_word_bits`、`input_share_group`、
   `source_placement`、`stream_identity`、`replay_mode`、`state_bits`、
   `frontend_replication`、`threshold_clock_gating` 和权重源模式分别配置。
   吞吐、更新能量、seed 恢复、分发与状态/阈值面积分开计费；不把 input_share=64
   自动解释为权重源也减少 64 倍。
6. **实际源验证后再更新质量引用。** 按 RTL 的 16 步更新、取字与停顿/重放规则
   跑实际位流或等价联合计数，再检查固定权重 PPL；权重路径改变时另测。
   使用新流的活动文件做 PT，旧 IID 输入下的加法树/比较器切换率也可能变化。

本次完成的是最新代码核对、固定权重基准补跑和预算分析；没有改动现有 TLM 主调度
或将上述候选写成已经实现的新硬件。
