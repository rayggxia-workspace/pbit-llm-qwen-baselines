# 概率计算如何降低大模型推理成本

两页说明  ·  面向项目讨论  ·  2026年10月23日

我们的目标是在模型回答质量基本可接受的前提下，降低每生成一个词元的能耗和芯片面积，同时控制等待时间。主要办法是让部分计算使用更简单的电路，并减少不必要的数据读取。概率计算有节省空间，但完整收益仍需用实际电路和系统运行验证。


## 一 功耗和面积从哪里省

概率计算用一串随机的0和1表示数值，例如“1出现的比例”表示大小。某些乘法因此可以由简单逻辑和计数完成。大模型中，我们重点考虑大量矩阵运算，以及决定读取哪些历史信息的注意力计算。

| 节省途径 | 为什么可能省 | 必须一起计入的成本 |

| --- | --- | --- |

| 简化计算电路 | 部分复杂乘法变成位操作、选择与累加，减少每次操作的电路规模。 | 随机数、比较器、计数器和格式转换；重复采样会抵消部分收益。 |

| 减少数据搬运 | 权重靠近计算单元并重复使用；注意力只读取筛选、采样后需要的数据。 | 筛选本身、地址处理及零散读取。片上SRAM和片外DRAM都不是免费存储。 |

| 压缩存储与共享资源 | 权重采用较低位宽；流式计数只保存累计状态；多个输入共享随机源。 | 缩放信息、缓冲及共享控制。低位宽收益也能用于普通数字芯片。 |


## 二 哪些收益现在可以说

现有系统模型的一组Qwen对照中，采用低位宽随机矩阵计算与筛选采样注意力后，已统计的片外读写量约减少32%～36%，片上读写量约减少30%～33%。这说明减少搬运有实际空间；它们是特定配置下的流量估计，不能直接当成整机省电比例。

面积方面，简单计算单元和较小的累计状态有望减少逻辑电路，但权重存储、缓存和互连仍占空间。为提速增加更多并行单元，还会把面积加回来。目前不能承诺整芯片缩小多少倍。

评价时应同时看每词元能量、每词元延迟和总面积。功率较低但运行更久，未必更节能；与GPU相比，还必须分清专用芯片带来的收益和概率算法额外带来的收益。


# 怎样控制速度开销并完成验证

随机计算的主要风险是反复采样：单次操作虽然简单，次数过多仍会变慢。因此，我们需要给采样、读写和中间处理都设定明确的预算，而不能只比较乘法器与逻辑门。


## 三 怎样避免运行时间大幅增长

缩短采样长度。先把不同大小的输入放到合适的数值范围，再用分层采样提高短序列的覆盖效率，争取用几十次而非数千次采样达到可接受质量。已有短流算法结果支持继续推进，但最新完整电路路径仍需对应验证。

并行计算并复用数据。让多个小计算单元同时工作，权重装入本地后连续使用；上一批计算时准备下一批数据。并行程度受真实读写带宽和面积限制，不能假定所有权重都能同时读出。

只处理需要的信息。先缩小注意力候选，再抽取需要读取的数据；将重复地址合并，并尽量成块读取。上下文变短时也减少采样预算，避免固定开销超过省掉的工作。

限制等待并保留退路。将恢复数值、累加和写回排成流水线。对可能反复尝试的采样器设置上限和可验证的回退策略；若某个模块始终不划算，就保留常规数字计算。

局部实验中，改善读出和流水线后，随机方案可以接近同资源的数字方案。这是继续推进的依据，完整模型的速度仍需验证。
