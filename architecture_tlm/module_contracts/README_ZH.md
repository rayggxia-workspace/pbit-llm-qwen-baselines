# 通用计算模块与 FP24 接口合同

2026-11-28，Issue225 / PR266。结论：以**矩阵、逐元素函数、归约、分布采样和索引访存**组织硬件；模型差异由任务图、张量形状和配置表达。跨块部分和及模块间的实数中间结果先采用 FP24 E8/M15。

## 1. 明确什么，而不是先为每个模型写控制器

|模块|任务粒度与接口|目前已有的能力|下一步扩展|
|---|---|---|---|
|P-CIM 线性核|K64×128物理输出；W8、P8事件输入；23bit整数局部结果＋指数|GU成对投影、Wd复用；T=8/16/32/64/128；精确计数|普通单路线性投影的调度适配，不能直接把GU的64g＋64u当128路同一投影|
|数值恢复与跨K累加|整数计数＋组合指数→FP24；FP24状态更新|12槽、每槽128项、两路32通道worker|与prefill多token状态、跨命令continuation对接|
|概率编码/逐元素前端|FP24输入→概率码/符号/尺度；LUT门概率；事件组合|x组64共享；g/u各自组64基准＋S/S2；sigmoid P8重建路径；三路AND|ReLU、GELU、GeGLU等新增LUT/模式及数值验证|
|共享数字矩阵/向量引擎|GEMM/GEMV、Norm、RoPE、残差等；按原生精度标价|已有BF16/FP32计算与接口|FP24收发格式桥接；不因接口变成FP24就假定已有FP24乘加器|
|Attention采样器|分数/阈值→V地址；独立采样预算与完成握手|现有赢家保持等方案|按选定版本绑定分数/LUT/RNG合同，不把FFN的P8码当分数|
|V gather与累加|地址＋次数→稀疏读取、返回合并、数值累加|沿现有Attention交接|必要的FP24格式桥接、返回乱序与回压验证|
|DMA、存储、随机服务|有限请求/返回；bank/端口；随机字消费握手|沿现有服务|具体模型尺寸与prefill重用策略接入|

这张表是逻辑能力划分，**不要求每行独占一套物理单元**。GU/Wd共核、共享状态worker和数字池继续复用。新增激活先映射为“矩阵＋逐元素LUT/乘法”，有质量与硬件证据后再融合为概率事件；不宣称所有函数都能只用一个AND门。

## 2. 统一三份合同

1. **数值合同**：[FP24_ZH.md](FP24_ZH.md)。明确每个字段是什么数、在哪里舍入、尺度在哪里恢复。
2. **任务合同**：[contract.json](contract.json) 与 [examples.json](examples.json)。明确模式、形状、数据位置、K范围、部分和归属、采样预算和依赖。它是软件/TLM任务记录，**不是已经综合的固定长度指令字**。
3. **执行合同**：`valid && ready`才接收，阻塞时数据与元数据保持；命令队列满就等待。权重写完才能启动；结果完整捕获后释放CIM，结果被消费后释放结果槽，最后K块提交/输出后释放状态槽。取消时停止新发、排空旧返回，再重用资源。

数值流：

```text
BF16模型接口 → 显式转换/概率编码 → P8＋符号＋尺度
  → W8 P-CIM整数采样 → 23bit计数＋指数
  → FP24逐tile恢复、跨K累加 → g/u FP24
  → 概率编码与sigmoid LUT → 三路AND事件 → Wd P-CIM
  → 23bit计数＋指数 → FP24跨K累加 → 显式转换至BF16
```

**FP24统一的是数值意义，不是全部物理位宽。** W8、P8、事件bit、地址、随机字、尺度指数仍各用自己的格式。中间存储建议FP24紧凑24bit打包；SRAM行填充、总线填充和转换必须另记字节/成本，不默认32bit容器等于24bit物理存储。

## 3. 怎么适配不同模型

模型配置提供层数、hidden/intermediate、Q/KV头数、head维度、Norm/激活类型、位置编码、词表，以及prefill/decode模式。任务展开器生成形状与依赖；局部核执行采样循环，全局控制器只管任务、资源和完成事件。

- **SwiGLU**：两路投影→g的sigmoid门→g·sigmoid(g)·u→Wd，沿当前事件融合路径。
- **GEGLU**：两路投影→g的GELU门→乘u→Wd。GELU可写为g·Φ(g)，需要Φ的LUT、符号/尺度及随机独立性验证；当前未实现该模式。
- **GELU/ReLU普通FFN**：单路上投影→逐元素函数→下投影；需要单路投影模式适配，不必复制全套控制器。
- **不同Attention**：普通MHA/GQA改变头数、KV布局和任务数量；DeltaNet、MLA、MoE等增加状态/路由要求，不能仅改矩阵尺寸便宣称支持。

矩阵尺寸尾块用有效lane mask，不能让填充通道参加最大值/尺度选择；`M`是token行数，`N`是物理输出数，`K`是输入维度。decode主要M=1，prefill有M>1的权重复用，**共享模块不等于共享同一种调度**。

## 4. 当前落地顺序

|步骤|动作|验收|
|---|---|---|
|A 已定|FP24数值接口、模块能力/任务字段|本目录验证器通过；来源SHA见results/SOURCE_BINDINGS.json|
|B 待接|prefill的21bit/64bit核与状态替换为23bit/FP24|同形状逐tile计数、两次舍入、最终输出、释放事件对齐；保留旧版结果|
|C 待接|完整层任务展开＋共享数字/Attention格式桥|至少SwiGLU及一个不同FFN结构的合成任务图；未知激活明确拒绝|
|D 待标定|真实SRAM组织及新转换/累加worker的时延、II、面积、能量|采用实际模块与工作点，重放资源竞争，再回填主TLM|

本轮核对的上游五核FFN和单层Decoder已经采用FP24；**旧prefill原型、旧多层model_rtl_services和主TLM未自动切换**。现有FP24合成功能结果不等于真实模型PPL、PPA或完整prefill结果。

需要特别补的适配有三项：

- 当前状态worker用`K==0`判定初始化。跨命令拆K时必须新增/适配`init/continue/final`与全局K偏移，否则新命令会清掉已有部分和。
- 当前worker在四拍捕获期间才完成一次输入握手；应由wrapper完整保持128项数据/元数据，或改为明确的32路逐beat握手，不能当成每拍接收一个新tile。
- FP24包输出overflow/underflow，但当前集成主要传播overflow；还需收集underflow计数。FP24→BF16边界必须检查舍入溢出，不能仅截取尾数。

验证命令（Python标准库即可）：

```powershell
python -B architecture_tlm/module_contracts/validate.py --self-test
```

本目录验证的是字段、边界与计划一致性；没有新增RTL仿真、工艺价格或GPU任务。后续模块只需填能力、数值、资源和完成事件四类信息，无需为每次优化另建一套整机TLM。
