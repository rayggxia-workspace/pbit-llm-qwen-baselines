## FFN：四档与分层如何进入硬件动作

1. **每64个输入动态确定顶档**：absmax 向上取二次幂；下档依次为 S/4、S/16、S/64。每个元素选能容纳自己的最小档，不重排通道、不主动裁剪大值。保存必要 q8、符号、档号和满幅旁路语义；这不是重复的概率寄存器银行。
2. **T32/K32**：门限0..255被分成32个宽度8的区间，每区间取一个3位层内随机偏移。一个随机字供同64路、跨四档共享。K1是IID；K256/T256是确定遍历，不把分层叫自然IID。
3. **固定 W8 与准确计数**：按8个位平面，对正/负输入和四档分别计数，再按二补码最高位负权、输入符号、档位尺度和W量化步长恢复。不是 OR 近似，也不是权重随机流。四档假定并行硬件，不能免费得到：计数工作、最大计数状态、恢复动作均输出；并非四次串行采样。
4. **跨输入组累加后才得到完整 g/u**。本版采用输入组优先的分块调度；gate/up 拼为同一投影，共用 x 抽样。不同输出波次恢复同一局部流状态，重放相同门限，保留共享协方差；不缓存T拍随机字。
5. 完整 g/u → FP32 SwiGLU → z重新分档/独立抽样 → Wd → FP32到BF16 → BF16残差。

权重量化和尺度元数据可离线准备。动态顶档、分档、概率编码、跨档恢复以及最后的BF16转换都有动作/时间，不能因输入尺度为2幂就忽略原W量化步长的恢复。`SC_encode_op`、`SC_restore_op` 是宏指令工作量模型，价格未标定；不能套旧4096拍G1的功率。

`bucket_code`、`stratified_thresholds`、`bitplane_reference` 是小形状功能对照。它们验证计数数学等价，不宣称有限硬件位宽/模型PPL已验收。既有数值方案来源、blob与SHA见 `SOURCE_INDEX.json`。

## Attention：流量如何真正减少

每个 KV 头对应的查询头组依次处理，避免一次保存全部头的分数、映射和摘要。

- 数字准确路径：K/V分块读取，GQA组共享一次物理读取；在线 Softmax，不物化 L×L 概率矩阵。FP32 PV 的能量未套 BF16 MAC 单价。
- PV路径：完整K→准确分数/Softmax→CDF顺序扫描，使用一个systematic随机偏移生成频数；不做S次二分搜索、不存S个随机数。与旧IID采样参考不同，不能直接继承旧PPL。
- 筛选：使用已合并max4摘要评分、标准化、sigmoid、独立保留判决；可选固定8块修复。当前不是训练中的小p-bit网络，也不是块间Ising退火。强制首块/末两块；配置不足时明确报错。
- 紧凑K：每个查询头保留自己的候选，GQA共享的K按候选并集读取，不能按逻辑保留率直接缩放物理K读取。
- 赢家/拒绝：重用已有v5 FSM，所有候选全宽提议，计数/仲裁/拒绝/偏移重编程/反馈/输出等待显式保留；不再支付另一个PV随机采样器。并行候选需要独立响应，不能套FFN的64路同门限共享。
- V：每个查询头先统计重复地址，再对同KV组求并集。V物理读取一次并广播给需要的查询头；重复次数进入准确选择加法，未删掉重复样本。物理突发对齐、32请求窗口排空与读写SRAM均计入。

筛选摘要在DRAM中持久保存，每个KV组读入SRAM使用；每个新token更新当前子摘要。摘要暖启动不是免费在SRAM常驻所有层。合成logits只用于决定事务地址；不将离线生成logits作为硬件额外完整QK，也不叫真实Qwen轨迹。`--trace`可接完整、逐token/layer/head匹配的既有logit格式，缺行/长度错误直接失败。

## 随机接口：第一版不建立随机流存储

`LocalRandomService.request(site, ready, words, width, parallel_lanes, semantic, frame, replay)` 是可替换端口；采样FSM内部源调用用 `embedded` 计需求，防止重复收费。

| 请求 | 共享/独立契约 | 存储 |
|---|---|---|
| FFN | 同64路共享R8；分层后只请求层内位；跨输出波次恢复同帧 | 随机流SRAM/FIFO=0；后端自身PRNG状态尚未定 |
| max4筛选 | 不同候选块独立判决 | 无随机字数组 |
| PV | 每查询头一个systematic偏移 | 无S随机数数组；必要CDF/频数仍存在 |
| 赢家/拒绝 | 每帧全候选独立有偏响应；公平随机位另计 | 无额外概率副本；响应/归约状态由采样器契约覆盖 |

默认假定需要处有足够本地供给，并给启动、帧切换、重放一个可调控制延迟。**这不表示随机源免费，也不表示实际后端已支持该并行度。** 需求、未知能量动作和接口限制随JSON发布。新帧是逻辑独立流请求，不要求每帧从外部重播种；实际种子策略由Issue95后端决定。全宽有偏响应的数值参考是理想Bernoulli，不因FFN采用8位就声称Attention驱动/DAC或随机阈值精度也是8位。本地数字p-bit还需要sigmoid概率转换与比较，其动作单独列出、成本待填。

按用户要求不计额外随机流SRAM/FIFO/概率副本。必要激活编码、计数器、部分和、候选映射和输出索引不因此消失。输出索引属于Attention结果，不属于随机数缓存。

## 调度与存储假设

- 常规矩阵按完整输出行分块，权重双缓冲有有限地址和释放时刻；下一块不能覆盖仍被消费的槽。比较方法共用同一资源配置。
- FFN保留gu→SwiGLU→down屏障，尚未自动搜索通道流水。下一版本可在同资源上比较loop顺序；本版不画出流水线就认为已优化。
- SRAM按字、bank和共用fabric预约。一个描述符占有所访问bank直到排空，是保守调度，不声称逐请求最优交错。
- 随机权重驻留宏接口假定完成装载后支持T拍稳定读取/选择；没有再添加DFF权重副本，但其输出能力、外围、面积/功耗仍须后续表征。`SC_resident_weight_feed_cycle`不设为免费。
- 新并行采样器请求期间保守占用sampler与SRAM fabric，逐输出留足一个SRAM写字时间，包含回压，没有隐含的大地址FIFO。以后可以验证并改成更细并行访问。
- DRAM默认Link按64B物理突发、32请求窗口排空。不是随机访问全部逐条支付一次完整延迟，也不是无限并发。DRAMSys接口可用完整JSON配置设置`backend/bridge_executable/configuration/output_prefix`；沿已有宏DMA barrier契约，尚未多DMA全局重排。

## 如何运行与看结果

仓库根目录，Python3.10+推荐（核心可用3.8，既有统一导航要求较新Python）：

```sh
python -m unittest architecture_tlm.unified_v6.test_model -v
python -m architecture_tlm.unified_v6.run --model qwen --context 2048 --output /absolute/new_directory
python -m architecture_tlm.unified_v6.run --suite --models qwen --contexts 2048 8192 --seeds 0 1 2 --include-winner --output /absolute/new_suite
```

运行前先提交执行源码；程序检查所有依赖与Git blob字节一致，再写不可覆盖的执行/配置/结果manifest。三模型结果各放在`qwen/llama1/llama2`子目录。

先看 `SUMMARY.json` 的时间、K/V物理流量、摘要流量和SRAM峰值；再看每项JSON的phase、资源忙闲、等待、动作和随机接口需求。`phase_ns`是相加覆盖总时间的阶段，`resource_busy_ns`允许不同资源重叠，不能再次加成总时延。事件只保存有上限的前缀，不把截断日志当全量轨迹。

**`priced_subtotal`仅是已有单价的部分和，不可用不同方法的该列比较总能效。** 完整物理能量、面积和新组合PPL保持null。SRAM宏内部成本有工艺依据；普通数字单价和Link DRAM单价明确为条件参数；随机源、B4阵列、恢复、FP32 PV、转换等缺失项按动作数单列。`V_selection_add`只是已计vector能量的活动别名，不能再重复收费。未来填成本时选择互斥模块边界，不能整宏和子动作重复收费。

本版回答“按这个具体执行策略，时间/流量主要受哪些因素约束”。真实精度和器件成本补齐后再做同质量J/token比较；若验证误差足以改变结论，再细化对应模块，不要求全模型逐门或逐周期运行。

## 交付时补充：接口与估计边界

- Issue95另行发布的PR97随机源服务在本任务执行期间已合并，merge27bf9c48。本轮52项仍冻结在fba22b1，未切换后端或改变数值源；新上游采样器的默认接口覆盖检查49项通过。FFN帧重放可对应SAVE/RESTORE/RELEASE；Attention需满足独立候选响应，不能因GF扩展有64路就当作联合独立。真实后端的多实例、空余lane、预热、种子包和背压应由适配器回填。
- 当前普通计算是可配置的抽象混合算术资源。W8数字对照暂也取512运算/周期，连续FP32的W8 FFN路径并不因此被证明能由已有BF16阵列原生执行；该速率与格式成本需要后续标定。此版不能用这个对照声称已测硬件优劣。
- x入口为BF16，z入口为FP32；两类编码活动分别记录。BF16残差与矩阵输出、z、宽部分和各有独立存储区域，传输跨区域直接失败。编码前端和小常量/bias接口目前在宏阶段中估计，并未细化到每个寄存器或每个bias参数读操作。
- `SC_reduction_bit_work`按所选二叉popcount树的位加法工作量核算，另列树节点数；它们不等同于开关翻转。counter、树与整宏价格不能重叠收费。局部计数状态是候选映射的逻辑位数，未宣称由某个已表征SRAM/寄存器电路实现。
- 未标定的`digital_idle_ns/sc_idle_ns`是保留的全窗口保持成本代理，不是已分离的互斥active/idle状态；当前未赋价。完整状态/功耗表须区分活动能量是否含漏电，避免后续重复计费。
- 采样输出地址使用一个SRAM字槽/项，之后进行依赖安全的直方图RMW。此策略可实现但保守，尤其winner更新数更大时，应优先验证流式直方图/转发/合并，而不是仅提高p-bit更新速度。
