# 单份g/u数值码→三流AND→固定Wd：首轮电路验证

2026-10-30，Issue204/rayggxia。用户同意沿PR219的raw-g编码继续，并提醒复用已有数字p-bit的全LUT、共享LUT及寄存实现。本文据此修正首轮范围；没有新RTL、Slurm、EDA、模型运行或PPA结果，不新增数字run。已有测量与本轮复算见SIGMOID_REUSE_ZH.md及SIGMOID_REUSE.json。

## 1. 数据路径与边界

已存g/u码及每64对的Sg/Su → 幅值阈值转换＋原Sigmoid表 → 三路比较/AND得到z事件及sign(g) XOR sign(u) → 固定Wd权重位掩码/正负分流 → 精确归约或OR4后popcount16 → 时间累计 → 位平面移位相加 → Sg·Su·Wd-LSB尺度对齐及跨K64块合并。

g8为signed8、单位1/8，直接作原Sigmoid表地址；g9为signed9、单位1/16，RNE除2再signed8饱和作地址。g幅值阈值分别为clip(RNE(abs(code)×2^(5-eg)),0,255)或clip(RNE(abs(code)×2^(4-eg)),0,255)。u8为1sign+7幅值、阈值左移1；u9为1sign+8幅值、阈值直接使用。q_sigma为0..256，包含满概率，组合端口需要9位。

本轮Wd仍是模型当前的固定PoT W8，幅值0..127＋权重符号；不能无授权改成权重随机流或增加第四路SNG。三路AND直接送Wd，不先给每个z增加计数器、存储或重新编码。z生成电路可跨M列共享；每列权重位掩码与输出累计仍各自承担成本。

OR4必须在每列每幅值位的权重掩码、正负分流之后进行，64→16，再做并行popcount；不能直接OR掉4个不同权重输入的z而保留一份权重。精确分支用于验证和模型合同对齐，OR4是另一个近似分支，不继承PR219 PPL。

LUT/转换在采样帧内输入稳定：查表动态更新每个新g计一次，比较与AND计T次，漏电及实际时钟按整个准备/采样窗口计。共享4/8路查表分别增加16/8拍准备；首轮不假设重叠或双缓冲。数字p-bit的pbit_sample8_reg已经包含LUT、q256比较器和bit/valid输出寄存器，采用该核时不重复收费，需对齐g/u分支延迟；若采用组合LUT＋比较器，则按组合模块计价。基础核无需重跑，集成仿真用于补新活动、时序与扇出。

Issue95的signed8、单位1/8查表合同与当前g8完全一致；g9先RNE除2并饱和。已有Ising的4/128 LUT整机也有实测共享/全并行实现，可复用bank、保持及门控方法；其中查表输入是unsigned gap/F4，不能直接当作本FFN的signed g/F3表。其整机能量含随机源、仲裁等，按层级边界取用。独立q9缓存阵列当前成本目录采用CE寄存器差分代理，不能把该估计或既有Ising整机当成新N64 FFN实测。

单个K64组内Sg/Su共同，Wd的对应64×64块也共享权重LSB，因此组内可以先归约，在块外统一做尺度恢复。旧sc_counter_merged含逐lane分桶对齐与流水，首轮复用其算术语义和oracle，不能不加修改地把旧分桶位宽/寄存开销搬进本共享尺度电路；单尺度popcount/累计实现是更直接的复用对象。

## 3. 还要补齐的内容

1. **写入前编码**：从完整GU累加结果及其整数单位生成raw8/raw9、选择原四档Sg/Su；本轮从已经存好的码开始，该成本独立补，不宣称GU全链bittrue。
2. **随机服务**：三路阈值对应g/sigmoid/u的4×2×4联合分层，格内低位为6/7/6。先用外部阈值端口测试逻辑，随机源及分发另计。不能让三路使用同一个阈值后仍宣称乘积概率；现有两颗源可否供给、跨64lane的共享/相关性须明确，不能凭共享初态继承独立lane模型质量。
3. **真实激励**：现有PR219保存汇总及探针，尚无这条RTL链路的逐拍输入包。先以三seed合成/端点覆盖功能和条件成本，再从冻结模型补短g/u码、尺度及对应Wd块回放，不因缺完整PPL重跑而停工。真实与合成PPA分开标注。
4. **SRAM及带载接口**：读宽、bank/端口、每次读供多少lane、T拍期间数据保持和向M列广播。全层只存一份g/u码；同一码派生幅值/概率。共享LUT所需活动块q缓存单列一次，沿用已有bank/门控实现，确认9位满概率端点和实际时钟成本；不将局部缓存误当成第二份全层存储。逻辑payload不是物理宏面积。
5. **输出和累计**：依据实际z稀疏度/权重位支持统计计数分布，再测缩位；精确上界保留作参考，不能直接沿用旧uniform活动下的位宽/能耗为最优值。
6. **同边界数字对照**：同一g/u码和Sigmoid表，定点概率乘法、z重定标，再接成熟A9×W8的Wd；前端公共成本两边相同计费。数字可以合理量化z，不能强制保留不必要宽度来制造SC优势，输出精度改变须另验。

## 4. 验证及计价单位

功能oracle显式产生每lane三路阈值，逐拍比较AND和各列带符号Wd整数和；测试零值、满Sigmoid概率、负数、最负g码、舍入平点、尺度边界、帧停顿及跨块对齐。当前模型用压缩binomial采样，不能要求同一个整数seed就与字面逐拍阈值全等；用同事件oracle验RTL，用条件均值/方差核对采样合同。

T32/T128、raw8/raw9、精确/OR4分别列出，不把OR碰撞误差叫硬件功能错误。需要时补实际共享随机源的相关性/质量检查，不用独立外部随机字的功耗测试冒充已接入真实随机前端。

每帧明确为一个K64输入组、T次采样、M个Wd部分点积；同时报前端每64对、后端每输出点积、集成每帧的pJ、面积、首结果延迟与II。记录准备、采样、排空及输出周期；完整FFN另含第一GU矩阵、全K合并、存储和格式恢复。完成RTL/EDA时在统一registry新增真实run、check/render并保留旧记录，不能把本计划登记为PPA完成。
