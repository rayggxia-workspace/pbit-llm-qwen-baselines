## 1. 只做这七组

| ID | 权重总有符号位宽 | 权重尺度共享 | 目标采样T | 唯一变化 |
|---|---:|---|---:|---|
| B0 | W8 | 每64×64块独立二次幂尺度 | 32 | 基线 |
| W6 | W6 | 每64×64块独立二次幂尺度 | 32 | 位宽 |
| W10 | W10 | 每64×64块独立二次幂尺度 | 32 | 位宽 |
| S1 | W8 | 全部36层FFN的Wg/Wu/Wd共享一个 | 32 | 尺度共享 |
| S3 | W8 | 全部Wg共享一个、Wu一个、Wd一个 | 32 | 尺度共享 |
| T16 | W8 | 每64×64块独立二次幂尺度 | 16 | 采样 |
| T64 | W8 | 每64×64块独立二次幂尺度 | 64 | 采样 |

## 2. 模型、训练参数与公平性

- 模型为后训练版 **Qwen/Qwen3-4B**，revision `1cfa9a7208912126459214e8b04321603b3df60c`；36层、hidden2560、FFN9728。禁止Base及静默改为其他4B型号。
- 七组从同一个核验过的父模型出发。先核对对方现有任务/快照，保留健康作业。旧任意tile尺度、精确非线性或不同训练预算的权重，不能冒充本方案已训练结果。若使用warm start，七组必须使用同一个父状态并注明训练历史。
- 沿用用户提供最新报告的**全模型参数更新**、固定原BF16教师、`CE + 0.5 KL`、蒸馏温度1及每优化步131072个有效监督token。学习率、优化器、数据顺序、loss mask、模板及教师设置从已验证训练配置导出，七组保持一致；不要重新扫描。
- 现有参考`stochastic_nonlinear/train.py`仅更新FFN，**不能不加说明直接当本方案的全模型训练器**。对方需在自己的训练器接入相同硬前向，并记录可训练参数审计；教师始终冻结。
- 默认上限100M有效监督token/组，达到预算不等于收敛。最后一批按有效loss mask精确计数，不能只按日志行数计步。核对现有900活跃GPU小时保护的剩余额度，先测实际吞吐；不要凭“多张H200”默认扩预算或取消别人的作业。
- Attention、Norm、残差、embedding、lm_head的前向沿用匹配BF16模型；本轮不叠加筛选/Ising/PV采样。

## 3. 权重尺度怎样产生与冻结

统一实际表示：`w_hat = Q * 2**k`；W6/W8/W10的码范围分别为±31/±127/±511，符号计入总位宽。符号控制正负累加，不参与输入幅度概率比较。int16/FP32只是模拟容器，不等于硬件位宽；W6/W10若未bit-pack，报告逻辑和实际存储两种大小。

先加载公共父权重，离线用[scale_maps.py](scale_maps.py)生成权重指数，正式训练/推理均冻结。首版统一采用cover-max二次幂初始化，避免把裁剪优化又变成一个因素：

1. B0：每64×64块选覆盖初始最大绝对值的最小PoT步长；全零块k=-24。
2. S1：把全部FFN的W8块指数合并为一个最大指数，广播给所有权重。
3. S3：分别合并gate/up/down各自36层的指数，再广播到对应角色。
4. W6/W10：使用与B0相同的二进制范围，不另行调范围。若B0步长指数为k8，则 `k_b = k8 + 8 - b`；等价保持 `E = k + (b-1)` 不变。这样位宽实验比较精度变化，不顺便重新优化尺度。端点±31/±127/±511的差异属于各格式固有量化端点。
5. T16/T64：完全复用B0权重指数，不能因采样数变动重选范围。

每组保存实际指数表、共享方式、位宽、父权重SHA、初始化规则和文件SHA。软件可展开为逐tile表；硬件S1只需一个指数，S3三个，B0为656640个int8指数约641.25KiB。不得把软件展开副本当S1/S3实际部署存储需求。

输入x/g/u的四档表是另一组参数：用公共TRAIN片段和新PoT-B0参考重新校准，随后七组复用相同表；g与u保留各自固定基准。不要继承旧任意权重尺度的激活校准，也不要为每组单独优化输入尺度以掩盖权重共享差异。记录每组实际截断、零码和档位利用率。

## 4. 随机硬前向与T的含义

本计划把表中T明确为**两个采样阶段共同的目标长度**：`T_x=T_AND=T`。Wg/Wu共享同一份x事件；AND事件直接送Wd，不再为Wd重新生成z流。整个FFN不是T个芯片周期，至少有前后两个采样阶段及归约/恢复/访存等调度。

为使16/32/64只变化长度，固定前级为R8的IID、64输入共享同一随机字；后级每通道三轴独立IID。三路比较器与P8端点必须实际模拟，或采用经过联合分布核验的精确计数压缩；前级不能用逐通道独立Binomial替代共享64规律，后级也不能用Gaussian噪声或均值替代有限AND。**本计划不使用joint32分层非线性，因此T16可定义。**

```text
BF16接口x
 → 固定四档编码（P8幅度+符号，显式概率1端点）
 → T_x次共享64的R8输入事件
 → 固定N位Wg/Wu，按冻结指数对齐、精确计数/宽累加
 → g/u有限位恢复并编码（P8幅度+符号）
 → 用真实g生成signed8驱动，查冻结P8 sigmoid LUT
 → g幅度流 AND sigmoid(g)流 AND u幅度流，共T_AND次
 → 同一AND事件驱动全部对应Wd输出，固定N位Wd
 → 精确宽位累计、PoT对齐、RNE恢复为BF16 → 残差
```

不允许硬前向调用无约束的精确FP32 SiLU×u。反向可以使用明确标注的浮点STE/条件均值代理梯度。g/u首级累计不能无条件视为8位：定义宽整数参考和舍入/溢出，再量化到P8接口。若保留FP32加速容器，须与小形状整数oracle核对，不把它当免费或无限精度电路。

## 5. 课程、顺序及减少重复训练

为延续当前报告的课程且不再扫描课程：0–10M为硬件编码条件均值；10–25M使用128；25–40M使用64；40–100M使用各组目标T。课程中的T同时控制前后两阶段，始终使用该组真实N位权重和固定指数；mean阶段也不能绕过量化或有限位非线性编码。

先将B0推进到进入目标32采样的训练阶段，确认目标前向确实执行、梯度有限，再扩展其余组。mean阶段loss下降不是目标采样已适应。

B0/T16/T64在前40M的模型、指数和课程完全一致，可以共享一个冻结40M检查点，然后显式分叉到32/16/64。分叉记录父SHA、optimizer/数据游标/RNG状态及唯一允许变更的目标T；这是新的case分支，不是篡改严格resume配置。若执行端尚未实现这种分叉，先分别从公共父模型运行，不能伪造严格续训。

W6/W10/S1/S3的前向不同，不能直接复用B0的40M前缀。可共享TRAIN文本及分词结果；教师缓存仅在已有协议实现并明确存储预算时复用，不默认保存全词表logits。100M×7名义700M；合法共享采样组三组的40M前缀后，唯一训练token约620M，不含教师、验证、旧实验及失败成本。

## 6. 验证与记录

- 先用小形状验证七个case：位宽码界、PoT与冻结、S1/S3组数、两阶段实际T、三路AND、整数对齐、可训练参数和checkpoint导出重放。采样两段都要打计数日志，不允许隐藏64/128默认。
- 0/10/25/40/60/80/100M记录同一heldout的CE和目标T前向，mean与课程T另列。使用部署seed101/102/103；它们不是三个独立训练seed。首轮一个训练seed即可，后续多训练seed只针对入选方案，另立预算。
- 首尾做完整WT2滑窗PPL：window2048/stride1024，原文teacher-forced，不套聊天模板，记录实际token/目标位置SHA及全36层全前缀替换覆盖。中间节点用固定验证CE或明确标注的后缀PPL即可。
- 同轮原始BF16参考必须复核。已有100M数字R0仅在模型/数据/优化器/预算/计分协议都匹配时复用；否则需要匹配数字继续训练控制，作为必要对照单列，不冒充第八个随机配置，也不把优于未训练BF16直接归因于随机方法。
- 记录校准/量化误差、截断与零码、AND零事件、sigmoid饱和、吞吐/显存、唯一优化步和活跃GPU小时。最后比较各组对B0的PPL/NLL差异，不能用不同训练批次的训练CE排名。
- 每个结果归档完整命令、代码/配置/模型/tokenizer/数据/校准/导出权重SHA、父检查点和执行环境。完整结果才写completed；预算结束与收敛分开。原始权重/数据/大日志不上传Git。

## 7. 对方实际需要接入什么

已发布文件及作用见[FILE_INDEX.json](FILE_INDEX.json)。共同PoT量化、冻结指数、共享尺度表、恢复和导出参考可直接复用；但这些不能冒充已完成的七组全模型训练器。

执行AI需在自己的Issue/独立分支中完成：

1. 将七组CASES解析进现有全模型CE/KL训练器；不执行旧57项矩阵，不直接把本计划JSON传给旧Config。
2. 为现有输入联合计数入口开放T_x=16/32/64及课程64/128，固定IID共享64；新增/核验IID三路AND的T_AND=16/32/64/128。原参考固定输入64且joint32仅支持32/64/128，不能直接运行全部七组。
3. 在加载公共父权重后调用make_scale_maps，传入对应weight_exponents，冻结并导出；新format与旧任意尺度严格区分。
