# 对照DS-CIM等工作：指标口径与当前随机矩阵实现审计

日期：2026-10-27；Issue187/PR189，rayggxia。无新RTL、EDA、TLM或模型作业。读取DS-CIM、uGEMM、SASCHA、tubGEMM原文及现有计数RTL，另做18个软件整数恒等式探针。来源/代码SHA与结果：`STOCHASTIC_METRIC_AUDIT.json`；复现：`python -B work/rayggxia/187/audit_stochastic_metrics.py`。

**有需要修正的口径，也有值得优化的电路选择；暂未发现上一轮30.48nJ的乘除算术有明显错误。它是当前多位权重精确归约实现的价格，不能作为随机计算最优成本。** 先前64MAC数字投影和CNN吞吐换算只是风险参照，不能作为同质量/同矩阵硬件的胜负依据。

## 1. DS-CIM的数千TOPS/W不是我们所报的同一种OPS

[DS-CIM表III脚注](https://arxiv.org/html/2601.06724v1#S5)明确把能效/面积效率归一到40nm、1位输入和1位权重。3566.1TOPS/W属于DS-CIM2、T64、宏级条件；我们的0.269TOPS/W按完整点积有效MAC计数。不得直接相除，亦不得将采样拍再计为新完成的整数MAC。

若按常见`A_bits×W_bits`位操作归一约定，8×8是64倍：3566.1/64≈55.72整数TOPS/W；我们乘64则约17.20位归一TOPS/W。**这是条件换算，原文没有披露完整操作计数与跨工艺公式，不能当作者报告的原始INT8测量。** 采样长度已体现在表III T64/T256的4倍差异，不能再额外除T一次。

指标统一应同时留三列：原文归一化值、条件去归一值、完成指定矩阵的总能量/时间。单MAC计数约定（乘加算1还是2ops）也须固定。我们原来`E_matrix/(M×K×N)`、`2MKN/time`的有效任务计数保留。

## 2. CMR64是额外计算并行，不是单向量采样缩短64倍

[DS-CIM§III-A/C、图4/5](https://arxiv.org/html/2601.06724v1#S3)使用128行×32列、32Kb权重，并在每列放64份廉价OR-MAC计算通道，复用权重/SNG；原文报告相对CMR1，面积约2倍、吞吐64倍。这个吞吐需要对应的并发输入与状态。

必须区分：点积输入数、输出列数、同权重并发输入上下文、采样长度。我们“64输出”不是它的“CMR64”。单输入仍要收集T次事件；B1自回归decode能否填满多上下文，须按真实跨tile/层/请求依赖判断，不能继承CONV吞吐提升。

因此，上轮数字0.004µs峰值下界、55nm CNN任务吞吐等效时间，都应留在估算附表，不当成与我们0.701µs直接对应的目标矩阵实测latency。

## 3. DS-CIM的低成本也对应不同的归约精度与质量点

[§III-D、IV-B/C、表I/II](https://arxiv.org/html/2601.06724v1)：DS-CIM1每16行OR归约，DS-CIM2每64行OR归约；SRR使组内事件互斥，但分别将激活和权重右移2/3位，不能视为原始两个8bit值的无损乘加。论文优化过PRNG及初始种子，不能把其误差直接套到自然IID p-bit。

DS-CIM2的128行归约，每拍只有两个OR64结果，合计2bit；它以8个D-latch缓存4拍再更新较宽累计。论文报告宏功耗少21.8%、面积多10%，是这套低带宽定制电路的结果，不能直接套给我们的20bit小计缓存。

表III输入条件写87.5% sparsity；应区分输入数值零稀疏、事件流1密度与SRR区域占用，不能直接宣称LLM模型有87.5%零权重。我们的合成均匀幅度权重、swept阈值并非同刺激，真实模型活动差异尚未测定。

质量点不能拼接：T64效率峰值与T256的LLaMA质量是不同配置。DS-CIM2在T64的RMSE约3.81%，ResNet18准确率89.46%；LLaMA评估用T256误差注入，FP8参考六任务平均66.0%，两变体62.6%/58.8%，不是WT2 PPL或完整硬件执行。我们可保留严格LLM质量目标，但必须明示它比某些宏级工作承担的约束更强。

## 5. 当前RTL确实保留了较重的多位归约状态

源码`sc_counter_merged.sv`执行：

`输入事件 × 固定7bit幅值/符号 → 按bin对齐 → 64项精确树 → 时间累计`。

B4叶子14bit、树顶20bit、T64累计26bit。三级切分显式数据寄存位为：`16×16 + 4×18 + 1×20 + 26 = 374bit/输出`。64输出为23936bit，不含控制/输入状态；这是RTL寄存位数，不是综合后单元计数。六级为1028bit/输出，B7/T128三级为507bit/输出。现有三级已比六级明显改善，但与OR事件窄累计仍是不同计算结构。

这些位宽是保留当前精确整数合同的推导，并非查出一个可直接删除高位的bug。若按应用容忍误差缩位/截断，应和采样误差一起测量。移位与符号输入在帧内静态，也不能声称它们每拍必然全部翻转；需要实际层次功耗分解才能确认DFF、加法器和驱动的占比。

权重寄存与上述状态分开。当前计数DUT本来不存权重/概率，改外部SRAM不会消掉其30.4nJ计数成本。固定向量的一次T拍计算中，概率、符号、档号应保持；变化的是随机字/事件。旧存储原型README也明确这一点，不能继续说所有概率寄存必须每拍写新值。若上游逐拍改变概率/存在反馈，则另按实际数据流处理。

## 6. 一个严格等价、值得补的实现对照：先计数，再加权

对当前线性tile，把固定权重、符号和档位合成`v[j,i]`，有有限序列恒等式：

\[
 S_j=\sum_{t=0}^{T-1}\sum_i v_{j,i}b_i(t)
     =\sum_i v_{j,i}c_i,\quad c_i=\sum_t b_i(t).
\]

不需要IID或特殊种子，甚至不要求跨输入独立；**同一事件序列下整数结果完全相等**。因此可先让每输入一个小计数器收集T拍，再用二进制或确定位串行做权重乘加，计数共享给所有输出。T64时c∈[0,64]需7bit，64路只需448bit计数状态（还未计后续计算、缓冲和控制）。

若用确定位切片，`c_i=Σ_k 2^k c_i[k]`，宽加权归约只需7个带2^k位权的阶段；不能把这7个位平面当成7个等权随机样本。它有机会减少宽树64拍反复更新；面积/能量并不保证降低64/7倍，后续MAC、位权恢复、输入事件计数、门控/保持/供数均需计费。

软件探针覆盖B4/B7、T32/64/128、三seed、64输入8输出、共享R8和概率0/1端点，共18组；逐事件加权、先计数加权、带位权确定切片三者整数全等。它验证代数和软件实现，不是新RTL功能/PPA或真实模型质量实验。

适用条件是同一线性tile内有效权重/档号固定且只在最后读出。**不把累计移过SiLU、FSM或反馈，也不改变上游事件生成。** 如果逐拍输出还驱动下一层状态，则必须保持那些依赖，不能用这个恒等式跳过它们。

## 7. 指标如何改，下一轮优先检查什么

1. 主表改成相同输入形状/质量下的nJ/矩阵、面积、单向量latency、连续II；1位归一TOPS另列，保留原公式与缺失项。
2. 继续保留当前精确加权树作可追溯参考，增加“先计数再二进制/确定位串行”严格等价对照，才能确认重复宽归约是否必要。不要先无依据承诺节能倍数。
3. 若实现DS-CIM式SRR-OR，单列低位损失、种子/二维序列、符号补偿、缓存和并发状态；普通OR4不叫SRR，不能同时继承精确树质量与DS-CIM能耗。
4. 匹配实际激励、模块边界与利用率。原55nm TT/SS、28/40nm、前/后布局和外设差异保留；64输出复制与64输入上下文不是一回事。

本轮判断是“比较口径需校正，当前电路存在可验证的架构改进空间”，不是宣告SC无效或功耗仿真错误。旧价格、失败与负结果保留；后续硬件修改另按任务/统一台账交付。
