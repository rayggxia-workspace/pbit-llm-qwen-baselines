# 硬件前向审计：FP32参考不能代替目标电路

> **2026-10-24补充：Python容器与电路数制分开。** 可以用FP32模拟定点运算，但须显式保持目标舍入、饱和、比较及概率响应；宽整数还须检查宿主精度。TLM和功能模拟引用同一数值契约。暂时没有RTL可以用已定义的功能宏及有来源的条件PPA估计，不得以理想转换代替尚未定义的硬件行为。局部累加位宽不等于g/u接口位宽，详见 [NUMERIC_BOUNDARIES_ZH.md](NUMERIC_BOUNDARIES_ZH.md)。

## 结论与责任

**是的，原训练清单明确要求FP32 g/u、SiLU和逐元素乘积，甚至把它写进“不可改变的前向契约”。这不符合用户要求的随机非线性电路。** 设计作者把数值oracle误当成部署训练目标，需要纠正。输入x和SwiGLU输出z的A8概率量化，并不意味着中间g/u及非线性已经量化或随机化。

旧执行代码的实质是：

```text
x编码/采样 → 用FP32解码权重进行线性归约 → FP32 g/u
 → F.silu(g) * u（无本段随机性）
 → z编码/采样 → FP32恢复/归约 → BF16接口
```

已有固定尺度PPL证明的是这条混合参考路径的效果。它不能证明低位宽g/u、随机sigmoid/乘积以及有限累加器的联合精度。PPL低于BF16也不能据此认定硬件更好：内部算术不同，且最近测试只是4096目标token的后缀PPL。

## 逐项核查

| 环节 | 实际实现/证据 | 与目标电路的缺口及处理 |
|---|---|---|
| x/z编码 | 动态absmax→PoT；固定版用TRAIN冻结四档；A8幅度+符号+满幅旁路 | 固定版确实无在线absmax；仍有逐元素选档、转换、裁剪。指数范围与有限输入边界须固定。A8不能称为全FFN INT8 |
| W4/6/8 | 清单按64×64 tile，scale=maxabs(W)/Qmax；当前pilot为W8 | 权重码固定，但scale一般不是2的幂。离线可量化scale，运行时仍需实现其应用；任意实数scale不能当成免费移位 |
| 随机矩阵累加 | `stratified_core.py::project_counts` 使用 `F.linear(sign*scale*counts, decoded_weight)/cycles` | FP32先恢复再归约并非有限位宽逐拍计数/跨档对齐。必须规定计数位宽、符号、移位、饱和和舍入顺序 |
| g/u | `StratifiedFFN.forward` 用 `x.float()`，g/u沿用FP32 | 没有面向非线性入口的定点量化。需要各自范围、尺度、位宽、裁剪和溢出策略，不应武断地都设8位 |
| SiLU与乘积 | `z=F.silu(g)*u` | 本段未采样、未量化；只在z生成后做A8编码。必须换成实际电路可实现的有限响应与随机乘积前向 |
| 非线性RTL | `digital_ppa_v1/rtl/nr_vector_math.sv::nr_swiglu_fp32` 是sigmoid LUT加两个FP32乘法器 | 并非完全没有考虑电路，而是表征了另一条数字路线。其PPA不能直接套给随机非线性；LUT近似也不是PyTorch SiLU的逐位等价证明 |
| 恢复RTL | `nr_bin_restore.sv` 和 `encoding_restore_contract/README_ZH.md` 明确FP32缩放、逐档及跨k相加 | 已有字级、握手及部分周期验证；不等于定点恢复已实现。更换格式时必须重验，不能沿用旧PPA当新路径结果 |
| RNG | 质量代码压缩理想共享门限计数；TLM默认已真正接入有限LFSR/Bivium服务 | 不能说TLM还只是免费随机接口。但质量代码尚未因此验证实际PRNG、重放、流相关性与随机非线性的联合结果；K=T也不是物理IID |
| Attention与其外围 | 该训练方案保留原准确Attention；TLM有筛选、winner/rejection/PV路径 | 不应把普通Attention基线称为已全部硬件化。量化logit输入、反馈、地址仲裁、V累加精度需按选用路径分别验收，FFN的A8不能覆盖它们 |
| 其他数字模块 | `nr_vector_math.sv` 的RMS apply/RoPE及stream accumulator也含FP32 | 这些是已有明确浮点候选，不是隐藏的零成本。若“无FP32”适用于整芯片，还需逐模块定点/混合格式替代，当前训练清单未完成此项 |
| TLM | `unified_v6/model.py` 仍分配FP32 z，SC恢复记录FP32 partial，调用FP32 SwiGLU；默认config含512 MAC/拍、64向量/16非线性lane及条件单价 | TLM不执行真实FFN数值，不能用它验证PPL。必须使算术路径、buffer字节、转换、非线性采样数、延迟/II/能量与新契约一致；旧结果不能冒称新电路结果 |

以上是本次核验的明确缺口，**不是全仓库所有分支的逐模块签核**。其他成员的周期后端、计数器、存储与PPA接合继续按各自Issue交付；本次没有覆盖或撤销其证据。

## 随机非线性的可实现方向及未定项

SwiGLU的标量关系是 `z = g × sigmoid(g) × u`。若幅度按Sg、Su归一化，三条流分别表示 `|g|/Sg`、`sigmoid(g)`、`|u|/Su`，且对同一给定g/u满足所需独立性，则AND事件的平均值乘SgSu及符号可估计z。p-bit的tanh输入需要对应 `sigmoid(g)=(1+tanh(g/2))/2`：不能把任意归一化的g直接当成驱动而遗漏增益。

这只是待选择的电路路径，**不是已通过PPL的推荐配置**。要明确驱动量化/饱和、概率响应误差、三流相关性、采样长度、稀少乘积事件与范围恢复。历史SgSu过大造成稀少事件的负结果仍有效；若改用Sz重定标，必须说明硬件如何形成Sz下的事件概率，不能先用免费FP32算好z再宣称随机非线性。

也可把定点LUT/乘法作为硬件可实现的对照，但它不等于用户要求的随机非线性，需另行标注。当前不擅自选定方案或编造位宽、功耗和周期。新增随机非线性后，原T_x/T_z外还需T_nonlinear；是否重叠由实际数据依赖和资源决定，不能统一说整个FFN只需T拍。
