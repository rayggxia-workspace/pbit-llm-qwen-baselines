# 完整 FFN 接合维护

- 长链仿真提交前，用小完整链确认源清单、实际随机阈值、逐阶段原始数值、压缩完整轨迹和失败状态均可落盘与回读。kernel完成后先保存原件，再做oracle/账目验收；只保留trace hash不足以支持独立审计。
- 完整尺寸长跑前，还应以相同峰值pending规模做有界前缀墙钟探测。小矩阵通过不能证明软件调度器可扩展；主机仿真耗时与被模拟硬件周期分别报告，性能优化须保持完整执行轨迹等价。
- 区分完整尺寸单token/单层、裁剪FFN、完整模型PPL、条件周期和STA/PPA。每输出恢复与跨k加法各计一次，组编码由所有gate/up消费者共享，信用保持到最后实际消费或写完成。
- 未公开的116依赖只记录固定源hash及本任务补丁，不把本地提交冒充正式发布。独立checkout应用前核验依赖，保留legacy默认回归，不覆盖其他任务工作树。
- sparse checkout 的 rebase/merge 后重新核对全部运行依赖，尤其跨目录 oracle；把缺失依赖纳入 sparse 规则，不能只临时写回后假定后续 Git 操作仍会保留。长跑使用实际归档提取副本通过测试后再提交。
