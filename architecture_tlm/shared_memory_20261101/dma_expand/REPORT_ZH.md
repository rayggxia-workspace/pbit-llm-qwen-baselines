# DMA扩展：消除人为入口瓶颈的实际DRAMSys结果

**片上100MHz、8通道DDR4-1866和8MiB SRAM不变；seed17完整单层从5.418380ms降至1.591150ms，快3.405倍。连续流探针达到110.84GB/s，约为119.424GB/s名义物理带宽的92.8%。** 这是带实际存储事务/命令的架构估计，不是芯片实测或完整模型PPL。

## 改了什么，为什么不只是扩大一个参数

旧前端8×64B/10ns本身封顶51.2GB/s；实际桥还只有一个原生initiator。阅读已安装DRAMSys的ArbiterFifo发现MaxActiveTransactions64是每initiator限额，单入口将8个通道聚在同一个事务线程，故扩大Python额度仍只有约28.5GB/s连续流。

本轮扩大请求发起、全局在途、返回FIFO及其bank并行度；增加8个按通道地址路由的原生initiator；移除额外1ns节拍但保留END_REQ和所有JEDEC约束；另将权重离线按计算tile连续排布，消除原行跨度让大量tile请求集中到单一通道的问题。8个端口共用256总额度，不是8×256。原FRFCFS、bankwise队列和DDR参数均不改。

资源表、构建和命令见[README](README_ZH.md)。算术/样本/核帧/外部字节/片上读写次数及容量逐项核对；重排改变物理地址，独立索引双射测试确认元素无遗漏或重复。不同seed的配对分别核对，不能要求不同seed有相同V地址。

单独移除间隔或只加宽发起没有改善，不能把收益归因于改了一个理想带宽。新桥1入口控制与旧桥有不到1%的时序差，来自桥内等待/仲裁事件顺序变化，未强行宣称逐拍等同；原gap-only桥的legacy配置精确复现5.418380ms。完整消融保留两种控制，不删除负结果。

推荐方案相对旧配置时间减少70.63%，DDR核心能量减少43.44%，SRAM总能量减少14.10%。片上动态事件数/能量基本不变，SRAM省在漏电时间。全部外存流量仍为128,770,048B，其中权重127,139,840B；没有通过删权重或少做采样取得加速。

## 能量与平均功率要区分

| DDR核心部分 | 旧配置mJ | 推荐方案mJ |
|---|---:|---:|
| 访问命令 | 15.448 | 17.714 |
| 背景/刷新 | 34.007 | 10.256 |
| 合计 | 49.455 | 27.971 |

读取RD本身约9.768mJ不变。重排使ACT/PRE命令能量有所增加，但运行短了，背景与刷新显著减少。DDR核心平均功率反而从9.13W升至17.58W：通道更忙、能量更低并不等于瞬时功率更低。NoPowerDown、64GiB/双rank及官方电流表保持相同；PHY/VDDQ、额外DMA控制/互连未标定，不能把上表当整芯片功耗。

## 面积、证据与后续

SRAM仍8MiB/512bank，已有价格折算后55nm等效面积55.1183mm²未变；返回FIFO从8KiB到32KiB使用原有空闲容量。DMA增加192个在途槽、通道入口/仲裁/路由，控制位和互连并非免费，但本轮没有新RTL/PT结果，不捏造其面积能量。新增电路校准优先是多端口DMA/返回分发，而不是重仿已测SRAM或改采样算法。

25项机制测试在本机和每个Slurm快照通过。两个桥分别Slurm3654/3662编译成功，依赖SHA与命令见BUILD_INDEX；每项源码/配置/输入/结果SHA及作业位置在RESULTS。原件在`project_archives/shared_memory227_20261101/`，不复制大trace/受限fixture/工艺库。无GPU/训练/PPL/新EDA，不新增数字PPA台账run。PR228仍open/draft，未合并；Projects无写接口待维护者同步。
