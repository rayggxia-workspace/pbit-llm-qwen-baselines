# 小型p-bit筛选网与max4：部署计算成本

Issue [92](https://github.com/rayggxia-workspace/pbit-llm-qwen-baselines/issues/92)，PR [94](https://github.com/rayggxia-workspace/pbit-llm-qwen-baselines/pull/94)，amlink1219，2026-10-22。

**单独看选择器，小网开销明显高于max4；只计小网首层乘法与候选QK乘法，当前三位置混合平均仍增加。** 小网取得了局部质量改善，但现有结果尚不能证明新增门控开销由后续节省抵消。这里是实际算子的运算账本，不是工艺综合、物理p-bit测量或完整模型PPL/PPA。

源版本`8f25afc5a2d1b46ce6e1b06dcbd7519f946bcc82`，硬件边界参考集成`83e15289434af50fc09c35e699d8b39965389d98`；源文件SHA、实际9个小网及全部上下文桶见[COST.json](COST.json)。[计算脚本](../../../experiments/pbit_gate_pilot_20261022/compute_cost.py)只读取已发布的结果及模型，不访问原始blind、不重训、不重新选模型。

## 统一比较边界

模型Qwen2.5-0.5B，head_dim=64，14个Q头、2个KV头，每组7个Q头。每64-token块包含4个16-token子块，输入4个分数为`q·mean(K_sub)/sqrt(64)`。比较同一查询、同一头的一次选择mask；首块和最后两个块强制保留，部署可跳过这些块和无效槽。

当前Python实际先对32槽计算再覆盖强制/无效mask。以下按可以跳过的部署映射计数，不能当成当前GPU/Python实际指令或耗时；不把训练的256隐藏态边缘化或评估的3seed×32draw计入部署一次mask。

## 每个自由块的选择器

| 操作 | max4＋概率节点，含低温版 | 4→8→1 p-bit网 | max4硬阈值 |
|---|---:|---:|---:|
| 四分数取max | 3比较 | 3比较，用于query统计 | 3比较 |
| query标准化的输入路数 | 1 | 4 | 1 |
| 连续输入×权重 | 0 | **32乘法** | 0 |
| 隐藏与输出加法，含bias | 节点bias另1加法 | **40加法** | 0 |
| 隐藏bit×输出权重 | 0 | **8个门控** | 0 |
| 概率/Bernoulli判决 | **1次** | **9次** | 通常0；阈值相等时随机 |
| 概率节点依赖阶段 | 1 | **2：8隐藏并行→1输出** | 比较路径 |

小网第一层8个4项点积：32乘法、24归约加法、8bias加法。第二层输入为0/1，8个输出权重可以按bit门控，无需8个通用乘法器；7次求和加1次bias。因此不能笼统称为40个通用MAC。当前软件仍执行输出乘法；门控等价已用9个真实小网的全部256隐藏态逐项验证，共2304例。

9次Bernoulli表示9个节点事件，不是9个连续周期，也不是9个均匀随机bit的固定消耗。若用数字概率发生器，需要9次sigmoid/概率近似及对应PRNG/比较；若用原生物理p-bit，概率响应由器件实现，但加权驱动、读出、随机分发和响应时间仍计入。32个连续输入乘法/加权作用没有因隐藏输出是bit而消失。

## 公共特征与动态归一化

双方都需四个64维摘要点积：每自由块**256乘法＋252点积加法**，另4个`1/sqrt(64)`标度可吸收。K摘要构建、更新、存储和读取是公共成本，不因使用小网才新增。小网第一层32乘法相当于公共256乘法的12.5%，仅是运算数比例，不能写成12.5%功耗或面积。

双方先对自由块max4计算query均值、population方差、sqrt及std下限0.01。F个自由块的两遍直接统计需3F次max比较、2(F−1)次求和、F次中心差、F次平方、2次常数倒数乘法、一次sqrt、一次floor比较。令`s=max(sqrt(var),0.01)`，再求共享倒数`r=1/s`。

- max4可复用方差的中心差，随后每块乘r；温度是固定增益，可并入r/节点驱动。概率版还需偏置、响应和随机判决。
- 最好小网用query-relative输入：另对4F个输入减均值、乘r，再clip±12，即4F减法、4F乘法、8F范围比较。这些不在上表网络本体的32/40中。
- 硬阈值版在实数下可以把判断改成`raw_max > mean + s*threshold`，省去逐块标准化。当前代码含FP32转换和tie概率，不能未经回归就声称折叠后逐bit相同。

两方案均有query全局统计屏障。单遍生成分数、统计后判决时，小网需保留4F分数，max4可仅保留F个max值；也可用二次读取/重算换缓存。2K上下文F=29，FP32分数缓冲分别464B/116B。小网另有49个FP32参数，共196B/层，可驻留并共享，不应按块重复计为必须外存读取。当前没有W8部署质量验证，不能把49字节或模拟加权器件面积当成已实现值。

## 当前候选QK节省能否抵消

每少选一个完整64-token块，每Q头少做`64×64=4096`个候选QK MAC。下面沿用原结果**1024/1536/2048三个位置等权混合**，平均F=21；不把混合平均少选块数套到一个2K查询。

| 层 | 强max4平均块 | 小网平均块 | 少选块数，负数为多选 | 节省候选QK MAC | 新增小网连续乘法 |
|---|---:|---:|---:|---:|---:|
| 0 | 8.03472 | 7.94247 | +0.09225 | +377.86 | **672** |
| 12 | 7.99188 | 8.03209 | −0.04021 | −164.70 | **672** |
| 23 | 8.16898 | 8.07634 | +0.09264 | +379.46 | **672** |

只比较第一层新增乘法与候选QK省掉的乘法，混合平均净增加约**294／837／293次乘法**；尚未计新增归一化、输出求和、8个额外概率节点事件/块等。这里按乘法个数比较，不代表不同位宽、数据流和模拟驱动的每次能耗相同。

单个上下文桶也有差异：例如层0的2K桶少0.24429块，节省约1000.63候选QK MAC，略大于928个第一层乘法；但还要承担额外归一化、加法、概率节点等，不能据此宣称该桶总能量降低。完整分桶数据在COST.json。

仅抵掉第一层乘法需`少选块数 > 32F/4096 = F/128`：混合平均至少0.16406块，2K时至少0.22656块；这不是完整节能阈值。若采用更低能耗模拟加权驱动，须改用对应的实际系数重新评估。

## 功耗、面积、延迟的可核实边界

现有集成的2pJ/MAC、10pJ/nonlinear等是proxy，不能当成小网的工艺表征。既有SRAM局部参数也不能替代新选择器的输入驱动、加权求和、概率节点、随机源与控制。完整面积/能量/功率/ns在COST.json保留null；本次没有启动RTL综合、Slurm作业或器件测量。

以`ΔE=E_net−E_max4`，F自由块、`Δk=k_max4−k_net`计，整体能量应按

`ΔE = ΔE_selector − 4096·Δk·E_QK_MAC + ΔE_K_group_union + ΔE_Ising/PV + ΔE_control`

计算；selector需包括双方的特征归一化差异、加权驱动、概率节点及随机源。仅`ΔE<0`时才省能。

- **K流量**：同KV组7个Q头mask先取并集。一块逻辑BF16 K为8192B/KV头，但只有其他头也不用该块时才省物理读取，不能用表中每头少选块数直接推DRAM节能。
- **V与采样**：固定采样数S时，PV仍约S×64次累加；候选少1%不代表累加少1%。V实际读取随抽样地址、缓存/去重和GQA并集变化。
- **延迟**：公共摘要和query统计后，max4概率版一阶段；小网是`隐藏加权→隐藏响应→输出求和→输出响应`。8个隐藏可并行、块可流水；不能说9倍串行，也不能用训练快推断推理更快。完整时延取决于资源复用和是否与其他阶段重叠。
- **质量**：强max4和小网当前工作点的局部误差及真实块数不同，尚无严格同PPL工作点。本表比较现有算子成本，不是同质量端到端Pareto结论。

当前平均8块约束主要训练质量改善，并不直接训练减少候选数。若后续目标是节能，应在可接受PPL约束下比较更低候选预算或加入经表征的总成本目标，重新冻结独立验证协议；本次不改模型、不调整已看blind。
