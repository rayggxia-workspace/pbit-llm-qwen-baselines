# 为什么这轮先测三项任务

依据用户提供的`LLM_PAPER_TASK_METRIC_MAP_ZH_20261019.md`选取。不是复现这些论文的全部分数，也不把不同模型、few-shot及计分定义混为相同设置。

| 文件中的任务类型 | 本轮决定 | 原因 |
|---|---|---|
| PIQA | validation完整1838题 | 生活/物理常识，二选一，DS-CIM也使用；完整数据已核验 |
| ARC-Easy | test完整2376题 | 科学知识，多选项短答案，较快，可与续写类互补 |
| HellaSwag | 固定1000/10042题 | 多token事件续写，检验答案概率积累；完整评分量约占这三项的90%，先用与标签/模型分数无关的预定子集 |
| BoolQ、WinoGrande、ARC-Challenge | 此轮暂缓 | 与上述任务存在部分覆盖；BoolQ本地未缓存，WinoGrande另有特殊候选构造；ARC-C对小模型较难，先看代表集再扩展 |
| LAMBADA、WikiText next-token Accuracy | 暂不新增 | 是有价值的词预测指标，但本轮优先补独立的下游选择题能力；不把已有PPL换个名字当作Accuracy |
| MMLU、GSM8K CoT、MATH、MedQA、AGIEval、ANLI | 此轮暂缓 | 本轮对象是0.5B Base，先避免大量高难few-shot/CoT配置；模板、shot数和评分协议需要各自固定，不与更大模型论文混比 |
| TruthfulQA、BBQ、IFEval、XSTest | 此轮暂缓 | 评测真实性/偏见/指令/安全等不同维度；部分原论文指标未完全确定，不能统一称作同一种准确率 |
| TriviaQA、Qasper、HotpotQA、NarrativeQA、CNN/DM | 后续单独设计 | QA的EM/F1、长上下文、摘要ROUGE与选择题准确率不同；尤其长上下文QA可能检验QK筛选，但需明确小模型能力和生成协议 |
| GLUE、图像、检索模块 | 不纳入此次Qwen解码器评测 | 模型/任务类型不同，不能直接用当前解码语言模型替换方法套用其榜单 |

本轮固定官方Harness0.4.8零样本任务，报告`acc`及`acc_norm`。对于某题，只要正确选项相对其他选项仍有最高分，即使所有选项的绝对概率都下降，该题仍然答对；因此PPL上升不能直接换算成准确率下降。反过来，选择题保持也不能证明概率校准、自由生成或长上下文能力无损。

每个随机配置三个seed分别做一次选择，不平均候选得分后再选答案，也不做多数投票来隐含增加采样预算。先计算每seed准确率，再报均值、seed标准差和相对本轮新BF16的百分点变化；逐题对→错与错→对单独统计。子集和seed有限，不预设“无显著差异就是等价”。

最重要的覆盖限制：这批实际输入最大约243/166/139 token，全部短于当前固定8×64候选预算。QK筛选不会裁剪，必须在报告注明实际保留比例为1是否得到运行审计确认；这些任务主要验证短上下文FFN和有限Ising/V采样。2K/8K的筛选质量继续依赖对应PPL或未来专门长上下文任务。
