# 需要回传的时序、面积与功耗

每个case使用唯一输出目录，至少包含：

| 类别 | 字段/报告 |
|---|---|
| 身份 | top、case参数、源码/向量SHA、seed、库名称与版本（不发布库本体）、PVT、电压温度 |
| 时钟 | 频率/period、uncertainty、输入/输出延时、负载/输入转换、门控模式、真实ICG cell与引脚 |
| 时序 | max/min timing、WNS/TNS、hold、unconstrained路径、check_timing与clock-gating检查；前布局还是后布局 |
| 面积 | 总标准单元面积、组合/时序/ICG面积及数量、单元数；不把外部SRAM/互连面积补成0 |
| 功耗 | total/internal/switching/leakage，counter或digital各层级；VCD strip路径/起止时间、活动覆盖、未知/X/Z、check_power告警 |
| 工作量 | 实际接受的输入、输出、采样/帧数、窗口ns；每帧M个输出必须注明，MAC8一拍8个MAC不能当1个 |
| 协议 | 无阻塞latency、II、尾部排空、帧间隔、暂停/唤醒；依赖累计与独立事务分开 |

至少比较continuous、idle、间歇/wake、stall；对有真实ICG的模块增加gated_idle。某窗口没有有效输出时，不计算pJ/操作；记录功率即可。

`窗口总能量 = 总功率 × 窗口时间`

`每个有效结果的毛能量 = 窗口总能量 / 有效结果数`

若需要拆动态增量，另列与相同频率/电压/门控状态的idle相比增加的能量；保留总量，不能把毛能量和已包含的idle再次相加。clock_network报告可能包含触发器时钟引脚内部功耗，不得与总单元功耗重复计费。关钟不消除泄漏。

计数器的一帧是64路输入连续T次随机事件、完成M个输出；它不是1个MAC。换成“等效确定性MAC”时，先说明一帧代表64×M个标量乘加，以及T次事件是实现成本，不能把T也乘进有效吞吐来虚增TOPS。

单lane独立MAC输出对应一乘一加。非融合BF16product＋FP32add分开计价时，不得再叠加整个MAC价表。MAC8仅证明8路独立事务吞吐，外部c的存储/供数另计；有反馈累计的top用于测寄存器、忙状态和依赖开销。最终跨上下文归约若未包含必须另计。

功耗算出但STA负slack：记录该电压下的功耗，状态为timing_violation，不用于宣称该频率可运行。无法自动识别活动覆盖率或库表越界时保留review_required，不能填100%或擅自删告警。

首轮不要求后布局；请保留“前布局、无CTS/SPEF”边界。500MHz的高驱动单元、额外流水、门控分布和布线成本不能用100MHz面积直接视为签核。
