# 新计数器与数字运算校准包

Issue193，关联Issue107/133/186；负责人jieruiz；基于main d83eeb1f，独立分支task/193-calibration-v2。
本包是供用户在55nm库上综合、STA和PT的可复现RTL。功能检查与工艺校准分开；没有新工艺面积/功率，也没有宣称500MHz通过。它不会自动替换TLM默认数值或继承算法PPL。

## 先看文件

| 目录 | 内容 |

| counter/rtl | 合并档位的精确计数器，N64、M1/M8、4/7档、64/128样本、六级/三级流水，含旧结构参考 |
| counter/tests | 独立整数oracle、同事件流旧RTL对照、暂停/回压/复位/门控与功耗激励 |

## 新计数器做了什么

旧结构每档各一棵64输入树和时间累加器，再左移对齐；新结构先对每个输入贡献按档位做固定二次幂移位，统一进入一棵树和一个时间累计器。每个事件仅属一档、最终公共系数和RNE不变时，两者整数结果相同。这里没有OR近似，没有减少采样，也没有PRNG或权重SRAM。

六级流水的每拍只过一级加法；三级流水每拍过两级。二者都能接受连续事件，但三级能否达到500MHz必须看真实关键路径。B7/T128的累计宽度33bit，B4/T64为26bit。合并后的接口是已对齐整数sum，不能未经适配直接接原来接收七桶counts的恢复器；后续只需公共系数与一次最终舍入，旧桶间归约应去掉，不能重复移位计费。

## 建议先跑什么

1. **不开门控、100MHz**：B4/M1六级，与旧结果同口径；再B7/M8六级、三级比较。此时不用等ICG单元信息。
2. 数字先跑FP32 add、BF16 product、单lane MAC，再MAC8及反馈累计；每个结果必须区分独立MAC II与有依赖累加II。
3. 确认功能/活动范围后跑250/500MHz；同一RTL可换约束，但负slack必须保留为失败，不通过调整报告名称或只看工具退出码宣称达标。
4. 得到库ICG后生成映射，跑相同结构、相同刺激的门控对照。门控版与无门控版必须使用各自正确网表/VCD，不能把功能模型当实库面积。

可复制的首轮命令见RUN_FIRST_ZH.md。工艺执行详见flow/README_ZH.md；没有运行环境或库配置时不自动发起EDA。

## 门控约定

用户已确认暂不知道ICG名字，先提供可配置接口。GATE_MODE=0不开门控；1仅供功能仿真；2必须映射真实库单元。case参数和固定top以实际实例化值为准，不靠文件名猜。MODE1在SYNTHESIS下会拒绝展开，MODE2没有wrapper/macro也会拒绝。

计数器数据域可关钟，控制和valid保持工作；复位、frame清零、采样和流水排空时必须开钟。输出被阻塞时保持结果，唤醒不丢样本。本版以实际valid立即判断可关钟，frame/sample在低相位准备开钟，没有旧TLM的idle8/wake1计时器；两者不能混称相同周期合同，后续TLM需依据此电路协议回填。当前一个M输出数据组使用一个逻辑ICG，实际扇出/负载、是否需按输出或流水级拆分ICG、时钟缓冲/CTS均待工艺检查。保留max_transition/max_capacitance/fanout及库表告警；没有CTS时不能将此布局前结果当成完整时钟网络成本。计数器门控不表示外部SRAM、随机源、其他数字模块或整机已经门控。若数字top没有ICG，报告只能标它的data-enable空闲，不能叫gated-idle。

## 要回传什么

见[校准结果字段](CALIBRATION_RESULT_FIELDS_ZH.md)。优先回传小型日志、报告、case配置、源manifest和结果汇总；不上传工艺库、私有网表或大波形到公开GitHub。把大原件保留在约定存储并提供路径与SHA即可。

## 完成边界

本包补“可以测的电路”，不预先提供新的pJ/MAC或面积。PT之后才能替换旧2pJ代理。exp/reciprocal/rsqrt和其他完整向量链的专用校准仍属后续；本包的乘加/转换可作为这些链的组成单元，但不能把它们的全部成本忽略。真实模型数值适配、500MHz全链路、物理布线/CTS和CIM外围仍需独立验证。
