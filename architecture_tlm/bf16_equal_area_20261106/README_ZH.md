# BF16整机近等面积对照（Issue236，2026-11-06）

补齐当前W8等面积对照之外的BF16对照。主配置为Qwen3-4B后训练版形状、B1、2K、36层加embedding/lm_head，55nm等效面积、100MHz、2.5MiB SRAM和原LPDDR5-derived8533原生时序。相同DMA、端口、bank、队列、回压和跨算子预取，不改变外存带宽。当前先建立一项BF16稠密对照，不扩大采样扫描。

|项目|BF16对照|概率参照|
|---|---:|---:|
|已覆盖面积|67.39315824 mm²|67.54144608 mm²|
|与目标面积偏差|−0.21955%|0|
|普通矩阵算术|1888路BF16×BF16、FP32 FMA反馈|原1024路共享数字投影＋12核C20 FFN|
|FFN矩阵权重|BF16，每权重2字节|固定W8，每权重1字节|
|FFN非线性|确定性BF16 LUT及两次乘法，沿用旧硬件参考|原T64随机非线性、直接接Wd|
|Attention|稠密QK、在线数字Softmax、完整PV|原SparQ K128＋Ising/S64|

1888路是**单个共享池**，QKV、O、Wg、Wu、Wd、lm_head按依赖顺序复用；不为每个矩阵各复制1888路。Attention的512路QK和原512路PV另计，保持当前数字Attention结构。BF16采用四上下文、同上下文4周期反馈、K32并行、K128 tile；每波最多236输出，权重tile为60416字节，放入原64KiB slot。FFN四slot，普通投影两slot，均沿用已分配SRAM，不额外增加容量。128个归约加法器、输入保持、非线性及共享存储单独计价。

面积按当前W8稠密预算删去W8 GU点积模块、W8解码增量及原Wd扩展，再按实测FMA16/c4价格重新填充。每16路0.2448702252 mm²（已折算）、增量6.61243384 pJ/FMA、idle 0.46836667mW；共享FMA池面积28.89468657 mm²，其他已覆盖部分38.49847167 mm²。最近可行32路步长为1888，不套用W8的1632/1728路数量。功耗收费包括所有有效FMA活动及整token物理idle，各一次。

执行前检查全矩阵MAC/2字节权重/输出覆盖、反馈尾部利用率及预取活跃权重不被覆盖。原生首层门禁使用完整36层分配和跨层预取；通过后才运行整机，结果核验全部36层、lm_head、SRAM容量、DMA返回/排空、原生外存字节、能量和面积守恒。完整结果另写RESULT/BUDGET/VALIDATION/SEAL及SHA；未封存时不得把预计时间当结果。

CPU Slurm调用：`python3 -B -m architecture_tlm.bf16_equal_area_20261106.run <冻结根> --scope prefix`，完整运行使用`--scope full`。执行根必须包含既有授权运行时/base、原生liblpbridge、LPDDR配置、PRICES和输入；代码中逐项核对EXECUTION_MANIFEST。仓库main尚不含全部私有历史依赖，恢复需按任务HANDOFF的精确源快照，不能只复制本目录宣称可独立运行。

这些是校准后的架构TLM结果，不是新芯片PPA或模型PPL。BF16非线性仍是既有硬件LUT参考；BF16算术并不等于软件无限精度。相同面积下BF16权重字节更多，这是数制差异，不人为降低其带宽。外存能量继续以4pJ/bit为主、6.6/8敏感性；PHY/IO/CTS、部分互连/转换/归约成本沿用原未知边界。项目原始面积仅一次乘0.81，功耗、时间和外部来源不额外缩放。
