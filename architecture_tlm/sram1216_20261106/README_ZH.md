# 1216KiB SRAM候选：落实Attention64KiB与640路数字池缓冲适配

2026-11-06，接续Issue225/PR248。这是同一完整TLM宿主的存储布局适配，不另建整机模拟器。原Attention64KiB交接只有方案；本次实际实现地址译码、区域重排及减少物理bank/端口。原198/204模块和已提交执行快照保持只读。

## 采用的容量

|用途|控制1952KiB|仅Attention1440KiB|完整候选1216KiB|
|---|---:|---:|---:|
|八组Attention|1024|512|512|
|普通数字权重双缓冲|256|256|160|
|CIM权重32个驻留槽|256|256|256|
|激活及量化码|256|256|128|
|GU跨K宽状态|96|96|96|
|norm参数双缓冲|32|32|32|
|DMA相关SRAM预留|32|32|32|
|合计|1952|1440|1216|
|物理4KiB宏/1RW端口|488|360|304|

1216KiB=1.1875MiB，不称1.2MB十进制精确值。前端176个bank，八Attention组各16个bank，共304；没有保留旧488个端口。仍100MHz、16B/周期/单bank读或写，既有有限互联上限保持，但可用bank数确实减少。每个4KiB宏的能量、时延和面积沿已表征单价，新增译码/互连增量尚无独立PPA。

## 实际数据布局

Attention仍K128/赢家保持S64、四Q共享V缓存：追加/转置及粗K双缓冲先使用0—16KiB；粗分数预留16—48KiB；筛选完成后候选K复用0—32KiB；精确QK全部读取及尾延迟结束后，V缓存再复用0—32KiB；四头候选分数32—34KiB，输出60—61KiB。128个V缓存项完整保留，不缩缓存导致额外DRAM读取。

粗分数仍继承旧16KiB事务合同，预留容量为32KiB；没有把容量调整冒充修复四头完整FP32分数行为。若以后修正流量，两侧应共同修改。当前候选不用于8K/K256或数字稠密Attention。

普通数字池仍640路、K并行8、4context、outputtile320/Ktile128、提前补货、128个FP32归约器。完整BF16权重块为320×128×2=81920B，因此两个80KiB槽可装下，不改变tile切分、MAC次数或权重字节。

激活区只压缩旧地址空洞：低32KiB激活/x码/g-u码，32KiB处5KiB残差，48KiB处八组各1KiB Q快照，64—96KiB元数据；这些对象永久互不重叠。没有将它们免费转存到寄存器，没有存完整随机流，也没有改FFN尺度、随机数或样本数。

地址译码在`mem.submit`边界执行，因此覆盖普通transfer、直接排队读取以及DMA源/回填全部事务。译码后才进入原BeatSRAM边界检查、轮转仲裁和实际bank服务；未知角色拒绝运行。Attention同时存活事务发生读写别名时立即失败。映射账本和校验集合只是模拟器元数据，不是新增硬件缓存。

### 能量和功率初步计价

同已有动作量和宏单价，仍以50ms/token作为计价窗口：覆盖面积约52.622mm²，片上24.133mJ/token、0.483W，含4pJ/bit外存197.298mJ/token、3.946W。该表没有按容量缩小比例给动态能量打折，也没有重新加FFN随机源。135个SRAM读词的一层差值未从整机动作估计中扣除，影响很小。

如果仅作敏感性，把合成一层的1.922%时间增量套在50ms窗口上，得到50.961ms、片上24.226mJ、含外存197.390mJ；这不是新整机TPOT预测。它说明本轮主要收益是约4.95mm²覆盖面积，不能把SRAM容量少37.7%宣传成系统能量少37.7%。完整结果与价表来源见BUDGET_ESTIMATE.json；新译码/互连PPA仍待补。
