## 先纠正“采样次数＝周期”的理解

Qwen2K、seed0、一个完整token（24层×14头）的封存账本：

| 量 | 赢家保持 | 校正拒绝 |
|---|---:|---:|
| 每query名义S | 128 | 128 |
| 每query实际输出预算 | 1024＝128×8 | 128 |
| 全token输出地址 | 344,064 | 43,008 |
| 全候选提议帧 | 344,064 | 128,012 |
| 被拒绝提议 | 0 | 85,004 |
| FSM服务核周期 | 7,045,032 | 8,542,939 |
| FSM服务时间（10ns核周期） | 70.45032ms | 85.42939ms |
| 源lane×cycle工作 | 704,643,072 | 261,656,528 |

最后一行是并行通道的工作量，不能乘10ns再加进墙钟。赢家输出相关且预算为8倍，不能仅因输出数较大就称为更多独立样本。

新全量聚合使这件事可以逐query检查。第23层第0头：128输出、387提议、25,983服务核周期；其中偏移后驱动重写16,835周期，源读取1,548周期，其他周期为编码、归约、决策、反馈、公平随机、提交和输出。这里的驱动重写为当前逐候选配置合同，不能描述为已经实现了廉价全局广播。

旧随机扫描串行诊断另有公式：`attempts=(N−1)×(burn+spacing×S)`，当前6周期/attempt。N512/S128/burn16/spacing4时，尝试服务为1,618,848周期；还没有加入配置和输出。旧CTMC的单位速率时间、sweep、单点attempt、并行proposal、保留输出必须分开；旧v4宏settle/sample-period也不能借用某一路的次数来证明时序。

FFN同样不能只写“T32”：Qwen全token有76,608个64×64 tile、10,032个输出波；B4与最多8引擎并行，单波`1+32+1=34`周期。原始阵列波服务合计3.41088ms，而当前64路通用向量恢复代理另需55.15776ms，编码、搬运和部分和访问还要另外计入。

## 最优先补齐的硬件和建模缺口

| 优先项 | 当前事实 | 下一步要得到的证据 |
|---|---|---|
| SC驻留权重供给 | 每波最多8个64×64 W8 tile＝32KiB；开始读一次后，假定T32期间可全部并行门控 | 明确定制CIM、保持阵列或更宽bank设计；接口、读/保持开销、吞吐、面积与能量 |
| 局部计数状态 | 上限393,216bit＝48KiB只列metadata，未落实到arena或物理阵列 | 计数器/存储实现与漏电/面积；不能用SRAM宏面积代替 |
| 新随机后端 | 整机默认仍是足量本地接口；PR103仅小接口证明 | 跨query时钟、供给消费重叠、种子/预热/回压、源实例和账本去重；再验证新概率量化质量 |
| Attention输出格式 | FP32累加后直接按BF16宽度输出，转换隐含在宏边界 | 确定融合实现或单列转换动作；表征数值和PPA |
| 跨组部分和 | 读写明确，跨组加法与SC恢复宏的包含关系不够清楚 | 单列动作或明确合同，避免漏算/双计 |
| 跨时钟与存储调度 | 100MHz核/80MHz SRAM，仅20ns CDC代理；保守bank/fabric阻塞 | 按需要做接口/队列/CDC和STA验证；有证据后再优化流水 |
| DRAM | 本52项为Link：16GB/s、80ns、32×64B窗口；窗口后排空 | 默认连续流约9.85GB/s，并非16GB/s有效吞吐；代表情景再接实际DRAMSys/DRAMPower |
| 总能耗/面积 | SRAM内部有校准，其他大量项未计价；各方案覆盖不同 | 同工艺动作单价与状态功率、完整计费边界，再比较整机；禁止先相除缺项小计 |

以上是明确的接口/证据缺口，不全是程序算错。它们足以影响整机速度、能量和面积的结论，所以在检查台中不能显示为“硬件已实现”。当前gu→SwiGLU→down全屏障、逐KV组/逐头、采样器独占SRAM及逐地址直方图RMW是具体且保守的合同，不是已证明最优的数据流。

## 观测和展示本身的检查

旧52项累计调度53,755,304个事件，但每项只保存80条。检查台仅展示其中前10条，明确标“原件保存80／实际总数”，不复制或推断后续事件。全量phase一直存在，可以画完整阶段时间线；微观细节依赖新导出的聚合，不靠想象补图。

新观测与旧52项分组，不混入旧种子均值。完整336query均唯一覆盖24层×14头；各query阶段和＝服务周期＝起止时间差/时钟，所有query服务时间和＝sampler资源busy。串行样例的stage仍是attempt-service宏，未伪装成逐门内部实现。

独立审阅还发现并修正了三个展示错误：结果链接原先错误指向执行提交（结果当时尚未入Git）；数字FFN模式仍显示SC合同；PV直接形成频数却被错误显示为0个输出地址。现在分别使用封存提交、动态数字格式/合同和真实V采样事件计数。新增负向检查验证删除QKV阶段、错误周期/拒绝数、容量重叠或把未知能量填0都能触发失败。

## 后续每次改动怎样复核

保留同一模型/配置/数据口径；更新代码与参数时生成新的检查快照与结果目录。先确认数值算法和质量证据，再确认资源/容量/时钟，再确认成本标定。若详细模拟或RTL对关键路径的偏差足以改变排序，只细化这些路径；不需要为了看起来完整而把普通算子都重新写成逐拍软件循环。

仍待用户电路/工艺证据的项、未接通的模块、未实现的优化必须持续留在页面和报告；不能因为模型检查全部通过就自动消失。
