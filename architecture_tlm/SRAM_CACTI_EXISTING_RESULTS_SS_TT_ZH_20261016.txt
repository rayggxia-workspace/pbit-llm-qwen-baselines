==========================
constrained/related slew均0.1ns时，常用输入A/D/CEB/GWEB/WEB的默认状态最坏值：

B/SS    0.7848     CEB      0.8174    WEB
F/TT    0.5547     CEB      0.3710    WEB
F/SS    1.1885     CEB      0.7786    WEB
setup最坏值对应读状态；hold最坏值对应写状态。不能忽略hold或上升沿后立即改输入。
静态MAR/MARE未包括在上表，仍应提前设置并稳定保持，遵守原库约束。

100MHz周期=10ns。F/SS、H/SS的最小读写周期大于10ns，不支持连续每拍访问。
仅由最小周期得到的上限：F/SS约90.405MHz，H/SS约89.809MHz，不是接口保证频率。
B两角与F/TT通过100MHz周期/脉宽初筛，不代表完整setup/hold及负载时序已签核。
后续F/SS可选80MHz(12.5ns)作为测试起点；或者为比较统一采用80MHz两角。
CLK-to-Q小于10ns不覆盖最小周期违例；CE隔拍有效也不自动保证所有周期检查通过。

当前配置支持write-through，但这不能推出部分写后整个Q都等于目标存储字。
部分写的未选位Q与存储内容是否相同，应区分模型行为；功能验证需随后显式整字读回。
本轮没有对B/F做新功能测试，不将旧A宏的Q瞬态X处理规则直接套用到新宏。

八、G未生成的原因
=================
8192x128/MUX4被厂商报Invalid parameter setting，SS/TT原因相同。
错误日志列出的候选范围：MUX8最大80bit；MUX16最大40bit；MUX32最大20bit。
所以仅改成MUX8仍不支持128bit字宽，不应原样反复重跑。
当前脚本日志识别没有触发MUX8尝试，但该尝试本身也不能解决字宽超限。
可先不补G，保留H独立验证；已有数据最大单宏为72KiB，不宣称验证了128KiB单宏。
若另选8192x64/MUX8，它是64KiB且不同结构族，应使用新标签，不能冒充原G。
多个bank组成128KiB与一个128KiB单宏是不同组织，需要分别计数与建模。

九、架构模型中的计算方法
========================
内部动态能量[pJ] = Nread*Eread[pJ] + Nwrite*Ewrite[pJ]。
漏电能量[pJ] = 各状态Pleak[uW]*该状态时间[ns]*0.001之和。
访问内部平均功率[mW] = Eaccess[pJ]*实际访问率[MHz]/1000。
实际访问率是有效宏操作次数/时间，不是默认等于系统时钟频率。
按活动宏数统计；不能将一个宏的访问能量当成整bank阵列或整系统总能量。

例如F/TT连续100MHz读：内部读功率约2.69123mW；连续写约5.50855mW。
还需另加对应漏电及真实外围/负载成本，不能当成完整电路功耗。
F/SS的100MHz连续访问点不合法；80MHz下内部读/写功率数值为1.846648/4.049256mW，
仅是库能量乘访问率的换算，未表示80MHz接口已经实测通过。
如果使用含漏电的总窗口能量，不要再叠加同一窗口的漏电。

CACTI使用原则：TT与SS分开；面积、读能量、写能量、漏电、access、cycle分别校准。
相同宏/PVT优先直接使用厂商库数据；未知组织才使用经验证的校准预测。
H验证预测误差，不用于先调系数再称独立验证；更大容量应明确标外推。
共享外围、多bank拼接与外部DRAM/PHY单列，避免重复计费。
