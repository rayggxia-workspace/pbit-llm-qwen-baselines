## 2. 为什么会有895万位，而不是2048个小计数器

当前每个输出、每个尺度档各有一棵64输入有符号加权归约树，六级全寄存：

`32×9 + 16×10 + 8×11 + 4×12 + 2×13 + 1×14 = 624 bit/输出/档`

32个阵列×64输出×7档，流水寄存器为 **8,945,664 bit**。最终时间累计是2048×7×21＝**301,056 bit**，前者为后者29.7倍。现版已是有符号单树，不能再次声称靠“正负合并”节省；它也不是七个权重位平面各一棵树。9～14位是加权和宽度，不能直接按普通popcount宽度缩小。

已测B7/M8面积0.81954216mm²，外推2048输出为 **209.802793mm²**。这是旧结构的条件复制面积；不代表改进结构仍需这么大，也不是完整FFN面积。

还发现统计口径不一致：TLM的`counter_pipeline_bits_per_lane=512`仍是旧假设，报1,048,576bit，比本RTL少8.53125倍；PPA已经用实际宏面积复制，**不能再把209.8mm²乘8.53**。后续状态统计应由N、BINS、寄存边界、表示法推导；宏面积和状态位面积不能重复计费。本次只记勘误，尚未修改模型或重跑旧结果。

## 3. 首选精确方案：提前对齐尺度，再共用归约和累计

现在是：按7档分流 → 7棵树 → 7组时间累计 → 左移对齐 → 档间求和 → 公共系数和最终舍入。

候选是：**各输入按所属档位左移对齐 → 1棵树 → 1个时间累加器 → 公共系数和最终舍入**。

这只是交换求和与固定左移的顺序。若每个采样事件只属于一档，则：

`先逐档求和再移位 = 先逐项移位再统一求和`。

依据现有restore合同，档位权重是`2^(2*(BINS-1-bin))`。它不减少采样、不改变随机分布、不引入OR近似。条件是公共coeff一致，中间没有逐档提前舍入/饱和，最终RNE只执行一次。当前硬件合同适用；推广至其他缩放方案前要重新检查。

| B7/T128、2048输出 | 流水状态 | 最终累计状态 | 相对旧流水状态 |
|---|---:|---:|---:|
| 现有7档、六级全部寄存 | 8,945,664 bit | 301,056 bit | — |
| 保留7档，仅第2/4/6级寄存 | 3,182,592 bit | 301,056 bit | −64.4% |
| 合并档位、六级全部寄存 | 2,826,240 bit | 67,584 bit | −68.4% |
| 合并档位，仅第2/4/6级寄存 | 970,752 bit | 67,584 bit | −89.1% |

表中不含valid/control、输入寄存、权重存储、输出缓存、移位MUX或恢复。**不是面积/能耗下降百分比**。主候选先做“合并档位六级”，以“保留档位三级”作最小变更对照；STA允许后再选择合并三级。全宽移位选择、33位反馈加法器或两级CPA一拍可能限制500MHz；不能无依据删寄存器。

位宽：B4/T64叶子14bit、树15～20bit、时间累计26bit；B7/T128叶子20bit、树21～26bit、时间累计33bit。Verilog先符号扩展再移位；不能在8bit表达式里先移位。B7硬件运行B4时需配置最高移位6而非12，或正确映射档号；共享物理资源按最大B7计价一次，不把B4+B7相加。

若反馈仍成为关键路径，再比较carry-save累计，直到帧末做最终进位加法；这会增加一份carry状态，需要与反馈吞吐一起评价。不能仅把普通累加器加流水却继续宣称同一累计状态每拍更新。

## 4. 门控必须从假设变成真实电路

当前RTL的`if(enable)`只是数据保持；普通综合没有证明时钟树被关掉。现有PPA默认80% idle动态可去除，是情景参数，不是测得的门控效率。已计价0.543J/token中，counter约0.530J，其中残余关钟时段动态约0.303J；这说明门控假设高度影响结论，不能靠调大百分比宣布节能。

具体实现按M8小bank或流水段布置库ICG，小控制器/valid管理保持运行；只有流水完全排空、最终累计与输出握手安全后才关钟。复位、frame清零、请求唤醒、test_enable均需可开钟。用标准ICG或可映射的安全latch结构，不能直接`clk & enable`。

- [ ] ICG映射、clock-gating STA检查和门级功能；保留状态，泄漏不归零。
- [ ] 排空后关钟；测试输入间断、输出阻塞、关钟边界请求、复位、多个bank同时唤醒。
- [ ] 测连续、稀疏、开钟idle、真实关钟、唤醒五类窗口，计入ICG/控制成本。
- [ ] 校验idle8/wake1是否符合电路；不符就改TLM。SRAM/HBM/RNG不随本次FFN门控自动关掉。
- [ ] 同时评估operand isolation，确保无效输入不引起组合翻转。

## 5. 数字校准：不再用统一2pJ支撑最终结论

| 最低表征集合 | 需要确定的边界 |
|---|---|
| BF16乘积＋FP32累加lane；8/16lane小tile | FMA或非融合、反馈/交错context、局部部分和、真实MAC/拍 |
| FP32加/乘；BF16残差加；FP32→BF16 | 位宽、RNE、特殊值/subnormal与溢出政策 |
| 负域exp、reciprocal、rsqrt、signed8→P9 sigmoid LUT | 输入范围、精度、误差、流水与查表实现 |
| RMS、RoPE、PV累加/平均短链 | 用前述单元组合，核对数据供给/归约/尾处理，避免重复计能 |

每项至少输出：工艺/PVT/电压、可达频率、延迟、II、面积、每有效动作能量、开钟idle、关钟状态、泄漏及活动条件。100MHz表征和500MHz目标分开；500MHz必须重新设置合理的时钟不确定度，不能沿用100MHz的2ns约束。

旧Issue107可复用代码/失败证据，但SS100MHz BF16 MAC、FP32加、PV累计存在严重负slack，不能作为500MHz价表。校准还要替换vector_op=1pJ和nonlinear_op=10pJ，不能只改MAC。算法中相同名称不保证位宽、舍入或功能相同。

- [ ] 先确定数字lane/tile合同并加合理流水，功能验证后再送综合/STA/PT。
- [ ] 得到可用配置后回填动作价表、pipeline/II与idle；失败配置保留失败标记。
- [ ] 数字与概率两条基线共用同一存储、数字模块价表和边界；不利用不同成熟度制造能效优势。
