# 55 nm、100 MHz纯数字LLM基线：已有数据与补充仿真清单

更新：2026-11-02。负责人：rayggxia。任务：[Issue #230](https://github.com/rayggxia-workspace/pbit-llm-qwen-baselines/issues/230)。

**目的：用尽量少的代表模块仿真，建立与概率方案共用工艺、时钟和外存条件的数字基线。现有数据足够开始架构估算；优先补“累加反馈、数字非线性、完整Softmax、局部供数”，不是重新综合整个LLM。**

本文件是待办和仿真规格，不是新PPA结果。本次没有运行新的RTL、DC、STA、PT、GPU或Slurm。源码交付、作业提交和实际结果分别验收；本文不表示这些模块已经实现。

## 1. 比较对象和统一条件

| 项目 | 本轮约定 |
|---|---|
| 模型/阶段 | Qwen/Qwen3-4B后训练版形状，36层；先B1、2K上下文、单token decode。实际模型revision、权重、tokenizer、输入SHA沿匹配参考冻结，不能继承其他模型质量 |
| D-BF16 | 原BF16权重/接口，数字FFN；完整QK、Softmax、PV；不筛选、不做概率采样 |
| D-W8 | FFN权重W8，保留匹配的激活量化、PoT尺度与端点合同；采用确定性点积和数字非线性。其余模块沿匹配BF16接口。用于分离量化收益和随机计算收益 |
| 概率方案 | 采用被比较版本的实际FFN/Attention参数，另记GU/NL采样数、候选数、PV样本数及随机源合同；本文件不改其默认 |
| 工艺/PVT | 本项目原65流程，面积按用户口径一次性×0.81报告为55 nm等效；主角SS、1.08 V、125℃。保留原始工艺标签、原始面积。功率、能量、频率不乘0.81 |
| 时钟 | 片上100 MHz，10 ns/拍；L、II、反馈依赖分别记录。DRAM按自身标准时序，不把DDR时钟改成100 MHz |
| 存储 | 沿匹配TLM的8通道DDR4-1866和8 MiB banked SRAM，统一地址映射、DMA、有限返回空间和仲裁版本；执行前固定准确配置SHA，不混用不同入口版本 |
| 数字计算资源 | 首轮普通投影以1024个MAC为资源参考；QK/PV、向量、非线性是否复用/独立要列物理实例表。再比较相同面积预算下的可行资源点 |
| 门控 | 两边都采用真实ICG和输入保持，报告持续工作、间歇、等待、空闲、唤醒；不拿自由运行的数字基线对比门控概率方案 |

D-W8中的A8、A9、P8阈值码不能混称：若用独立符号和幅度0..256，普通signed8不匹配；采用已验证的A9×W8＋满幅端点旁路，或另给出数值等价实现。权重离线量化不按每token收费；运行中的激活转换和尺度恢复要收费。

同外存配置不强迫传输字节相同。当前形状的矩阵权重统计中，全BF16约8.04 GB/token，只有FFN改W8时约5.35 GB/token；在119.424 GB/s标称带宽下，权重搬运下限分别约67.4和44.8 ms。它们是B1、无法完整驻留权重条件下的理想下限，不是整机仿真结果。

## 4. 最少需要补的五类代表模块

### A. 数字矩阵小阵列＋累加反馈（P0）

**目标：校准“输入、权重、部分和如何流动”，不是再写一遍浮点乘法器。**

- BF16先做16路FMA切片，复用已测FPnew内核；每路接BF16 A/B、FP32部分和，显式ready/valid与真实ICG。权重先从外部端口供给，片内实际需要的寄存/上下文/路由包含在边界内；SRAM本体另计。
- 验证1/4/8个独立累加上下文；实测反馈延迟，再决定维持II1需几个上下文。整段K测试64、128和2560；不能把独立输入II1等同一条依赖链II1。
- 数字W8控制另用一个已测N64 A9×W8核，接INT32部分和/必要宽度扩展、每64块的PoT对齐与输出转换；只补尚未表征的包装。带符号端点和最大累加范围用独立整数oracle检查。
- 输入激励同时含权重连续更换、激活广播、长K连续累加、尾块、DMA间歇、输出回压；不能固定全部B值让综合裁剪掉乘法器。
- 输出每有效FMA/每N64点积能量、上下文寄存面积、每块启动/排空周期、真实反馈L、独立II和依赖II；逻辑、数据保持、ICG、idle、漏电分列。
- 第一个切片过功能/STA后再扩至64路验证一次规模影响，64路是扩展点，不要求首轮直接综合1024路。全阵列先按切片数外推，局部广播/路由单列。

### B. 完整数制边界的数字SwiGLU（P0）

**目标：真正算出 z = g × sigmoid(g) × u，并计入运行时转换。**

- D-BF16入口先冻结为Wg/Wu的FP32累加结果，经规定RNE窄化为BF16 g/u；用BF16接口包装数字sigmoid与两级乘法，输出BF16 z送Wd。内部采用定点LUT或分段近似可以，但输入范围、变换和误差必须有明确实现。
- D-W8若沿用定点g/u，则使用匹配PoT尺度；旧Q10核可作为参考。必须用原g求sigmoid，不能先把g除尺度后直接计算sigmoid而漏恢复自变量。
- 起步做1路，16路为扩展点；包含实际FP32→BF16、BF16↔定点、舍入、饱和、尺度恢复、valid和ICG。离线生成的LUT内容不按每token生成，但其存储/逻辑面积计入。
- 记录实数语义、码域、LUT格式、L、II、幅值/端点；用真实g/u捕获加合成极值、正负、接近零、饱和/非饱和区分别激励。
- 数值对照与功耗激励分开：先对原BF16前向做局部误差检查；若近似导致质量差异，保留标注，后续才安排匹配模型验证。不能把现有Q10功耗直接贴给未实现的BF16路径。
- 已包含的转换/乘法不在总体账本重复收费；暂不需要整层FFN门级仿真。

### C. 完整上下文的流式数字Softmax与PV缩放（P0）

**目标：给概率Attention提供有优化依据的数字参考。**

- N=2048、d=128、先单query/head，tile取64或128。允许分块在线/融合Attention，避免强制物化完整N×N概率矩阵。
- scores和最大值/分母等统计按FP32语义；列明max、减法、exp/exp2近似、和、reciprocal，以及跨tile最大值改变时的旧分母/旧V部分和重缩放。
- 先做4路分数/指数切片；V侧算术复用已测FMA/ADD。保留一个已完成输出的对照，以确定首块、稳态、尾块和最终归一化周期。
- 明确选择“概率窄化BF16后进PV FMA”还是“FP32概率乘V”；前者先验证数值，后者需要对应位宽乘加依据，不能免费套BF16×BF16单价。
- 若暂时采用两遍Softmax，第二遍QK或分数读出必须计入；若采用在线方案，重缩放、状态保持和额外乘法必须计入。两者按真实数据流比较，不把其中一项省略。
- 报告pJ/score、pJ/归一化或在线更新块、状态字节数、每块周期和II；N=128/2048以及均匀/尖峰/长尾分数用于范围检查。
- 不包含Ising、PRNG或概率样本计数器。已有128候选P8核仅提供部分结构参考，不通过乘16自动变成完整原模型Softmax。

### D. 向量算术、RMSNorm及缺失转换（P1）

**目标：补齐共享但当前不能免费处理的部分；避免为每个公式独立重做FPU。**

- 先做16路向量切片：BF16/FP32加、乘、RNE窄化、valid和ICG；已有合格FMA/ADD/FP32→BF16结果优先复用。
- RMSNorm按2560维向量分块：平方和FP32累计、除维度/epsilon、rsqrt、再乘gamma；明确要保留输入或读两遍。rsqrt可LUT＋迭代，迭代次数/精度和共享数量固定后表征。
- RoPE按一对元素、sin/cos常量查表/读取、乘加路径计；残差明确在BF16还是FP32相加。Q/K归一化若模型存在也列入，不能遗漏Qwen3的Q/K norm。
- 只对实际执行路径新增BF16→定点、定点/INT32→BF16、PoT对齐等PPA；conversion-1587-functional已有功能参考可接续，不从零重做验证。
- 输出pJ/元素、pJ/2560维归一化、L/II、额外输入保留字节，以及共享/专用资源实例数。若统一用FMA完成若干运算，同一FMA面积只计一次。
- 本轮可先用已测算术＋明确LUT/迭代宏成本估计；归一化/转换若占比高再优先补综合，不能把这几项都填0。

### E. 局部存储供数、DMA返回和门控（P1，共用）

**目标：估计真实局部端口成本，不综合一个不必要的全连接巨型交叉开关。**

- 代表切片取一个DDR通道的有限返回保持、128 bit SRAM目标端口、4个目标bank组；路由/仲裁按选定架构实现，不预设每个返回都能同时到所有bank。
- 接口含请求ID、返回数据、ready/valid、有限credit/空间预留、目标写完成；空闲停钟、回压保持、冲突轮转、队列满和排空均测试。
- 容量从统一TLM配置导入；新/旧返回方式各自封存。不要把保持容量、全局未完成请求数、片内落地队列混成一个计数。
- SRAM以真实宏接口或黑盒模型接入：宏面积/内部读写/漏电沿已校准数据，控制和选路只收外围逻辑，不能把SRAM综合成DFF后再次加宏面积。
- 交付每64 B接收/转发、每128 bit局部读写的外围能量，空闲/拥塞功率，面积随队列深度/端口数的分解，以及可持续拍数和回压传播。
- DDR控制器/PHY若未综合，明确其边界；已有DRAMSys中的命令/状态能量不等于PHY和DMA数字逻辑功耗。

## 5. 给仿真人员的统一执行与回传要求

### 5.1 先功能、再综合，边做边调整流水

1. 每类先选一个最小配置，冻结源码/参数/SDC/参考向量SHA；对拍oracle检查数值与握手，再综合。
2. 使用同一SS100 MHz约束、真实时钟和ICG映射；输入到达、输出负载、reset释放合同沿匹配核，记录实际数值。不要为过时序给数据路径加false path。
3. setup或hold为负先保留结果，定位并改寄存边界或真实缓冲；复跑功能，再做门级与STA。不能用增加TLM拍数冒充RTL已经流水化。
4. 时序通过后跑三seed17/503/1009的PT；已有真实激活捕获优先，同步保留合成输入的可复现来源。
5. 不要求首轮P&R或整芯片RTL。小模块后布局可后续校正；每份报告注明无CTS/SDF/SPEF等实际边界。

### 5.2 建议的最小功耗窗口

每配置三seed，先连续/25%有效率/真实门控idle/周期性回压四类，共12窗口。25%窗口采用64拍活动＋192拍空闲；周期性回压作为独立激励。需要时加入一次唤醒测量，但不要把所有子模块、规模和模式笛卡尔积一次全跑。

每窗至少包含足够有效结果，并说明是否含fill/drain；idle只报告功率，不除以0。停顿时保持输入与停顿时外部仍翻转分开检查，避免只测到最有利的静态输入。三seed用于输入活动变化，不称训练seed或随机器件质量证据。
