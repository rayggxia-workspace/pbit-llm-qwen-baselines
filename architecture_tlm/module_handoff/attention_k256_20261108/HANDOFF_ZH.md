## 3. K256的工作量变化

固定上下文2048、r32、四Q头/GQA组、d128、S64、local32：

|每个KV组|K128|K256|
|---|---:|---:|
|粗QK MAC|262144|262144|
|选中K精确QK MAC|65536|131072|
|总QK MAC|327680|393216（+20%）|
|粗K读|128KiB|128KiB|
|精确K读|32KiB|64KiB|
|PV加法|32768|32768|
|PV读取SRAM有效数据|64KiB|64KiB|
|候选FP32分数存储|2KiB|4KiB|
|完整token ID表/u32|512B|1024B|

V外存流量取决于四头共享缓存的实际缺失次数：`256B × misses`，不等于256个V，也不能用单头S64的唯一数替代四头并集。缓存容量128条，K256时允许重读，misses可以超过unique数。无跨组共享时上界为4×S×256B；不会把缓存命中率预设为100%。

SparQ专用norm16/top16逻辑复用；`keep_k=224`加local32才是总K256，**不能把256写进原8bit keep_k端口**。输出slot index为8bit，但candidate_count/popcount/rank count需要9bit表示256。公平选秩也须用8bit，不能沿用只取低7bit的诊断版本。

## 4. 面积及整层能量增量的接法

采用既有共享64lane QK租约，64候选一tile，K128两tile、K256四tile；**不增加共享MAC或PV实例**。每组多1024个纯算术周期（100为10.24µs、250为4.096µs），不等于实际整层延迟增量。

例如4个物理采样核、4个活动缓存槽、8个KV组/层：

|K128→256增量|100MHz|250MHz|
|---|---:|---:|
|采样核面积|+0.128115mm²|+0.131598mm²|
|缓存控制增量代理|+0.012mm²|+0.012mm²|
|共享MAC/PV/SRAM容量面积增量|0|0|
|精确QK动作增量能量|+3.466820µJ/层|+4.934518µJ/层|
|采样核gross增量|约+0.027015µJ/层|约+0.034663µJ/层|
|选中K外存增加|256KiB/层|256KiB/层|
|仅此K增加的外存能量，4pJ/bit情景|+8.388608µJ/层|+8.388608µJ/层|

缓存控制增量每槽0.003mm²（0.001～0.005敏感性），是两路tag/LRU/pin/仲裁的工程预留，**不是新综合**。数量由宿主配置乘，不默认32个Q头各一核。以上尚需加实际V缺失变化、SRAM读写、宽前端、selector输出、等待泄漏与活动时钟差值，不能求和后称完整Attention能量。未知总能量和总时延在JSON中保留null。

## 5. SRAM与调用方式

每并发KV槽48KiB/12bank/1RW，100与250 SRAM/计算同频。粗阶段和精确QK阶段复用前32KiB；精确QK全部完成后，前32KiB转为V缓存128×256B。后16KiB容纳四头分数、候选ID、Q、输出及元数据，地址区间见JSON。

V缓存采用64组×2路；`set=slot_index%64`、`tag=slot_index//64`。同一token的在途DMA合并；有消费者引用时禁止替换；两路都被占用时回压。描述符总容量128、QK输入4×32B信用、每头PV输入1×32B信用。K256不是增加256个bank。

```python
from architecture_tlm.attention_k256_20261108.module import Config, profile
from architecture_tlm.attention_k256_20261108.adapter import AttentionSelected
c = Config(clock_MHz=250, candidates=256, samples=64)
card = profile(c)
actor = AttentionSelected(host, shared_FMA_pool, slot_region, c,
                          pv_lanes_per_head=4)
# 先由原SparQ流程输出224个非local候选+32个local候选。
# 宿主须取得采样核与PV实例的租约；本actor内部只租共享QK MAC。
yield from actor.run(candidate_token_ids, sampled_slot_indices,
                     selected_K_base, V_base,
                     sample_cycles=per_head_output_cycle_trace)
# SRAM/DMA已产生真实事件；动作计数在actor.result['actions']。
```

这是**筛选后的可替换事件模块**；粗QK、特征选择、四头粗概率相加及top-k仍由宿主原模块执行。宿主需要把候选表长度和keep_k参数切换为256/224，并按K256表计输出事务；不能仅替换采样器面积而仍读128个K。

原生宿主尚未接入本备用配置，没有新36层/整token结果。旧固定128的`qk_layout.selected`、`pv_stream.sampled_explicit`和旧65536+index×256的V地址不能直接继续用；本actor替换其筛选后路径，不MonkeyPatch旧默认。
