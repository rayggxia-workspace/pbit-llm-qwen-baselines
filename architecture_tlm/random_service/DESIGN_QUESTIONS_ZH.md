# 设计决定、疑点与待验证项

用户要求遇到疑点保留并说明。本轮不以这些问题为由中断可完成的模型/RTL交付。

| 问题 | 初版处理 | 还需验证/决定 |
|---|---|---|
| “LFSR加更多共享逻辑”是哪一种？ | 复用已存在的32→64默认GF映射，保留原代数证据；不另挑seed | 两两秩不等于高阶/跨时独立。Attention默认禁止直接使用；后续真实阈值/自适应轨迹质量另测 |
| 非LFSR选择 | Bivium-B，177bit非线性反馈，160bit展开 | 160步组合路径能达到多少MHz、比较器和控制加入后的PPA，由用户综合验证；不是加密认证 |
| 单根种子扩展还是逐端点新种子？ | 逐端点新合格字包，启动和每次重播种均真实装载；没有根SHAKE硬件假设 | 大量实例启动时种子传输更多。以后若加扩展器，必须给RTL、派生流合同和活动数 |
| “每次开始纯随机”能否在软件里保证？ | 硬件强制外部播种；软件默认OS新种子并明确标注，支持有来源的trace | 只有接入实际合格物理源才能证明物理启动。公开仿真/OS源不被重命名为物理熵 |
| 健康/调理如何做？ | 合格字入口＋fault；不把qualified当熵证明 | 原始核心至调理字的采样、健康、提取/偏差预算仍由物理端验证，未包含在RTL面积 |
| 物理源可能片外/慢时钟 | 模型供给间隔可慢，入口要求已经同步 | CDC、片外I/O、FIFO、唤醒/模拟稳定需另实现；不把单时钟入口说成CDC已验证 |
| 旧权重概率q/127与新q/256 | 保留旧路径；接口拒绝隐式换编码 | 需要旧权重兼容时另加明确拒绝映射/成本，不能继承旧PPL |
| 源有64输出是否等于FFN共享64？ | 分别提供GF64字扩展与FFN单字广播64阈值 | 两者相关结构完全不同，不能按名字互换 |
| 阈值保持/面积 | FFN参考top显式576bit阈值保持；通用endpoint在请求沿比较并保存输出 | 若消费者已有阈值存储可进一步合并，必须相应改RTL/活动边界，不能先免费减面积 |
| 概率sigmoid电路 | 显式q/256 LUT参考＋配置吞吐，保存表SHA | LUT/阈值存储RTL本轮不实现；量化改变响应，全模型质量未验证 |
| 高速共享总线调度 | Python按完整包轮询，端点本地并行；核心入口RTL提供 | 仲裁器、长距离分发、CTS等完整RTL尚缺；不能把总线动作计数称整机周期验证 |
| 周期换种与FFN重放冲突 | SAVE锁定epoch，RELEASE后换种，统计延期 | 调用方必须有界释放；不保证在用户无限回压/锁定时仍严格1秒换种 |
| LFSR零状态 | 丢弃无效全零种子并重新请求 | 这是去除非法状态，不是挑选“表现好”的种子；小概率额外流量应保留 |

验证过程问题：本机Icarus10.1在沙箱内报DLL重定位，沙箱外同一现有工具可正常执行；第一轮断言中的for变量声明被旧版拒绝，改为独立integer声明后通过。失败日志保存在work/rayggxia/95/rtl_validation，最终成功结果独立保存，不覆盖失败证据。

算法诊断只覆盖三固定seed、q=128、首/末输出路、lag1及T32/T128窗口；不会据此声称所有概率、所有lane、所有lag或自适应算法下均通过。原FFN B4/T32/K32分层和新均匀流不是同一算法，本轮调用示例只验证共享/重放协议。
