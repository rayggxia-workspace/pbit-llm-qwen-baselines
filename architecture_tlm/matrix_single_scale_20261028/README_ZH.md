# 单尺度INT8：先OR4，再并行计数

用户2026-10-28要求硬件重测先假设64路输入共享同一尺度。沿用Issue204/PR205，新目录和独立冻结包，不改旧四档实验或模型默认。N64/T32，真正有符号INT8权重/输入[-128,127]，含−128；共同输入/权重尺度在结果之后恢复，不存在逐输入bin移位或bin端口。

| mode | 实现 | 输出 |
|---|---|---|
| 0 | 精确INT8事件加权树，三级流水 | 同事件精确和 |
| 1 | 8个位平面的精确popcount，再跨32拍累计 | 同事件精确和 |
| 2 | 64个6位输入事件计数共享所有输出，6拍Horner加权 | 同事件精确和 |
| 3 | 每符号/权重幅值位平面先64→16个OR4，再精确popcount16，跨32拍累计 | 普通OR4近似 |
| 6 | 同样先OR4，16路各自6位时间计数，32拍后并行求和恢复位权 | 与mode3逐帧全等的不同计数硬件 |
| 4 | signed INT8×INT8并行乘法/加法树 | 原始INT8精确点积 |
| 5 | 输入幅值8个确定位，含符号，位串行加权 | 与mode4逐帧全等 |

OR4每个平面、正负分开，不能在权重位/符号选择之前把任意四个输入事件OR并丢失输入身份。mode3每拍16个bit的和0..16，跨32拍单符号0..512；mode6每组计数0..32需6位。两者OR损失相同，区别在时钟/计数/归约硬件，功能oracle必须相同。

SC输入事件概率abs(x8)/128，外部R8比较阈值2abs(x8)，−128端点概率1。SC原始事件和的期望是数字点积/4；最终×4与共同尺度恢复不在计算核内。SC最坏正值64×128×32=262144，需20位有符号累计；数字最大64×128×128=1048576，需22位有符号和，均无溢出后符号扩展至32位输出。旧四档W7幅值+符号未包含−128，不能把新旧差异全归因单一尺度因素。

功能：M1/M8×七mode×三seed×16帧，覆盖符号极值、−128、零、共享/逐路R8、稀疏/半概率、分层事件、reset中止、gaps/stall。PPA使用单独resident-W激励：16帧保持W不动，uniform signed INT8输入逐帧变，公共R8输入事件；所有方案同一组数据。它是合成计算核，不是真实模型精度，也不是RNG/SRAM功耗。

先VCS功能通过，再SS1.08V125C100MHz DC/门级/PT；M1全部7核，M8补0/2/3/5共11核，三seed active/idle。完整mapped边界逐bit活动核验、常量输出仅有显式连线和VCD共同证明时补齐。原始库面积和×0.81后的55nm等效面积双列保留；功耗/时间不缩放，时序/功耗告警保留。

本轮没有ICG、权重保持存储/读口、RNG/比较器、输入编码/尺度选择、CTS/SDF/SPEF或最终浮点恢复成本。旧四档激励含逐帧换W，新profile驻留W，不作单因素因果归因。执行状态、源SHA与结果以本轮manifest/RESULT/汇总为准。
