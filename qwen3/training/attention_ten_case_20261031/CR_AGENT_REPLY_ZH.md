CR保留为备选。维持每query/head总提议上限S×64，S128即8192轮；达到上限仍未收到128地址，记录失败并退出当前CR配置，不返回不足S的输出，不复制地址，不丢弃失败训练行，不阻塞其他配置。沿用现有分布式launcher统一传播当前case失败，避免单rank退出而其他rank一直等通信。先完成至少两次真实optimizer更新的梯度/冻结/导出检查，再按原10M阶段看heldout与PPL决定是否继续；不要直接把本次行级通过当成100M质量验收。

原13组、模型/教师/训练范围/预算、m初值0与上限24、P8 LUT、随机规则均保留。无筛选S128和筛选256的S128两CR组都保留，不新增混合回退组。赢家和数字对照可独立推进，CR不是启动其他配置的前置依赖。

## 当前固定执行设置

| 项目 | 固定要求 |
|---|---|
| CR训练组 | N_CR128、K_CR128；后者候选256，ID中128是样本数 |
| S | 128个被接受地址，允许重复 |
| row_trial_cap | S×64＝8192轮，含接受和拒绝的全部提议 |
| 每轮含义 | 对该query/head的全部非参考候选产生一次提议并分类；不是单个节点更新 |
| 达到上限 | 若第8192轮恰好收齐S则成功；否则当前case报错并归档 |
| 不完整结果 | 不进入loss、反向、optimizer或正式评测 |
| 回退 | 无；不静默换赢家/准确Softmax或减少S |
| 失败范围 | 当前case的所有worker协调退出，其他case继续 |
| 必须记录 | 行/层/有效候选数、S、提议数、已接受数、m轨迹或直方图、配置/代码SHA、复现输入与RNG状态 |
| 监测 | 训练时继续记录完成率、提议数分布、cap失败、参考频率、P8归零质量 |

执行端必须是有界计数循环，不得只有无限的while accepted<S。上限保证算法在有限提议次数内成功或报错，不保证纯拒绝法在所有输入都能成功，也不是墙钟超时/ASIC周期保证。GPU/分布式/Slurm的故障退出沿用当前训练器机制，不按每个候选增加全局通信。

如果以后需要“任何输入必须返回完整结果”，只能另定义显式回退/不同概率表示，再匹配训练与部署并单独验证；本次没有批准或实现这种算法变更。增加cap、限制m或增加S不能自动修复分布偏差。
