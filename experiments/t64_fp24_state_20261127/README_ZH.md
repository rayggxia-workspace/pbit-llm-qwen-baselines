# FP24跨块部分和：真实T64小规模数值验证

Issue225 / PR266，2026-11-27。局部P-CIM整数归约不变，比较高精度参考、BF16累加、FP24累加及24/32位定点状态。新实验不修改现有RTL/TLM或在运行的完整PPL。

FP24为E8/M15、16位有效精度；BF16为E8/M7、8位有效精度。每个完整tile先按组合尺度转换并RNE，每次状态相加后再RNE。零统一正零；第一版明确采用“精确非零幅度小于2^-126时，先清零”的正常数合同。溢出饱和且计数，任何溢出均不得认定该配置有效。没有用FP32长累加后只在结尾量化。

软件用float64承载本格式的离散数值，每一步仍舍入到目标有效位数。p≤16时，两个已舍入操作数在可能影响最终RNE的指数距离内可由float64准确相加；更远项不会改变目标舍入。独立Fraction参考覆盖随机tile转换、加法、抵消、边界与真实完整累加链。专门包含“FP32相加再截FP24”会双重舍入出错的反例。

复用冻结0d1e85176fd52205669148296c585a06c47bc369数值入口与原T64训练100M/W8，GU16/Wd32，x/g/u64基准+S/S2，准确Attention。重新运行同环境完整BF16，核验模型/语料/代码身份，再运行原高精度概率模型的真实128-token前向。只读抽取各层GU/Wd的4个token位置和完整64通道组；每条链保留全部GU40/Wd152块及其真实顺序。GU选3对g/u组，Wd选首尾两个128输出组。每条抽取链首先须与原GPU整数后端完全一致。

随后重放各数制，记录转换/加法的溢出与清零、g/u概率码/符号/指数/采样域变化、Wd最终BF16变化及数值误差。每层每投影的FP24/BF16各有两条真实链以Fraction独立核验。轨迹仅供软件诊断保存在个人共享目录，不代表硬件要存储所有tile结果，Git只登记SHA。

本轮是小规模真实链数值可行性测试，**不是FP24完整模型PPL**，也不是新电路PPA。BF16重跑只是匹配原始环境的参考。各格式重放相同局部采样事件，不改变权重、输入尺度、采样次数或Attention。

复跑CPU：`python -B -m unittest discover -s experiments/t64_fp24_state_20261127 -p 'test_*.py' -v`，本地9项PASS。真实模型通过Slurm运行capture.py，需原冻结快照及授权模型/数据。代码/配置/作业与原件SHA见同任务交接。

电路候选可参考[Berkeley HardFloat官方说明](https://www.jhauser.us/arithmetic/HardFloat-1/doc/HardFloat-Verilog.html)：expWidth=8、sigWidth=16满足参数约束，但非标准格式和清零规则仍需单独验证。本轮没有实例化或综合HardFloat。
