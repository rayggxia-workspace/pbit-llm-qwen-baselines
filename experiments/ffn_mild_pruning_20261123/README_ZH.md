# 温和GU剪枝＋原P-FFN采样

Issue261 / PR262；2026-11-23；rayggxia。T64训练100M的Qwen3-4B，先只改Wg/Wu入口。

五配置：未剪枝、纯输入幅度固定阈值10%/20%、输入幅度×GU联合范数的二次幂
近似固定阈值10%/20%。目标比例在WT2训练语料前四个不重叠2048-token窗口校准；
每64个token抽一个输入向量拟合，全部36层分别给阈值，测试集不参与拟合。
离散码并列和分布变化导致测试实际比例不必精确10%/20%，结果记录实际值。

剪枝依据是已经按原静态四档编码的输入幅值；不是运行时FP32重要性乘法。
联合范数为sqrt(sum_j Wg[j,i]^2+sum_j Wu[j,i]^2)，在导出的W8码及原64×64
PoT LSB恢复后离线计算，再舍入到最近2的整数幂。对PyTorch W[out,in]，这是
第i列方向；按输入行存储布局时称输入权重行。保留每输入静态指数，在线用整数
移位/比较。完整norm指数向量是模型派生校准数据，只在已授权私有存储留存。

对同一token/层，一张掩码同时用于GU两分支、64拍和全部输出条带。先生成原
shared64分层T64计数，再将舍弃方向的计数置零；保留方向计数与原同seed逐位
一致，不重编码、不改尺度、不乘1/q、不额外消耗随机数。它是有偏动态激活剪枝，
不是归一化地址抽样，也不承诺无偏。输入SNG逻辑行为保留；软件没有以少取随机
数改变后级随机流。硬件可随后对不参与比较的方向门控，尚未测该开销/收益。

复用既有已验证的CSR精确计数投影，仅加载保留且实际命中的W8方向；原64×64
权重指数和精确恢复保留。后级P8 g/u、sigmoid LUT、4×4×4三路AND、T_AND64
直连Wd不改，Attention为准确SDPA。只记录GU选中payload，不把它称DRAM实测。

执行分gate/screen。gate重新跑同轮8窗口BF16父参考、8项小型GPU/独立CPU
检查、全部36层GU整数no-op与完整2048 logits一致，再只用训练输入校准阈值。
screen使用共同冻结校准文件，5配置×三个seed101/202/303，WT2窗口编号
0/41/82/123/164/205/246/287；各8窗/9215目标，非完整WT2。不训练或自动扩大。

run_pruning.py的路径参数由个人服务器launcher提供；必须通过Slurm运行，输出
目录不可覆盖，源码EXECUTION_MANIFEST封存。记录模型/数据/代码/配置SHA、全部
层计分、原始与删除事件/输入质量/分数平方质量、实际剪枝率和唯一权重地址率。
目标是比较两种评分依据，不能从范数更合理就预设其PPL一定更好。
