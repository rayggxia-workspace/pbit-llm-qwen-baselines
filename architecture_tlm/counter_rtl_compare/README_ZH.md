# FFN两种精确计数电路对比

2026-10-23 PPA v2：上传和Slurm运行优先参见 `RUN_PPA_ZH.txt`。
修正输出活动校验位宽，新增源码快照、四项小规模试跑和数值汇总；RTL/TB未改。
此前验证结果是有日期的历史证据，不代表本次DC/VCS/PT已执行。

本包用于回答一个问题：固定INT8权重、输入为随机0/1流时，**按权重位分别计数**和**先合成整数再累计**，哪种电路的面积、每帧能量和时序更好。这里只交付电路与验证流程，尚未执行目标工艺DC/PT，不能预先认定B更好。

## 本次约定的边界

- 依用户要求，SRAM权重假定全并行可见。64×64 W8为4 KiB，通过32768个输入位同时提供；权重、输入符号及档位在一帧内保持不变。模块内部**没有权重寄存器副本**，不实例化SRAM。不估计这个假设的SRAM、保持、驱动和全局互连成本。
- 随机源、概率比较器不在本包中；输入直接是每拍64个采样bit，以及true-one覆盖位。相同激励给A和B，不比较序列质量或PPL。
- 计入采样使能/分档、整数归约、累计寄存器、可选一级归约流水、A末尾的有符号位权恢复、相同帧控制和输出寄存器。
- 不计入浮点恢复、缩放系数、SiLU、残差及跨tile合并。四档结果分别输出，不跨档融合。使用同一工艺库、PVT、时钟和负载对比。
- 没有缓存四拍或OR近似；本轮只隔离“计数状态组织”的影响。按使能更新寄存器，不手工插ICG；工具映射/是否自动门控必须记录。

## 两个方案具体差别

**A `ARCH=0`**：每输出、每档、每输入符号、每权重位分别popcount，累计无符号计数；采样结束按W8二补码重构整数。bit7系数为−128，不能当+128。

**B `ARCH=1`**：每拍将有效W8权重按输入符号取正/负，用平衡加法树分别归约到四档，再累计每档整数。必须先把−128扩到9bit再取负，得到+128；否则极值错误。

两者都是精确整数计算。RTL均写成平衡树，未采用串行for加法链偏袒某方。综合工具可继续优化，两者使用相同`compile`设置，不能只对一方特殊优化。

64输入×64输出，四档，T32，`PIPE=1`时的**逻辑状态位数**：

| 状态 | A 位平面计数 | B 整数累计 |
|---|---:|---:|
| 主累计状态 | 6144 B | 640 B |
| 一级归约流水数据 | 3584 B | 480 B |
| 相同的输出寄存器 | 640 B | 640 B |
| 三项合计，不含少量控制 | 10368 B | 1760 B |

主累计位宽：A为12bit计数器，B为20bit有符号累计器。正极值为64×32×128=262144，19bit signed不够。20bit包含该正端点。以上不是综合面积，组合逻辑、时钟和实际映射必须一起计入。增加PIPE=1会同时增加两边的流水数据状态，不能只比较6144与640。

## 协议与周期

1. `cfg_ready && cfg_start`在上升沿开启一帧，同时清零累计器。随后进入采样状态。
2. `in_ready && in_valid`接受一拍64路样本；精确接受T次。`in_valid=0`允许任意间歇，期间不计数。
3. 第T拍之后排空归约流水，再捕获完整四档整数到输出寄存器。`out_valid && !out_ready`时结果必须保持，不能接收新帧或多余样本。
4. 接口不包含输入/权重锁存：调用者必须保持weights/sign/bin/true_one直至输出消费结束。样本仅在采样握手时有效。
5. `rst_n`为低有效、**同步**复位，可中止帧，输出不得泄漏旧结果。固定T合法值16/32/64；PIPE为0或1；M支持1/8/64。

从开启帧的上升沿到out_valid首次有效：无间歇时`T+PIPE+1`周期。当前保守的单帧接口不允许帧间重叠；连续事务启动间隔为`T+PIPE+3`周期。因此T32/PIPE1的完整连续帧为36周期，不能只按32周期算吞吐。A/B有相同协议与周期；**功能周期一致不代表STA都达到100MHz**。A的末尾恢复路径也必须检查。

## 用户先做什么

请先解压ZIP，在已有DC/VCS/PT环境中运行单输出smoke，确认库、功能、VCD活动映射和PT单位，再跑64输出正式对照。现有55nm库默认路径沿用此前脚本，可通过`SS_DB`、`TT_DB`、`STD_MODEL`覆盖，库文件不包含在包中。

```bash
# 在解压后的counter_rtl_compare目录运行，结果路径必须是全新绝对路径
bash flow/run_one.sh A ss 1 32 1 /your/results/counter_A_ss_smoke
bash flow/run_one.sh B ss 1 32 1 /your/results/counter_B_ss_smoke

# 上面无错误后，Slurm提交A/B × SS/TT共四项，64输出T32 PIPE1
bash flow/submit.sh /your/results/counter_formal_NEW
```

主比较固定100MHz，SS1.08V125°C、TT1.2V25°C，setup uncertainty2ns、hold0.1ns、输入输出delay/负载同旧PPA包；数值约束见flow/common.tcl。这些是统一测试条件，不代表最优时钟。setup/hold不通过仍保留功耗，但不能把该点当可实现性能；提高频率需对A/B同时重综合。下一轮可用`SC_PERIOD_NS`和`PIPE=0/1`做频率/流水对照，不能直接由一次slack倒算未经验证的Fmax。

完整阵列建议4CPU/32GB/12h起步，最多2项并行；只是资源预留，不是运行时长保证。没有GPU/PPL任务。权重引脚多属于此次理想供数边界，DC不得将其常量化或把某个激励的权重写进RTL。

## 流程会输出什么

- DC：综合网表、SDC、层次面积、单元清单、setup/hold关键路径及slack、约束违例。
- VCS：先用独立Python整数golden验收符号、极值、档位、间歇、reset和回压；通过后运行mixed/sparse/dense/zero四类活动，各seed17/43/101。
- PT：每类活动测完整连续帧窗口与64拍空闲窗口，共24窗口。所有权重写入引脚变化及帧清零在工作窗口内；外部SRAM代价依旧排除。输出每个bit活动率与VCD比对，PWR-981或窗口X/Z失败不能忽略。
- 采样激励由合成概率码和共享阈值生成，不是实际LLM激活。主结论看mixed/sparse/dense三类是否一致；zero用于时钟/空载分析，不能拿其省电比例代表模型。
- 保留范围超表、缺失表、未注释活动等警告。工具算出功耗不等于结果已验收。零延迟门级VCD没有毛刺/布线/CTS/SDF成本，最终物理比较仍需后布局活动。
- 原始netlist/VCD在结果目录，自动生成小型`*_reports.tar.gz`供回传。VCD在PT完成后无损gzip、逐SHA复核再移除明文，恢复索引WAVE_ARCHIVES.json；不丢失波形。`KEEP_PLAIN_VCD=1`可同时保留明文。每类默认8帧，可用`SC_POWER_FRAMES`增加，不能将短合成窗口当真实模型活动。

## 回传后怎样判断哪种更好

请回传A/B、SS/TT四个reports包。至少同时比较：

| 必填量 | 口径 |
|---|---|
| 总标准单元面积，组合/时序及层次分项 | 包含A的恢复逻辑与两边公共输出/控制，不含SRAM面积 |
| setup/hold slack和真实关键路径 | 区分采样归约、累计反馈、A末尾恢复、输入输出约束 |
| internal、switching、leakage、total power | 同活动、同电压/频率，不把时钟内部功耗重复加一次 |
| 每完成一帧的能量 | `E(pJ)=P_total(µW)×窗口时长(ns)/(1000×完成帧数)` |
| 每输出每档的整数结果能量 | 每帧能量再除`M×4`；不能当一次完整FFN或浮点输出能量 |
| 有效吞吐 | 完成帧数/窗口时间，采用含清零、排空、恢复和握手的实际周期 |
| 活动映射与警告 | X/Z、逐bit映射、load/slew范围、时序违例都保留 |

如果B面积更小但功耗更高，或时序失败，需要看归约树和宽累计反馈，而不是立即选B。如果A靠更深流水达到频率，额外寄存器和延迟也要计入。**本包的目标是让这项选择由同口径工艺结果决定。**
