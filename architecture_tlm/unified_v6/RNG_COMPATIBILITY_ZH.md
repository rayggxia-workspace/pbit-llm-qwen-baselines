FFN不必用GF64扩展：当前算法就是**一个随机字共享给64输入**。同一输入组在多个SC输出阵列之间也可以共享这一阈值，广播连线/驱动成本仍需表征。GF64的64个不同输出不是相同语义；其总状态只有32bit，不能拿任意两路的性质替代全Attention候选的联合独立性。

## FFN需要加的只是分层前端

K32时：

```text
LFSR32 → R8的低3位 ─────┐
                       ├→ {5位stratum计数, 3位抖动} → R8阈值
0..31分层计数器 ───────┘                                │
                                              与64个概率码比较
```

即`threshold = stratum * 8 + (R8 & 7)`。阈值仍在0..255；不是把R8直接比较32次。后者丢掉分层覆盖，已经通过重放同一源状态证实二者不同。

四档的q8和exact-one标志继续使用已有编码：普通概率为q/256，`one=True`强制输出1；不改成q/255，也不移动已有PoT尺度。新前端的输出与v6准确位平面读出逐项对齐。它利用随机字作层内抖动，但覆盖顺序受计数器控制，不称完全IID。

同一输入组：SAVE → 第一输出波次 → RESTORE → 下一输出波次 → … → RELEASE。锁定期间到期重播种会延迟并记账，释放后才换种；本次三seed、强制短重播种周期验证这一点。只保存PRNG状态，不保存32个随机字。

## 不能直接忽略的四个边界

1. **供给宽度。** 512候选需要26个Bivium端点，原生520路中的8路仍生成并收费；公平端口另算。本次实测26端点一帧、156个32bit播种总线拍。Qwen的筛选器在同一KV组处理7个Q头：2K有224个块响应，8K有896个，512路阵列容不下后者。可以明确分波筛选或加宽，但不能静默把容量视为无限。筛选、PV和采样器是否复用硬件必须固定后再算实例面积。
2. **数值响应。** 新数字源为R8与q比较，概率为q/256，p=1用q=256，故概率阈值需9bit；随机字仍为8bit。已有`SigmoidTable`还采用0.125驱动网格。这会改变理想sigmoid采样的目标分布；接口连通不代表继承旧Softmax/PPL。FFN的分层前端对齐现有编码，也不证明该PRNG的模型质量或联合独立性。
3. **时间与账本。** 整机用ns，新源按时钟沿。源对象必须跨查询持续存在，不能每行重新启动；source等待、种子总线和预热进入同一时间线。FFN的32次供给要与32次消费重叠，不能先生产32拍再完整多算32拍。采样器已有计时钩子时，`embedded`仅作需求统计，不能再次追加一段源时间；源累计账本只能取差分或最终计一次。当前`advance_to`逐沿推进空闲，后续若跳事件需保持年龄、重播种和统计等价。
4. **存储与能量。** 没有随机流SRAM/FIFO，不等于源内部没有寄存器。新端点有状态、保存状态和单响应寄存器；数字p-bit还需要q阈值的驱动/保持。接合时明确替代哪一组旧配置状态，避免又复制一份概率。原生端点的比较、前端64次比较、无用原生输出活动、LUT/阈值写入分别列账；不能同时按宏能量和其内部动作重复收费。实际面积、功耗仍待用户工艺表征。
