# 500 MHz TLM 的可追溯 PPA 后处理

本目录为 Issue186 的派生PPA估计，保留原始证据字节，不修改 Issue193 的实测结果。`PPA_ANCHORS.json` 是可公开的小型参数索引，只包含数值、状态、相对名称和原始 SHA，不含远程用户、工具安装或工艺库路径。`build_anchors.py` 仅是本机提取辅助脚本，无需随正式成果上传。

调用：

```text
python -m architecture_tlm.clock500_resource_20261026.ppa path/to/RESULT_SUMMARY.json --output path/to/PPA_ESTIMATE.json
python -m unittest architecture_tlm.clock500_resource_20261026.test_ppa
```

脚本直接读取 `clock_gating.resources`，也允许 `--usage usage.json` 显式提供实例占用。`sc:0...` 每个代表一个 64 输出阵列，因此一个阵列要计 64 个输出计数通道。32 个 64×64 阵列的物理计数通道为 2048 个；M8 面积已经包括 8 个输出，不再乘错 64。

| 实测边界 | 面积 | 功耗依据与局限 |
|---|---:|---|
| N64/M1/B4/T64 counter | 0.06091056 mm² | 100 MHz active 2.56267 mW，clock-on idle 1.554 mW；一帧 64 样本、72 拍 |
| N64/M8/B4/T64 counter | 0.47885112 mm² | 仅面积/STA；没有活动功耗 |
| N64/M8/B7/T128 counter | 0.81954216 mm² | 仅面积/STA；没有活动功耗 |
| B4 恢复单 lane | 0.01371672 mm² | idle 0.318233 mW；连续、cadence64/72 分开 |
| B7 恢复单 lane | 0.02154024 mm² | 仅面积/STA |
| signed64 饱和累加 lane | 0.00198036 mm² | 仅面积/STA，不含多条部分和存储 |

共享 GU/Wd 硬件按最大 B7 容量收费。B7 功耗只能暂按 B4 实测和面积比例外推；GU 阶段未使用的 3 档仍计漏电和 clock-on 背景，不默认这些档已有独立门控。T128 的活动增量按样本数比例外推。以上是明示代理，不能声称新配置已经 PT 仿真。

每个模块使用的能量式为：

`漏电功率 × 实例数 × 总时间 + 开钟实例拍数 × 每拍 idle 动态能量 + 有效动作数 × 相对 idle 的活动增量 + 未门控的空闲动态能量`。

开钟实例拍数是逐实例求和，含流水线填充/排空及调度器报告的唤醒时间。门控只删除关闭期间的动态项，不删除漏电；动作增量不能再叠加 gross energy。默认情景仅消除空闲动态的 80%，同时列 0%、50%、80%、100% 敏感性，不假定所有组合输入和全局网络也停止翻转。现有 RTL 只有 CE/数据保持，测量时全程开钟；真实 ICG、CTS、唤醒控制、输入隔离、互连及 500 MHz 时序修复成本仍未计。因此“理想门控节省”是条件上界。

恢复宏已经含分档移位求和、系数乘法、舍入、符号恢复。本 TLM 把 bucket reduce 和 coefficient restore 分成两个时间资源，后处理仅价格一次，不可把同一门重复收费。共享物理恢复宏在两段都必须开钟：脚本取 `min(总时间, bucket 开钟时间 + restore 开钟时间)` 作为占用上界。这两段有效工作串行，但开钟保持区间可能重叠，求和会保守高估；尚未提取准确区间并集，不声称此部分门控精确。合并宏实际 lane 数及流水线也尚未与两个调度资源完全对齐。稀疏恢复活动增量暂取 cadence72；连续流的增量较小，可另做敏感度分析。

SRAM 继续读取真实字数与宏数量。SS 的 E256×128 单宏面积 0.03322622 mm²、读 10.0527 pJ、写 13.9599 pJ、CE-off 漏电 7.7544 µW；周期至少 3.468 ns。F4096×128 单宏面积 0.31216331 mm²、读 23.0831 pJ、写 50.6157 pJ、漏电 45.20772 µW；周期至少 11.0613 ns。核心提升至 500 MHz 不意味着 SRAM 也能直接变成 500 MHz。其值来自 Liberty/LEF 提取，不是本次新芯片测量。

普通数字算子仍把原 TLM 的 2 pJ/BF16 MAC、1 pJ/vector、10 pJ/nonlinear 独立列为代理。已有 BF16乘积/FP32累加原型在 100 MHz 仍有严重时序违例，且边界包括多周期帧/寄存器，不能直接当作成熟 500 MHz MAC 阵列单价。FP32→BF16 的小型原型也不能代替宽定点→BF16。脚本不凭空补 HBM、NoC、CIM 改造或完整数字阵列的面积和功耗；输出 `full_chip_* = null`，只列有依据的小计和未定项目。
