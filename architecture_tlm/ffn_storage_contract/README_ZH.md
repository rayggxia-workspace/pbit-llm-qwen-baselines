# FFN权重供数与精确整数状态合同

本轮把32KiB/波权重供数与48KiB计数状态的假设变成可检查代码：两种有限状态的供数调度、独立轨迹验证器，以及逐档整数累计的等价诊断。对应 [Issue118](https://github.com/rayggxia-workspace/pbit-llm-qwen-baselines/issues/118)，由用户2026-10-23的清单执行请求启动。最新项目进展与优先级调整见 [研究对齐报告](RESEARCH_STATUS_ZH.md)。

**结果等级为软件接口设计验证。** 这里没有新RTL、STA、物理CDC、PPL、完整FFN/decode或芯片PPA；`area/energy/PPL`保留null。没有改v6默认、旧52项或真实源40项原件，也没有接管Issue116的周期核心。条件结果在 [结果目录](results/run_20261023/SUMMARY.json)，实际测试记录在 [VALIDATION.json](../../work/amlink1219/118/VALIDATION.json)。

## 两种供数方式

| 项目 | 显式整波保持 resident | 串行重读 reread |
|---|---|---|
| 权重在SRAM中 | 8个64×64 W8 tile，共32768B | 相同 |
| SRAM/Fabric | 16bank、每bank单1RW、128bit、80MHz；公共16GB/s | 相同 |
| 局部权重保持 | 明确分配32768B；装载完成后才能消费 | 0B持久权重保持 |
| 响应/在途预留 | 256B；从发射至目标提交持续占用 | 16B；只有一个字可在途或等待消费 |
| sample/sign/bin | 共享64路，共256bit；按帧冻结 | 相同，必须保持至整波分块消费完 |
| T32 SRAM权重读取 | 每波装载一次32768B | 每sample重读整波，共1048576B |
| 采样推进 | 装载完成后显式全宽本地接口消费 | 一次完整扫描后才接受下一个外部sample |
| 额外条件 | 全宽保持/写入/扇出与消费时序尚需实现及表征 | 分块精确加法、计数状态读写与消费时序尚需实现及表征 |

这两项是不同状态/响应预算下的可执行候选，没有宣称同面积或同资源最优。`resident`不预设现有SRAM会永久保持32KiB输出，也不推荐默认把全部权重换DFF：它把必须实现的保持端口和容量明确暴露出来；采用寄存器、专用局部存储或宏自身输出保持，都要另给真实实现证据。`reread`给出降低保持量的保守代价。

本轮执行的完整边界时间（从SRAM内权重可读到全部sample消费完）：

| T | resident时间/µs | reread时间/µs | resident读取/B | reread读取/B |
|---|---:|---:|---:|---:|
| 16 | 6.76 | 1638.4 | 32768 | 524288 |
| 32 | 6.92 | 3276.8 | 32768 | 1048576 |
| 64 | 7.24 | 6553.6 | 32768 | 2097152 |

resident预装6.6µs；其32KiB保持、16个本地写口与256B响应容量均已声明。reread为16B响应、单分块消费者，每字从issue到commit为50ns；T32可独立回算`2048×32×50ns=3.2768ms`。纯SRAM/fabric必要下界为2.0805µs/波，不能替代实际6.6µs装载时间。表中差异来自不同局部资源和重读次数，不是已经证明的全FFN或同面积加速。

原配置若**没有任何局部权重保持，却要求32KiB在每10ns拍全部可见**，需求是3276.8GB/s；16bank×128bit×80MHz理论20.48GB/s，且公共fabric只有16GB/s。增加总SRAM容量本身不能消除这个带宽缺口。代码拒绝无保持的整波消费；不把总字节除带宽所得下界当作合法执行周期。

默认宏时钟约束复用F/SS、4096×128库表：读cycle10.9192ns、写cycle11.0613ns，按单1RW最慢值向上取11062ps。80MHz通过此库表周期门槛，100MHz不能使用同一合同。来源是`EXTRACTED_NOT_SIMULATED`，不是本次新STA；读返回延迟、20ns CDC和本地消费仍是显式接口假设。其他深宽/工艺的配置不能自动继承该宏证据。

## 计数状态优化

结构A保留 `[输出][档][输入符号][权重位]` 的无符号计数，最终按二补码bit7=-128重构；结构B直接累计每输出每档的有符号整数和。二者均保留四个独立档，不做跨档浮点融合。

| 每tile，64输入/64输出/4档 | T16 | T32 | T64 |
|---|---:|---:|---:|
| A每计数器位数 | 11 | 12 | 13 |
| B每档累计位数 | 19 | 20 | 21 |
| A总状态字节 | 5632 | 6144 | 6656 |
| B总状态字节 | 608 | 640 | 672 |

T32下8tile由48KiB计数状态变为5KiB，位数相差9.6倍。新增signed归约树、更新端口、控制、时钟、保持与布线成本没有定价；**这不是9.6倍面积或能量收益**。单拍正边界`64×128=8192`需signed15，T32正边界262144需signed20；不能只按负数可容纳范围选位宽。

`counter.py`的A/B与第三条直接dot参考，在固定seed20261023的66个合成场景、888个逐档输出上相同。另有全256种W8码×两种输入符号、true-one、全0/全1、分档、T16/32/64、帧清零和中间溢出检查。-128是W8接口压力边界，不是声称现有absmax/127模型实际用了该码。没有生成真实LLM激活，没有验证统计质量或改动FP32恢复；未来连接仍须保持原每档转换、尺度相乘与顺序FP32加法。

## 时序与数据边界

- 时间使用整数ps。非整除Hz按每个绝对有理时钟边沿向上取整，避免逐周期截断累计漂移。
- 每次读都记录issue、ready、fabric区间、complete，以及本地hold-write或chunk-consume；单1RW bank只允许每边沿一次访问。
- 有限响应容量从发射开始预留，持续至目的端提交，不借用无限在途队列或免费的宏输出缓存。
- 外部sample由输入bit/sign/bin的SHA标识。`reread`不能在扫描中改sample，也不能重复一个字来代替漏掉的字。输入/权重已驻留；此处没有模拟随机源发生器。
- 同一整数时刻先完成释放，再允许新事务接受；依赖的零等待传递只在事件契约明确允许处使用。`validate()`独立检查轨迹，不调用调度器生成期待值。
- 局部权重、响应、sample、signed累计状态分别分配。SRAM容量检查仅针对静态权重映射；这些局部状态不是从SRAM中免费借用。控制元数据、尺度、加法树pipeline等额外电路状态未完整建模，物理成本未知。
- 只有一个不可变权重wave，不声称实现DMA写竞争、ping/pong、prefetch、恢复或跨k流水。直接供数阶段结束不代表完整FFN结束。资源下界与实际保守调度分别报告。

## 复现

仅需Python标准库。从仓库根运行，输出目录必须不存在，防止改写封存结果：

```sh
python -B -m unittest architecture_tlm.ffn_storage_contract.test_model architecture_tlm.ffn_storage_contract.test_counter -v
python -B -P architecture_tlm/ffn_storage_contract/run.py --output NEW_DIRECTORY
python digital_circuit_simulation_registry/registry.py check
```

runner输出T16/32/64×两种策略、拒绝反例、计数诊断、小规模输入与完整轨迹。大型trace只保留配置、输入、事件数和规范JSON SHA，按命令可重生成；没有冒称大型原始trace已存服务器。`EXECUTION.json`绑定实际执行源的SHA，`MANIFEST.json`绑定输出原字节。仓库工作提交与执行源码manifest分开，后续文档/发布元数据不会改写结果。
