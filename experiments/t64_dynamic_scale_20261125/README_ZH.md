# T64动态组共享二次幂尺度：单种子PPL初筛

Issue225 / PR266，2026-11-25。接续尺度合同质量验证，新增目录；不改旧已提交快照、权重或TLM默认。

规则：x/g/u分别按连续64项计算最大绝对值M，选择能覆盖M的最小二次幂S；M为0时选最小档。全局最小指数−6，最大尺度x512/g256/u512；超上限饱和，记录比例。取消各组校准四档目录，不是向下取幂后主动截断。g/u独立选尺度，sigmoid沿用真实尺度P8 g恢复为signed8/Q3再查冻结P8 LUT。

固定训练100M的T64 W8和配套non_ffn，准确Attention；前后采样预算16/32、64/128。前级R8共享64路，分别16/64层各采一次；后级联合4×2×4、8×2×8每格一次。仅改变尺度分组时不同时改变随机字共享粒度。事件计数直接用于Wd，不重新生成z比特流。

单部署seed101，8个分散2048上下文窗口（0/41/83/125/166/208/250/290），保留逐元素四档和组64四档对照；它是小规模PPL，不是完整WT2。原BF16完整292窗/299077目标在新环境重跑。若动态64任一预算较对应lane对照PPL高5%以上，则自动补全x/g/u均为32、16一组的两档预算；5%只用于调度分支，不是接受标准。

新指数范围可能超过冻结T64 INT8参考核的14位对齐限制，因此独立wide_wd.py仅把数字分解前的对齐容器改为INT64，保留INT8分段点积与INT64恢复，并保留实际signed64最坏界检查。GPU先以独立CPU整数oracle验证R6/12/15/29。不是把溢出警告删掉或用FP32近似替代；未提供该宽归约的物理PPA。

动态参考仍遵循整数归约/明确RNE恢复的原路径；Python的frexp/ldexp表达选指数和二次幂移位的数学规则，并非宣称片上使用通用浮点除法。CPU选档、端点、符号/舍入、精确尺度对齐4项预检先通过Slurm；GPU核oracle、原生no-op和新环境BF16均通过后才报告candidate。
