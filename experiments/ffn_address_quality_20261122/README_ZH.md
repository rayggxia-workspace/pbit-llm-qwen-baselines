# T64：GU入口地址/次数驱动的稀疏权重读取质量测试

Issue261 / PR262；2026-11-22；负责人rayggxia。用户授权远程Slurm小规模PPL与唯一地址测试，合格候选再完整WT2；不训练、不改主线默认。

## 执行的确切计算

**输入P8幅值码/PoT尺度 → 采样 → 合并重复输入地址并保存次数 → 仅加载这些输入方向的W8权重 → 次数×有符号权重精确累加 → 尺度恢复及平均 → 原P8 g/u、sigmoid LUT、AND、Wd。**

PyTorch的`W[输出,输入]`的一列，在本包的存储中是一行。Wg和Wu共享一份地址/次数表。权重由既有T64整数码直接转存为W8，不重新量化。

权重bank布局为`[输出条带512][输入编号][g或u][连续512个W8]`。稀疏投影核唯一的权重读取点由CSR中的输入编号生成地址；次数为0的输入没有CSR记录。每个输入地址只读一次对应权重，再乘次数，不能把重复抽样算成重复外存请求。原64×64权重指数表按原输入编号/输出编号选择，没有重新拼尺度。

bank在本次GPU质量实验的global memory中，实际投影只gather所选行。一次性构建bank会读取所有导出权重，这是部署/布局步骤；评测不把它伪装成每token稀疏加载。原导出张量保留用于身份核验与no-op oracle。新采样分支不做全量GU矩阵乘法；只有验证模式额外执行原稠密GU整数oracle。

本实验验证模型数值与所选权重payload。LPDDR burst、bank冲突、DMA、SRAM/缓存、时钟、面积和能耗不由GPU运行时间推断，也没有把软件global-memory访问当作目标ASIC的DRAM时序测量。

## 三类采样与补偿

既有编码`x_i=sign_i q_i 2^(e_i-8)`，保留零码与full-one=256。

* 原对照：每原64输入共享分层R8，T=64；后级joint-grid=(4,4,4)，64次。
* PoT：同一分层R8比较，再与每原64输入共享的独立高k位全零事件相与。`L=2^k`，原始次数仍在0..64；整数GU累加乘L后沿原尺度/64恢复。没有右移8位阈值导致小概率变0，也不伪造大于64的原始事件计数。
* 归一化：用编码输入幅度及PoT指数构建整数质量`a_i`与总质量M，使`|x_i|=a_i 2^e0`。整数uniform ticket用拒绝去掉2的幂范围偏差，不使用FP32概率oracle。`normalized_bernoulli`使用每原64输入共享、跨轮IID的ticket进行逐输入比较；每轮期望一个命中，但允许零或多个命中。`categorical`每轮选一个地址，有放回抽S次再计数。二者都执行`2^e0 M / denominator × sum(count_i sign_i W_i)`；S与原T分开。

归一化法的总质量及公共乘法是新增硬件工作，本轮仅验证其整数行为，没有把它记作免费运算。PoT与归一化法的随机联合分布不同；输出表分别报告它们，不混称原T64。

## 初筛与完整评测

PLAN.json含9个FFN配置：原对照、L2/4/16/64、归一化伯努利64、单地址S64/256/1024；三部署seed101/202/303。固定WT2原滑窗中的8个索引0/41/82/123/164/205/246/287，按照原window2048/stride1024的目标位置计分。它是**8窗口探索性子集PPL**，不是完整WT2。未修改BF16同轮跑相同子集；主要新增损失相对同T64权重原P-FFN计算。

功能gate先核验独立CPU整数oracle、未选权重扰动、零向量与预算、L1分层等价，再核验全部36层GU整数结果及整2048窗口logits与原实现逐位相同。只有gate封存JSON、SHA与源码身份通过才能运行screen。

初筛记录NLL/PPL、目标位置与token SHA、每层输入事件、逐token唯一地址数、所选GU有效W8字节、原输入组命中率、次数最大值、CSR字节、ticket拒绝和随机位。比例按每token地址并集计算，不把整个文本窗口合成一个地址并集。Wd与Attention保持原算子；读取量仅代表GU。
