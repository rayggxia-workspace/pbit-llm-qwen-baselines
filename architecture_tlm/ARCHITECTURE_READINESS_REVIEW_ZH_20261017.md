# 当前概率 LLM 架构离实际可用还缺什么

日期：2026-10-17；负责人：@jieruiz；任务：[Issue #3](https://github.com/rayggxia-workspace/pbit-llm-qwen-baselines/issues/3)。

**当前已有可用于研究的算法实验、部分 RTL 和宏级事务仿真，但还没有形成数值行为、访存调度与硬件成本一致的完整加速器。最需要补的是这三者的对应关系。现在不能据此承诺真实芯片的 tokens/s、J/token 或相对 GPU 的节能倍率。**

本文以 Qwen2.5-0.5B 的 24 层 decode 路径为主。Qwen3.5 的混合 Attention/DeltaNet 不能直接套用同一张调度表。现有模型有价值：可以检查动作、容量、因果关系和参数敏感性；已接入的 DRAMSys 也确实模拟外存请求。但这些证据与芯片可用仍有距离。

## 1. 一眼看清主要缺口

P0：会改变正确性或结论方向；P1：决定实现能否兑现性能；P2：扩展到部署场景。

|---|---|---|---|---|

## 2. 之前 Attention 的错误应怎样认识

这些是建模与结论管理的不足，我需要承担并用验证约束修正，不能归咎于随机算法本身。

1. **把数学上的稀疏化直接当成高效实现。** 旧路径逐头、逐样本等待 CDF/SRAM 和 V DMA，缺少适当合并与并发，使省下的工作被可避免的串行开销淹没。v6 已修正一部分，不表示整个架构已优化完。
2. **复用和物理流量口径没有先闭合。** GQA 的多个 Q 头共用 K/V。采样后应按 KV 组并集读取并显式广播，不能每头重复搬运，也不能把单头采样比例直接当成整机 V 流量比例。
3. **局部阶段与整个核的端点混用。** v6 的独立 PV 阶段约节省19%时间，但同一轮完整 Attention 只有约0.5%～0.7%的时间降低。稀疏方案还有全 QK、指数统计、预算和第二遍扫描。这些时间不能省略。
4. **成熟模拟器的示例参数被过度信任。** DRAMPower 执行的公式与分项账本可以正确，但输入电流不适合做器件结论。最新审计没有发现原桥重复加总，也没有证据说增能来自更多 ACT；真正问题是状态驻留变化遇到了反常参数。
5. **不能混淆不同随机机制。** v6 是 PRNG 驱动的 systematic PV，未运行 Ising。v4 的宏间隔也没有证明真实网络已充分混合。

以上历史结论依据本地 `PV_ENERGY_AND_ISING_AUDIT_ZH_20261016.txt`、`PV_SANTA_PAPER_AND_GQA_READ_AUDIT_ZH_20261016.txt` 和 `PV_STREAM_V6_RESULTS_ZH_20261016.txt`。这些 v6 文件尚未随本次报告发布；本任务仅记录其 SHA-256 和可访问的本地位置，不伪装为远端已发布代码。本次没有重跑实验。

## 3. 从当前源代码还能看到的具体边界

### 3.1 v6 的收益及扩展性

`pv_stream_v6.py:StreamPVDecode.attention()` 的第一遍读取 K、计算完整 QK 与块内指数统计，第二遍按 KV 组扫描、合并所选 V 并累加；明确保留了串行 tile 阶段。其数值地址用软件 softmax 参考生成，硬件前缀/路由按操作和资源计费，并不实际运行有限位宽 RTL。

- 当前每头预算为2K/128、4K/256、8K/512。这是调度情景，尚未通过同版本真实模型质量确定最小可用采样数；固定比例也不一定是最优预算。
- Qwen2.5 每7个 Q 头共享一个 KV 头。即使每头只取上下文的1/16，组内并集仍可能明显更大；本轮 V 物理读取约为稠密的34.6%，不能说只剩6.25%。
- scores 空间为 `14 × L × 4 bytes`：8K时448KiB，32K时1792KiB。单这一项已超过当前1MiB片上预算的32K配置，尚未加 KV tile、状态和描述符。必须重新分块、外存暂存/重算或增大容量；不能无代价外推到32K。
- 目前独立 PV 微基准的前序状态和中间数据端点并不逐命令相同。报告已说明这点；最终比较应统一 Attention/整机端点。

这些是当前实现的边界，不是随机采样机制本身不能更快。

### 3.2 片上 bank 已有模型，仍须验证接口

`banked_sram_v5.py:BankedSram` 已明确分 lane、1RW、固定字宽、带宽、宏延迟和每描述符 CDC 成本。它使用一个描述符排空后释放资源的服务界，不是完整的逐字请求队列。不能继续沿用旧报告中“完全没有 bank 模型”的说法，也不能因此声称已经逐周期准确。

`memory_schedule_v5.py:StagedWeights.tile_ready()` 读取 SRAM 后仍使用 `resident_read_pJ_per_tile` 宏级成本，随机核按 `(T+1) × period` 服务。这没有确定 SRAM 的128bit读口如何给64×64并行阵列提供并保持整个权重 tile。接口能抽象，但必须给出可实现的组织及其成本，不能只用一个很小保持功率绕过这一问题。

SRAM 第一轮 CACTI 校准也不是全指标可靠：H 验证点的写能量误差约64%～73%；实际已有宏优先查库。库内部能量不自动包含整个 wrapper、输出负载、mux和时钟树。用CACTI探索尺寸合理，不能把探索预测当工艺签核。

### 3.3 不同采样机制需要不同验收

`ising_macro_v4.py` 默认用 `categorical(softmax(logits), ...)` 产生地址，明确声明硬件分布未验证。宏接口有容量、配置、预热、样本间隔、读出和背压价值；默认地址参考不能证明真实 Ising 的采样正确性。

`configs/local_shared_v2.json` 的输入是8位阈值，PRNG状态是32位，二者不能混称“8位LFSR”。真实截取方式、跨64路相关性、权重流独立性、checkpoint恢复及短流质量，都要用实际位流验证；软件理想共享随机字的 PPL 只能作参考。

筛选目前的 max4＋归一化＋sigmoid/Bernoulli 也不能写成“QK耦合退火已实现”。固定候选预算修复有额外工作，也改变选取分布；要单独验证组合精度，不能从各模块分别表现好推导联合后同样好。

## 5. 后续设计必须通过的检查

### 第一关：同一个算法、同一份数值参考

先冻结模型提交、数据哈希、BF16参考、定点格式、尺度、舍入、采样/PRNG、GQA映射和累加策略。改变编码或架构作比较时按原AGENTS要求在实验环境重跑未改BF16基线。用实际数值参考导出地址及事件trace，再由TLM模拟，不让另一个理想采样器替它生成“更好”的轨迹。

小例子检查：每头样本数守恒、尾块有效、GQA掩码正确、重复样本计数正确、scale恢复一致、无溢出。然后测单层误差、完整WT2滑窗PPL、多种种子；长上下文方案还要验证长程检索/任务质量。仅PPL或局部MSE不能单独决定可用。

### 第二关：数据在哪里、什么时候读、资源归谁

先写每个算子的输入/输出大小、地址布局、活跃时间、驻留位置、端口及就绪/完成事件。权重、K/V、scores、部分和、索引和描述符都有有界空间，双缓冲不能免费；数字与随机通路共享资源时必须争用同一实例。

对批次做有界的读取—计算—写回流水。只有不同资源、输入已就绪、输出有容量时才允许重叠；用停顿原因证明快在哪里。SRAM扩深只增加容量，不自动增加bank并行度。DRAM请求数少不保证能耗低，还须核对命令和状态驻留。

### 第三关：自动检查反常结果

| 检查 | 必须看到什么 |
|---|---|
| 存储/流量守恒 | 有用字节、物理字节、burst、GQA并集分别记账；所选V确实不被无依据全量读取 |
| 容量与所有权 | 峰值占用不超容量；buffer释放不早于最后消费者；所有in-flight队列有上限 |
| 端口与依赖 | 1RW读写互斥；完成前不消费；超出带宽/周期的服务明确排队 |
| 改参数的反应 | 内存受限微基准降低带宽/增加访问延迟后变慢；若整机不变，能用其他瓶颈或已验证重叠解释 |
| 下界检查 | 时间不少于关键依赖链及必要资源服务量的下界；“全部PV零成本”也受Amdahl上限约束 |
| 能量闭合 | 总能量等于互不重复的动作项＋状态积分；同迹改功耗系数不应改变时序 |
| 独立交叉验证 | 规则子图与Timeloop/ZigZag动作量一致；小型bank/DMA/SC例子的周期与RTL或独立拍级参考一致 |
| 统计质量 | 真位流/真Ising采样与其参考的差异有测量；不能把相关样本总数直接等同有效样本数 |

这些是待建立/补全的验收项，不是本文已经运行通过的测试。

### 第四关：把成本变成有证据的参数

成本分成“直接库/实测”“RTL/PT标定”“CACTI外推”“未标定情景”四级。先补影响排名的参数：SRAM—阵列接口、实际SC阵列与累加器、PRNG及扇出、数字前缀/路由/广播、BF16转换及宽定点部分和、Ising有效样本服务。

TLM按这些动作与资源计费；DRAMSys负责外存命令，CACTI/宏表提供存储参数，RTL/STA/PT提供电路服务能力与成本。只有当互连/主机/缓存一致性成为明确需求时，再引入更重的NoC/gem5系统模拟；工具越多不自动意味着越准确。

## 6. 建议先做什么

1. **先冻结一个最小可运行原型目标。** Qwen2.5-0.5B、batch-one decode、2K/8K、固定权重SC精确计数＋准确QK/Softmax＋systematic PV；Ising保留为独立探索。不能预先假定4096是必要预算，也不能未经精度验证就减少。
2. **闭合两个最关键接口。** SRAM如何供给/保持权重，真实有限精度采样器如何产生TLM使用的地址。这两项不清楚，继续优化宏级能量小数没有意义。
3. **先让数字和概率Attention在同资源下得到可信调度。** 统一端口、缓冲、DMA和端点；用真实模型trace，比较分块/融合与有界重叠。报告“PV、完整Attention、整机”三层收益。
4. **补能改变结论的PPA及DRAM参数。** 优先按敏感性决定仿真投入；未测部分给区间，不用示例参数承诺倍数。
5. **单独评估Ising路线。** 先取得有限候选网络的真实采样统计，再比较同质量下的有效样本/J和有效样本/s。若混合/配置代价过大，允许只用数字systematic采样；不为“全p-bit”强行降低系统效率。

通过这些步骤后，才适合确定片上SRAM容量和分布、阵列数、工作频率及对GPU的整体优势。当前更合理的定位是“可审计的架构探索原型”。
