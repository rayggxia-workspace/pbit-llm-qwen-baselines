# SRAM 邻近 SNG、驱动与计算门：初步面积功耗验证包

Issue146；默认 **N64 × M64，固定 W8，8 位概率比较，T32/K32，100 MHz**。本包不改变已验证的模型算法，不含新的 PPL。目标是把“权重留在 SRAM，旁边计算”的数字部分拆开测量。

2026-10-23 v2批处理入口：[RUN_BATCH_ZH.txt](RUN_BATCH_ZH.txt)。已补SS/TT自动选择、真实非反相buffer绑定与Tcl插值修复、Slurm不可变源码快照、三个seed、叶子分类功耗汇总、失败日志归档。当前仍是待服务器DC/VCS/PT验证，不是已有新PPA结果。

## 先做哪几项

| 模块 / 顶层 | 做什么 | 含哪些硬件 | 怎么用于总估计 |
|---|---|---|---|
| `cim_sng`（KIND1） | 64 个概率同时生成 64 个 bit | 1 个本地 LFSR32、8 位共享阈值、64 个比较器、阈值驱动、分层计数和握手 | 可加在已有计数器前面；还需计算 bit 分发 |
| `cim_w8_gate`（KIND2） | bit 驱动 64 个输出的 W8 权重门 | 两级分发缓冲、32,768 个逻辑 AND 位 | **已有 A/B 计数器含权重门控，不能再把此项全加一次** |
| `cim_frontend`（KIND0） | 上述两项真实负载连接 | 完整 SNG＋驱动＋原始 W8 门控 | 推荐首测；从层次报告取 `sng` 与 `gates/sample_drive`，再加原计数器 |
| `cim_sram_q_probe`（KIND3） | 稳定权重 Q 引脚的本地缓冲 | 每权重位 1 根缓冲＋1 叶缓冲 | 可选接口情景，不代表必须每位用两级，也不代表 SRAM 本体 |

这里的“64 路共享”是 **同一个 8 位随机阈值被 64 个不同概率比较**。输出存在相关性，符合当前共享方案，不是 64 个独立随机源。默认 LFSR 映射复用项目已有源码；每接受一个样本更新 16 个 Galois 步。`EXTERNAL_RNG=1` 可旁路本地发生器，保留未来物理随机源/随机服务接口；该配置不把外部源能量当成零。

```text
共享 R8 ── 阈值驱动 ── 64 个 q8 比较器 ── bit 分发驱动 ── W8 AND ── 已有计数器
                           ↑                               ↑
                    上游稳定概率                         SRAM 稳定权重
```

## 概率、分层与存储接口

概率是 `q8/256`；`one=1` 明确表示概率 1，避免把 255/256 当作 1。输入幅度分档、符号和后面的加权恢复留在原模块，本包没有替代它们。K1 为普通随机；K32/T32 依次遍历 32 个区间，每区间取一次随机点；T64/K32 为每区间连续两次。K256/T256 是完整枚举，不宣称其仍有随机积分收益。

`q8/one/weights` 必须在 `frame_start` 接受后一直稳定到完成，包括暂停时。**本包不添加概率或权重副本寄存器**，也不存储 T 个样本。上游已有结果存储和 SRAM 的保持成本仍需系统计费。种子只在空闲握手时装入；跨帧保留 PRNG 状态，没有强制每帧重新播种。零种子报错；忙时种子请求不接受。

每个有效且 ready 的周期产生一次并行采样；暂停时计数/本地随机状态冻结。外部随机接口遵守 valid/ready：被阻塞时 word 和 valid 保持。无暂停时从 start 到完成需要启动后 T 次采样，前后传输/后端排空另外计入，不能把“32 次采样”当整条 FFN 的全部 32 周期。

## 真实驱动不能用导线代替

`cim_buffer` 在功能仿真中是导线，在 PPA 中必须绑定一个**真实工艺库非反相 buffer**；脚本检查函数、输入输出和综合前后数量。默认每 8 个比较器一组阈值驱动；每 8 个输出一组 bit 驱动。N64/M64 时共 72 个阈值 buffer、576 个 bit buffer。它们只是可综合的初步布局方案，尚未优化布线。

必须看缓冲路径的负载、slew、时序和层次功耗；摆放后的长线/寄生并未由 RTL 自动解决。输出负载默认每 pin 2 fF，是扫描情景而非工艺实测；建议 1/2/5 fF 对照。库须以 pF/ns 为对应单位，否则先换算脚本参数。

## 第一版怎样相加

**初步总能量 = SRAM 保持能量＋摊到本帧的装载能量＋SNG/分发能量＋原计数器能量＋原有后处理能量。**

旧 A/B 计数器已经有权重门控、符号与分档，所以只把 KIND0 的 `sng`、`gates/sample_drive` 加到旧计数器。此加法仍是模块级近似：原计数器的边界驱动/负载可能重叠，后续用集成顶层综合消除重叠，不能声称精确整机 PPA。KIND0 的整项不能再次叠加全部计数器。

权重只在装载时改写；计算过程中不按每次采样计一次普通 SRAM 读，也不计一次全矩阵搬运。写入摊销要按实际重用次数，不能固定假定“只写一次永不换”。64×64×8 为 4 KiB，一个 tile 的 32,768 个稳定权重引脚是一项 **CIM 并行可见性假设**，普通窄端口 SRAM 宏不能直接实现。

## SRAM 还需要补什么

| 项目 | 现在能做什么 | 是否必须重跑大阵列 |
|---|---|---|
| 保持漏电、面积、正常装载读写 | 复用已有 SS/TT 宏数据及尺寸差分；保留必要外围 | 否 |
| 稳定 Q 到计算门的数字缓冲/扇出 | KIND3；先只做 512 位，按位数初估，再看大 tile 布线 | 否 |
| 存储节点被计算门加载后的扰动/延迟 | 用真实 bitcell＋门级晶体管模型，按 `sram_probe/cell_load.sp.template` 做小探针 | 需要小型 SPICE；PT 不能验证存储稳定性 |
| 初始化/改写权重后的可靠读出 | 有新端口时检查写入和保持，若走标准宏端口可沿用原宏 | 小单元/小行即可开始 |
| 整 tile 线路、电源、拥塞 | 后续布局估计，第一版列为尚未标定项 | 暂时不用全阵列仿真 |

最小 SPICE 组合：SS 1.08 V/125 ℃、TT 1.2 V/25 ℃；存 0/存 1；无附加负载/接一个真实计算门；输出 1/2/5 fF。先保留相同电压，**不因计算简单就降低 SRAM 电压**。测保持是否翻转、Q/QB 最小最大电压、单元漏电、逻辑能量和延迟。无负载与有负载对照能估计附加成本，但普通编译 SRAM 黑盒的总功耗不能唯一分解出裸 bitcell 成本。

SPICE 模板不含工艺模型，须提供真实 `CIM_BITCELL`（BL,BLB,WL,Q,QB,VDD,VSS）、`CIM_AND2`（A,B,Y,VDD,VSS）、`CIM_BUF`（A,Y,VDD,VSS）适配；禁止用理想电压源替代 Q 再声称验证了 SRAM。模板的理想 BL/WL/随机输入驱动能量未计入，当前只量存储单元和相邻门。小探针足够启动初估，不要求先完成定制 SRAM 全版图。

这与 [OpenRAM 官方表征流程](https://github.com/VLSIDA/OpenRAM/blob/stable/docs/source/characterization.md) 的层级一致：先用 SPICE 得到存储电路的延迟/功耗，再生成 Liberty 表供上层使用。这里借鉴表征方法，不借用其工艺数值，也不要求迁移到 OpenRAM。
