# 面积复核：随机乘法小，为何当前SC整核仍大于四路INT8核

用户2026-10-28要求核对面积推理。本页仅重读已完成的映射库存与原报告，没有新增EDA。原件、结果成员和RTL SHA见work/rayggxia/204/int8_classic_ppa/AREA_AUDIT.json。

**小AND门不构成整个点积核面积必然最小的证明。** 这次比较的是六个位平面全并行的64路SC核，与四个完整INT8乘法器复用16拍的整数核。N64是问题长度，不是两边都实例化64个完整乘法器。此前仅报告总面积，未展开这个关键结构区别。

统一面积由库内全部映射单元面积求和，再单次乘0.81；两边原始面积分别6819.84和3825.36µm²。不是不同缩放系数导致排序。

| 面积组成（55nm等效） | SC54 | 四路INT8/INT32 |
|---|---:|---:|
| 寄存器单元数 | 77 | 109 |
| 寄存器面积 µm² | 449.064 | 785.279 |
| 组合单元数 | 1860 | 793 |
| 组合面积 µm² | 5075.006 | 2313.263 |
| 总面积 µm² | 5524.070 | 3098.542 |

SC寄存器部分确实更小，节省约336µm²；组合部分却多约2762µm²，合计大约多2426µm²。这是实际库单元库存的分组和，不是按门数或状态位数推算的面积。组合分组包含综合共享和优化，不能进一步未经证据地把其中某一数值全部归给popcount。

SC54的77个状态单元对应54位计数状态、16位结果、5位采样计数、2位状态。六个权重幅值平面1..6，每平面包含64路事件/权重位/符号掩码、正负分别OR4、两棵16输入popcount及相减、9位饱和累加；最后做固定移位归约。因此不能将总面积仅估为“64个AND＋一个计数器”。输入576位中权重、事件和乘积符号均外部供给，没有在该SC核里额外放整组权重/概率寄存器或SRAM。

四路INT32核的109个状态单元对应64位乘积寄存、32位部分和、13位控制。只有4个8×8乘法器，连续16拍处理完64对数；平衡归约与一个反馈累加器复用。外部只需每拍32位A/32位B流；完整权重存储、SRAM和供数仍未计入。两边均没有把完整矩阵权重DFF算进核心，排除了“SC算了权重存储、数字漏算”的解释。

若改成64个INT8乘法器全并行，旧本项目数字参考面积约0.04621mm²，确实大于SC54的0.005524mm²。但其帧间隔约20ns，与SC350ns及本次四路整数190ns不同。该旧点只说明结构/速度/面积权衡，不能把它改称本次相同接口下新测的严格消融。

所以应分别判断“同物理并行规模下哪种单元更小”和“在规定延迟内完成同一点积，整核需要多大”。当前SC54在后一个比较中未胜出；它不是所有SC实现的面积下界。符号处理、popcount/饱和累计和恢复网络仍值得独立优化，但需要新RTL、质量与PPA验证。时分复用这些网络可能降低面积，也必须计入增加的周期，不能只保留较小的面积数字。

这里只是N64/M1计算核。完整阵列还需匹配精度/激励、输入复用、权重驻留及SRAM端口、随机源、广播和时钟网络；现表不能宣称整片面积结论。
